# ランキングリンクカード サムネイルA/B表示仕様

## 1. 目的

ランキングへのリンクカードを見た瞬間に「何の統計か」「1位はどこか」「代表値はいくつか」が分かるようにする。
地理分布を見せる **A: 地図型** と、代表値を強調する **B: 数値型** を使い分ける。

視覚参考: [`../assets/ranking-thumbnail-ab-proposal.png`](../assets/ranking-thumbnail-ab-proposal.png)

> 参考画像は方向性を示すモックアップ。画像をカードへ貼らず、既存データからSVG/HTML/CSSで決定的に描画する。

## 2. A/Bの役割

### A: 地図型（後方互換の標準）

- 地域差や分布を見る指標
- category / survey / ranking一覧 / 関連ランキング
- 指標名、47都道府県タイル地図、1位強調、`1位 都道府県名`、値・単位を表示
- 既存`generateMiniTileSvg`を再利用し、日本地図・順位計算を別実装しない

### B: 数値型（強調表示）

- 1位の値自体にニュース性がある指標
- homeの注目ランキング、将来のOGP/SNS
- 指標名、代表値、単位、`1位 都道府県名`を表示
- 背景の地図は薄い装飾とし、数字の可読性を優先

| 表示場所 | 既定 |
|---|---|
| home 注目ランキング | B |
| category / survey / ranking一覧 | A |
| 関連ランキング | A簡略版 |
| OGP / SNS | B（別PR） |

## 3. SSOTと解決規則

`MetricConfig`へ任意のvariantを追加する。既存`visualization`配下に置くべきかは着手時に型とexportを読んで決める。

```ts
type RankingThumbnailVariant = "map" | "number";

interface MetricConfig {
  thumbnailVariant?: RankingThumbnailVariant;
}
```

解決順:

```text
metric configの明示値
  > 呼び出し側のvariant prop
  > 表示場所の既定値
  > map
```

既存2,000件以上のconfigへ一括追記しない。完全未設定は必ず`map`とする。

初回の数値型候補は10件以下に限定する。

- `unmarried-ratio-male-30-34`
- `total-population`
- `software-engineer-annual-income`
- `fiscal-strength-index-prefecture`
- `annual-sunshine-duration`

値または1位欠損、長すぎる値・単位はAへ戻す。

## 5. コンポーネント方針

まず既存`RankingThumbnail`へvariantを追加するだけで収まるか確認する。不要なコンポーネント分割をしない。

```ts
interface RankingThumbnailVisualProps {
  variant: "map" | "number";
  title: string;
  topAreaName?: string;
  topValue?: string;
  unit: string;
  tileMapSvg?: string;
}
```

- `topAreaName`または`topValue`欠損時、Bを描画せずAへ戻す
- raw値をUI内で再計算せず、既存display formatting結果を使う
- Server Componentを維持し、`"use client"`を付けない
- variant解決は純関数にする

## 6. ビジュアル仕様

共通:

- semantic color token、light/dark対応
- 指標名は最大2行、数字は`font-mono tabular-nums`
- 色だけで1位を示さず、`1位`を文字表示
- raw hex、巨大shadow、独自角丸を増やさない
- accessible nameを重複させない

A型:

- 地図はサムネイル面積の45〜60%
- 既存のアンバーリングで1位を強調
- 小カードで読めない凡例は省略可

B型:

- 代表値を最大要素にする
- 単位を値と明確に結合する
- `1位 都道府県名`を下部の固定位置に置く
- 5桁以上、長い小数・単位は縮小しすぎずAへ戻す

## 7. 実装手順

### Phase 0: 現状固定

1. 現在のカードをPC・mobile・darkで撮影
2. home、category、surveyのカードサイズを記録
3. 代表5件のtitle・topAreaName・topValue・unit・tileMapSvgを確認
4. dirty worktreeを確認し、競合ファイルを分離

### Phase 1: 型と解決関数

1. `RankingThumbnailVariant`を正規typesへ追加
2. MetricConfigへ任意設定を追加
3. UIがconfigを直接読めるなら不要なR2フィールドを増やさない。必要な場合だけitemへ焼き込む
4. variant解決を純関数化し、解決順とfallbackを単体テスト

完了条件: 未設定configは変更前と同じA型になる。

### Phase 2: B型visual

1. 既存カード入力だけでB型を描画
2. 欠損・長文・長い単位のfallbackを追加
3. light/darkとアクセシビリティを確認

### Phase 3: 表示場所へ配線

1. homeは既定`number`
2. category / surveyは既定`map`
3. metric明示設定が表示場所の既定を上書きすることを確認
4. OGPは変更しない

### Phase 4: OGP（別PR）

カードUIの検証後に`generate-ogp-images.ts`へB型を展開する。variant解決規則と入力だけ共有し、
UI用HTML/CSSを画像生成へ無理に共有しない。

最終fallbackを`map`に固定する。問題時は呼び出し側の`number`指定とmetric明示設定を外すだけでAへ戻せる構造にする。
初回PRでR2画像を一括上書きしない。
