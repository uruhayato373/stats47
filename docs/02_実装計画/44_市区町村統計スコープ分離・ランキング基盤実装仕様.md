# 市区町村統計スコープ分離・ランキング基盤実装仕様

## 0. 位置づけ

本書は、市区町村統計を47都道府県のテーマ・ランキングから分離し、検索、比較、個別市区町村ページを
一貫した情報設計へ移行するためのClaude Code向け実装契約である。恒久的なページ責務は
`docs/01_技術設計/03_情報設計.md`、実装契約と公開後の判定日は本書を正典とする。

本書を新規作成する理由は、doc 43が日本全国値の意味・取得・R2契約を扱うのに対し、本件は約1,700の
自治体エンティティ、比較集合、検索・絞り込み、ランキング配信、既存city URL移行を独立して所有するためである。
この文書は全work package完了後に削除し、残すべき恒久契約を情報設計、R2設計、コード近傍READMEへ統合する。

ローカルのread、実装、test、dry-runまでは許可する。remote R2 write、git push、PR、deploy、sitemap submit、
GA4管理画面変更は、この文書やTODOに記載されていても実行直前にオーナーの明示承認を得る。

### 0.1 実装状況（2026-08-24）

  検索、県絞り込み、50件ページング、city profile相互導線、known set、middleware、sitemap、navigationを実装済み。

  remote R2は未変更である。

  `/municipalities` で「データ監査中」として表示する。個別特別区を推測生成して公開しない。
- WP7のうちローカル検証だけを行い、remote R2、push、PR、deploy、公開後計測はオーナー承認まで未実行とする。

## 1. 採用する設計

### 1.1 URLとページ責務

```text
/themes/{slug}                              47都道府県のテーマ
/ranking/{key}                              47都道府県ランキング

/municipalities                             市区町村統計ハブ
/municipalities/themes/{slug}               市区町村テーマ
/municipalities/ranking/{key}               市区町村ランキング

/areas/{prefectureCode}/cities/{cityCode}   個別市区町村プロフィール（既存canonicalを維持）

/japan/{slug}                               日本全国値
/world/{slug}                               国際比較（将来）
```

- 公開URLは `cities` ではなく `municipalities` を使う。町・村・東京23特別区を含むためである。
- `municipalities` はCategory、Theme、Tagに加える第四分類軸ではなく、`municipality-set` という地理スコープである。
- `/themes/*` と `/ranking/*` の主語は47都道府県のまま維持する。
- `?areaType=city` を別canonicalとしてindexさせない。公開済み市区町村キーなら専用URLへ遷移させる。
- 個別市区町村URLは検索資産と内部リンクを維持する。今回 `/municipalities/{city}` へ移さない。

### 1.2 型の境界

画面の問いを表す地理スコープと、既存R2・e-Statの保存種別を同じ型として増築しない。

```ts
type StatisticsScope =
  | { kind: "prefecture-set" }
  | { kind: "prefecture"; prefectureCode: string }
  | { kind: "municipality-set"; prefectureCode?: string; peerGroup?: string }
  | { kind: "municipality"; municipalityCode: string; prefectureCode: string }
  | { kind: "japan" }
  | { kind: "world" };
```

- UI、route、canonicalは `StatisticsScope` を使う。
- 観測値の既存 `EntityKind: "city"`、rankingの `AreaType: "city"`、e-Stat area種別は互換性のため維持する。
- `municipality` と `city` の変換は一つのadapterへ閉じ込め、表示コードへ文字列比較を散らさない。
- `municipality-set` の県フィルタや類似団体フィルタは同じページ内のview stateであり、新しいcanonicalを作らない。

### 1.3 自治体エンティティ契約

比較集合の既定は、市、町、村、東京23特別区である。政令指定都市の行政区は自治体ではないため、
自治体ランキングと地方財政から既定で除外する。将来、行政区単位で有効な統計を扱う場合も
`administrative-ward` として親政令市を持たせ、自治体比較へ暗黙に混ぜない。

WP0で既存 `packages/area/src/data/cities.json` と取得データを突合し、少なくとも次を型または生成可能な
git TS policyとして確定する。

```ts
type MunicipalityKind = "city" | "town" | "village" | "special-ward";

type MunicipalityEntityPolicy = {
  code: string;
  name: string;
  prefectureCode: string;
  kind: MunicipalityKind;
  validFrom?: string;
  validTo?: string;
};
```

- 廃置分合、改称、コード変更を現在名への無条件joinで隠さない。
- 最新年ランキングは観測年に有効なentityを使う。歴史系列を現行entityへ合算する場合は明示recipeを要求する。
- 欠測、`-`、非数値、比較対象外は0へ変換しない。
- 指標固有の母集団が異なる場合はcatalogに理由を持たせる。地方財政では財政主体を最優先で監査する。

## 2. 現状と解くべき断絶

2026-08-20のgit TS inventoryではactive MetricConfig 2,193件のうち、市区町村だけを持つもの19件、
都道府県と市区町村の両方を持つもの165件で、候補は計184件ある。これは取得可能性の候補数であり、
公開可能数ではない。entity、年度、値分布、R2 artifact、出典、検索需要のgateを通す前に一括公開しない。

| 現状 | 根拠 | 必要な修正 |
| --- | --- | --- |
| 市区町村観測値は既存namespaceにある | `app/stats/<metric>/cities.json` | 観測値は再利用し、配信メタとURLだけを分離する |
| ranking route loaderは県に固定 | `ranking-page-route.ts`、`load-ranking-page-model.ts` の `AREA_TYPE="prefecture"` | scopeを引数にした共通coreと薄いroute adapterへ分ける |
| ranking values keyがareaTypeを無視 | `rankingValuesKeyPath(rankingKey, _areaType)` | 県valuesを上書きできない市区町村専用namespaceを追加する |
| city-only metricをknown rankingから除外するtestがある | `ranking-key-entities.test.ts` | 県集合と市区町村集合を別generated allowlistとして持つ |
| 地方財政の市区町村UIが県theme配下にある | `/themes/local-finance/cities`、`areaType:"city"` | 新themeへ移し、県themeからは要約リンクだけを置く |
| 個別city profileは既に存在する | `/areas/{pref}/cities/{city}`、stage city allowlist | canonicalを維持し、比較面から接続する |

直近28日の計測snapshotでは、`/themes/local-finance` がGA4 124 PV、旧市区町村財政が7 PV、
個別city profile群が155 PVだった。GSCでは個別city profile群が18 click / 2,398 impressionを持ち、
「自治体 借金 ランキング」「自主財源 比率 ランキング 市町村」の検索も観測された。恒久設計をこの件数に
固定しないが、既存city canonicalを一括移動せず、比較ページを追加する判断の根拠とする。

## 3. Git TS catalogと公開状態

MetricConfigの `entities` は取得可能性を表し、公開可否を兼ねない。市区町村向けの人手で採択する構成は
git TSをSSOTとし、観測値や件数を複製しない。

想定する責務は次のとおり。正確なファイル配置はWP0で既存exportと依存方向を読んでから決める。

```ts
type MunicipalityMetricAvailability =
  | { status: "published"; entityPolicyKey: string; comparisonModes: string[]; valuePolicy?: ValuePolicy }
  | { status: "candidate"; reason: string }
  | { status: "unsupported"; reason: string }
  | { status: "unknown"; reason: string };

type MunicipalityThemeCatalog = {
  slug: string;
  title: string;
  metricKeys: string[];
  defaultMetricKey: string;
  entityPolicyKey: string;
  status: "active" | "draft";
};
```

- `published` だけがknown key、sitemap、内部リンクへ入る。
- `candidate` と `unknown` をUIへ暗黙表示しない。
- `metricKeys` は既存MetricConfigを参照し、title、unit、source、yearsを複製しない。
- theme catalogとranking catalogは同じmetric availabilityを参照する。
- known municipality theme/ranking keysはcatalogから生成し、route、middleware、sitemap、関連リンクが同じ集合を使う。

## 4. R2契約

観測値の正典は既存のまま維持する。

```text
app/stats/{metricKey}/cities.json
```

市区町村ページ用の配信snapshotはURLに対応する専用namespaceへ置く。

```text
app/municipalities/index.json
app/municipalities/themes/{themeSlug}/page.json
app/municipalities/ranking/{rankingKey}/item.json
app/municipalities/ranking/{rankingKey}/values.json
```

- `app/ranking/{key}/item.json` と `values.json` をcityデータで上書きしない。
- `item.json` はMetricConfigとmunicipality catalogから決定的に生成する。手編集JSONをSSOTにしない。
- `values.json` は `cities.json` から公開entity policy、year、null規則を適用した配信用派生物とする。
- 1,700 entity × 全年を初期HTMLへ埋め込まない。初期表示年の上位・下位・要約と、必要なpartitionだけを返す。
- ページ単位のsnapshot、schema、reader、writer、retention、shape gateを同じwork packageで追加する。
- remote write前にkey、件数、hash、追加・更新・削除をplanとして提示する。

`docs/01_技術設計/02_データアーキテクチャ.md` と `.claude/rules/r2-storage-design.md` には、
実装で確定したパスと生成責務だけを反映する。仮案の段階で先に正典化しない。

## 5. UI・UX契約

市区町村ページは47県dashboardの単純複製にしない。entity数と比較の意味が異なるため、次を基本形とする。

### ハブ

- 市区町村向けのテーマ、公開ランキング、個別市区町村検索を一つの入口にまとめる。
- 「都道府県」「市区町村」「日本」「世界」を主語として切り替える。世界が未公開なら無効なリンクを出さない。
- 市区町村数などの時点依存値はsnapshotから表示し、文言へ固定しない。

### テーマ

- 主役は市区町村分布、関係、地域差であり、「全市区町村平均」のKPIを既定表示しない。
- 指標名だけの冗長なカード見出しを繰り返さず、metric switcher、説明、chartを一つの作業面にまとめる。
- 県フィルタ、自治体検索、必要な場合だけ類似団体フィルタを提供する。
- 比較母集団、除外entity、年度、単位、欠測を画面内で説明する。

### ランキング

- 全国の上位・下位要約は表示できるが、1,700行を初期DOMへ出さない。
- 検索、都道府県フィルタ、ページングまたは仮想化を備える。URL queryはview stateとして共有可能にする。
- 地図は全国全entityを常時読み込まず、県絞り込みまたは明示操作後に読む。非対応時はtableだけでも成立させる。
- 行から既存city profileへ遷移し、city profileから同metricの市区町村rankingへ戻れるようにする。
- 値が無いentityを最下位として順位付けしない。

## 6. SEO・移行契約

- 新URLのmetadata、canonical、breadcrumb、structured data、OGPを主語に合わせる。
- 未公開slugはknown setに入れず、既存URL policyの404/410規則へ従う。soft 404を作らない。
- sitemap segmentは既存segment IDを変えず、公開承認時に末尾追加する。
- `/themes/local-finance/cities` は新ページが同等以上になり、canonical、内部リンク、計測を確認してから
  `/municipalities/themes/local-finance` へ301する。
- `/themes/local-finance-city` はredirect chainを作らず、移行時に新canonicalへ直接301する。
- `/ranking/{key}?areaType=city` は、その市区町村rankingがpublishedの場合だけ新URLへ遷移させる。
  未公開キーを存在するように見せない。
- `/areas/{pref}/cities/{city}` は維持する。将来移行する場合は別backlog、GSC実測、redirect map、rollbackを要求する。

## 7. 計測と判断

- 市区町村rankingのpage viewは既存 `ranking_view` と登録済み `area_type=city` を使える。
- page pathが県rankingと市区町村rankingを分離するため、URL由来で取れる値のcustom dimensionを増やさない。
- ナビゲーションclickは既存 `nav_click` / `nav_surface` を使い、新しいsurface値をコードと台帳へ同時追加する。
- custom eventやparameterを追加する場合は `.claude/rules/analytics-event-standards.md` の登録台帳を同じ差分で更新する。
- 公開前にGSC/GA4のURL群baselineを保存し、公開28日・56日後に次を比較する。
  - 市区町村ranking/themeのclick、impression、CTR、engagement、内部遷移
  - 個別city profileへの遷移と検索流入の毀損有無
  - 県theme/rankingへの誤流入、重複canonical、404/soft 404
- page viewだけで拡大を決めない。検索需要、データ品質、次ページ遷移、保守コストを合わせて判断する。

## 8. Work package

Claude Code Sonnet 5 highを既定executorとし、一回のsessionで一つのWPだけを完了させる。
複数writerを同じworking treeで並行させない。各WPの終了時にTODOの再開ポインタだけを更新する。

3. active MetricConfigを `pref-only / city-only / both / other` に決定的に分類する。
4. 市区町村候補について `cities.json`、ranking artifact、latest year、unit、null/zero率、entity数、出典を一覧化する。
5. 現行route、redirect、canonical、sitemap、known keys、個別city allowlistの対応表を作る。
6. 行政区、東京23特別区、政令市本体、廃止entity、重複codeを機械的に分類し、未解決をunknownにする。
7. pilot候補を一つ選ぶ。地方財政は財政主体監査が完了するまでpilotにしない。

成果物は機械JSONを `.claude/state/municipalities/` へ置き、レビュー全文をdocsへ複製しない。

Gate: 候補全件にavailability理由があり、entity母集団とartifact有無を推測していない。コード、R2、URLは未変更。

### WP5 — 地方財政の母集団是正と移行

開始条件: `2026-07-13-theme-local-finance-city.md` の財政主体scopeと最新年監査が解消済み。

1. 市・町・村・東京23特別区を含み、政令指定都市の行政区を除外するfinance entity policyを一次資料と照合する。
2. 0と欠測、政令市本体と行政区、latest year、単位、類似団体比較をfixtureで固定する。
3. `local-finance-city` IndicatorSetをmunicipality theme catalogへ移す。
4. `/themes/local-finance` からcity selectorと市区町村chartを除き、市区町村財政への要約リンクを置く。
5. 新ページのparity確認後に旧2 URLを一段の301へ移す。

Gate: 財政主体の重複・行政区混入・欠測0化が0件で、県地方財政と市区町村地方財政の主語が画面とcanonicalで分離する。

### WP6 — URL、sitemap、navigation、計測

1. page、middleware、sitemap、内部リンクが同じgenerated known setを使う。
2. global navigationまたはhub導線に市区町村を追加し、都道府県を主入口として維持する。
3. 旧query/route redirectを追加し、redirect chain、loop、未知keyの偽200をtestする。
4. 既存eventで計測し、必要なsurface値だけをanalytics台帳へ追加する。
5. local production buildでcanonical、robots、sitemap segment、structured dataをsmokeする。

Gate: known/unknown、old/new、pref/municipalityのroute matrixがgreenで、重複canonicalがない。

### WP7 — release gateと段階公開

1. 対象test、変更package type-check、全package type-check、web full build、docs gateを実行する。
2. local R2 stagingと公開R2のdiff planを作り、pilot key、bytes、hash、rollback prefixを提示する。
3. GSC/GA4 baseline、公開後28日/56日の判定日、停止条件を記録する。
4. owner承認後にだけremote R2、git push、PR、deployを一回にまとめる。
5. 本番でcanonical、200/404/301、R2、mobile/desktop、計測発火を確認する。

Gate: pilotだけがindexableで、県ページとcity profileに回帰がなく、rollbackがkey/commit単位で可能。

**公開順序は deploy → sync-snapshots（★2026-09-01 実測で確定・逆順にすると1 keyしか出ない）**:
`sync-snapshots.yml` は `ref: main` を checkout するため、catalogをdevelopへmergeしただけでは
generatorが新keyを知らない。第1バッチで「develop merge → sync-snapshots」の順に実行したところ、
runはsuccessなのに生成されたのは`elderly-population-ratio` 1件だけで、残り6 keyのR2は404のままだった
（proxyのrunもsync-snapshotsのrunも緑なので、**成果物を実測しなければ気づけない**）。正しい順序:

1. catalog を develop → main へ merge（= deploy。この時点ではR2未生成なのでページは「準備中」を200で返す）
2. `sync-snapshots.yml` を `only=municipality-ranking` で起動（mainのcatalogから全published keyを生成）
3. R2実体を公開URLで実測してからページを確認する

「準備中」を返す窓は手順2の完了まで（実測で数分）。この窓を避けたい場合はsync-snapshotsに
ref入力を足す改修が要るが、他taskへの影響が広いため第1バッチでは採らなかった。

## 10. 停止条件・禁止事項

次の場合は推測、0埋め、allowlist拡大、暫定公開をせず停止する。

- 自治体か行政区か、観測年に有効なcodeかを決定できない。
- 財政主体、単位、年度、母集団が県版や他自治体と同条件でない。
- `cities.json` の欠測、重複、極端なzero、entity不足を説明できない。
- municipality snapshot生成が県 `item.json` / `values.json` を変更する。
- 既存city canonical、redirect、sitemap、GSC資産を壊す可能性がある。
- 対象fileに他者のdirty変更があり、安全に外科的編集できない。
- remote R2 write、push、PR、deploy、GA4登録など外部変更が必要になる。

禁止事項:

- 184候補の一括公開。
- 県と市区町村を同一canonicalのtab/queryだけでindexさせる。
- city-only metricを県ranking known setへ混ぜる。
- 既存 `app/ranking/{key}` をcity payloadで上書きする。
- 行政区を自治体財政主体として集計する。
- 欠測、非数値、対象外を0または最下位へ変換する。
- 個別city URLの一括移行。
- `git add -A`、他者差分のrestore/reset、承認なしの外部反映。

## 11. ロールバック

- route公開可否はgit TS catalogの `active/published` から決定し、pilotだけを外せるようにする。
- municipality R2 namespaceは県rankingと分離し、prefix単位で復元または削除できるようにする。
- 旧routeの301は最終移行WPまで追加せず、追加後もredirect mapを一つ戻せば旧ページへ戻せるようにする。
- city profileは変更しないため、比較面を止めても個別市区町村の検索資産は維持される。
- schema versionを持たせ、readerとwriterを同じcommit境界で戻せるようにする。
