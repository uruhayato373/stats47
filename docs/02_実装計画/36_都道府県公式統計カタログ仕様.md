# 都道府県公式統計・ダッシュボードカタログ仕様

## 1. 目的

47都道府県が公式公開する統計ポータル、可視化ダッシュボード、オープンデータ、統計年鑑を一元管理し、そこで反復して採用される指標を stats47 のランキング・テーマ拡充候補として抽出する。

自治体による掲載は検索需要そのものではないが、予算・担当者・更新運用が割かれた需要シグナルである。単一自治体の掲載だけで採用せず、複数自治体での反復、掲載位置、更新性、比較機能、stats47 の情報設計との適合を合わせて判断する。

## 2. 成功条件

1. JIS X 0401順で47都道府県すべてに1件以上の公式統計リンクがある。
2. URL、種別、分野、発行主体、発見元、確認日をgit TSで管理できる。
3. 同一県に統計ポータル、分野別ダッシュボード等を複数追加できる。
4. 47件、コード重複、URL形式、公式ドメイン、列挙値を機械検証できる。
5. リンク到達性を通常の型チェックと分離してオンデマンド検証できる。
6. 掲載指標を正規化し、既存指標との照合後、検証済み候補だけを `docs/todo/03_指標バックログ.md` へ送れる。

## 3. SSOTと責務

| 対象 | 正典 | 理由 |
|---|---|---|
| 公式リンクと分類 | `packages/data-configs/src/prefecture-statistics-catalog/` | authored referenceとして型・レビュー・差分管理する |
| 詳細設計と判断基準 | 本文書 | 人間が読み返す運用仕様 |
| 未採用の指標候補 | `docs/todo/03_指標バックログ.md` | 指標拡充TODOの既存SSOT |
| 採用済みテーマ構成 | `packages/data-configs/src/theme-catalog/*.ts` | ThemeCatalogの既存SSOT |
| 観測値 | R2 snapshot | 完全DBレス設計に従う |

永続D1、手編集JSON、新しいリンク管理DBは作らない。カタログをWeb表示する場合も、将来git TSからR2 JSONを生成する。現段階では内部調査基盤であり、本番ページは追加しない。

## 4. データモデル

### 4.1 都道府県エントリ

- `prefectureCode`: JIS X 0401の2桁コード
- `prefectureName`: 表示名
- `resources`: 公式リソースの配列。1県に複数登録可能

### 4.2 リソース

- `id`: `<都道府県コード>-<用途>` の安定キー
- `title`: 公式名称または内容が分かる名称
- `url`: HTTPSの公式URL
- `type`: 下記のリソース種別
- `topics`: 扱う統計分野。複数可
- `publisher`: 発行主体
- `isOfficial`: 公式資料のみを入れるため常に `true`
- `discoveredFrom`: 発見・照合に使ったページ
- `lastVerifiedAt`: URLまたは内容を最後に確認した日
- `notes`: 粒度、更新制約、別ドメイン等の補足

### 4.3 リソース種別

| type | 定義 |
|---|---|
| `statistics-portal` | 県統計主管課等の総合入口 |
| `dashboard` | 統計探索・比較を主目的とした可視化UI |
| `open-data-portal` | データセット検索・ダウンロード中心 |
| `statistical-yearbook` | 統計年鑑・県勢要覧等 |
| `policy-dashboard` | 総合計画、EBPM、KPI進捗等の政策可視化 |

「県公式ドメインからリンクされた外部BI」は、発行主体が県であることを公式ページで確認できた場合のみ登録する。単なる委託事業者のサービス紹介は登録しない。

## 5. 初期カバレッジ

初期版は47都道府県すべての統計主管部門・統計ポータルを登録する。全国一覧の発見元は一橋大学経済研究所附属社会科学統計情報研究センター「地方統計へのリンク」で、各URLは県公式ドメインへ正規化した。

- 都道府県: 47/47
- 公式リソース: 47件
- 初期種別: `statistics-portal`
- 分野: 総合統計 `general`
- 確認基準日: 2026-07-18

分野別ダッシュボードは同じ `resources` に追加する。初期網羅と二次深掘りを混同せず、未確認URLを推測で登録しない。

## 6. 指標需要の抽出手順

### Phase A: リソース発見

1. 統計ポータルから「ダッシュボード」「見える化」「オープンデータ」「統計年鑑」を探索する。
2. 発行主体、公式ページからの導線、更新日を確認する。
3. カタログへ追加し構造検証・リンク検証を実行する。

### Phase B: 掲載指標の収集

各リソースから次を記録する。

- 原文指標名
- 指標の定義・単位
- 対象地域粒度（都道府県、市町村、圏域、メッシュ）
- 対象年と更新頻度
- 表現形式（KPI、地図、ランキング、時系列、構成比）
- データ出典と統計調査名
- 掲載位置（トップ、主要カテゴリ、下層資料）

### Phase C: 正規化

「総人口」「人口総数」「県人口」などの表記揺れを同一概念へ寄せる。正規化キーは既存 `rankingKey` があれば必ず再利用する。似ているが分母、対象年齢、名目・実質、実数・率が違うものは統合しない。

### Phase D: stats47照合

候補を次の4区分に分類する。

1. `existing`: 同一定義の公開指標がある
2. `near-duplicate`: 類似指標はあるが定義差がある
3. `candidate`: 未掲載で47都道府県データを取得できる可能性がある
4. `local-only`: 市町村・県独自調査等で全国比較不能

### Phase E: 実在検証と採用

`candidate` はe-Stat等の一次データで、統計表ID、分類コード、47都道府県可否、直近年、既存重複を確認する。確認済み候補だけを `docs/todo/03_指標バックログ.md` に追加する。テーマ採用時は `theme-designer` 相当の判断を経てThemeCatalogへ反映し、観測値は既存のdata-ingester経路でR2へ投入する。

## 7. 需要スコア

自治体掲載を過大評価しないため、指標候補ごとに以下を記録する。

| 要素 | 点数 | 意味 |
|---|---:|---|
| 採用都道府県数 | 1県につき3 | 横断的な行政・住民需要 |
| トップまたは主要画面掲載 | 1県につき2 | 情報設計上の重み |
| 直近2年以内に更新 | 1県につき1 | 継続需要 |
| 市町村比較または時系列比較あり | 1県につき1 | 意思決定用途の強さ |
| stats47既存テーマに適合 | 2 | 導入コストと回遊性 |
| 47都道府県データ取得可能 | 3 | 実装可能性 |

優先度の目安:

- high: 20点以上、かつ47都道府県データを確認済み
- medium: 10〜19点
- low: 9点以下、または地方固有性が強い

GSC需要、競合掲載、白書での重要性が確認できる場合は別軸の根拠として併記する。需要スコアだけで自動採用しない。

## 8. 品質ゲート

### 構造検証

```bash
npm run validate:prefecture-statistics --workspace packages/data-configs
```

検証内容:

- 47都道府県が存在する
- 都道府県コードとresource IDが一意
- 各県に1件以上のリンクがある
- HTTPSかつ都道府県公式ドメイン
- type/topicが許可リスト内
- 確認日がISO日付形式

### 到達性検証

```bash
npm run check:prefecture-statistics-links --workspace packages/data-configs
```

外部サイトの一時障害やbot対策の影響を受けるため、通常の型チェックから分離する。HTTP 403は公式サイトのbot拒否として到達扱い、404/5xx/タイムアウトは人間がリダイレクト先を調査する。

### 型検証

```bash
npm run type-check --workspace packages/data-configs
```

## 9. 更新ルール

1. リンク移転時は既存resource IDを維持してURLと確認日を更新する。
2. 同一目的の新URLへの完全移行なら旧URLを残さない。履歴はgitで確認する。
3. 別目的のダッシュボードなら新resourceとして追加する。
4. 県公式ページから辿れない外部URLには、公式性を示す発見元URLを必須とする。
5. `lastVerifiedAt` は実際に確認したときだけ更新する。
6. 掲載指標の抽出前に既存metricsとThemeCatalogを読み、重複候補を量産しない。

## 10. 今回実装した範囲と次の反復

完了:

- 47都道府県の公式統計入口をgit TSで一元化
- 複数リンク、分類、分野、発見元、確認日に対応した型定義
- 構造検証と外部リンク到達性検証
- package rootからの参照用export
- 指標需要抽出から既存バックログ・ThemeCatalog・R2までの連携仕様

次の反復は、各県ポータルから分野別ダッシュボードを収集し、掲載指標を正規化する調査工程である。47県の入口カタログはその作業のSSOTとして利用できる状態にある。
