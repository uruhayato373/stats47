# 収益化実装方針 (P1-P2 実行計画)

## 0. 位置づけ

- 親: `docs/02_実装計画/01_収益化マスタープラン.md`。本計画は SSOT の **P1「収益密度」** と **P2「トラフィック成長」内の高単価アフィ記事** を具体化する従属計画。
- 目的: アクセス増を **週次収益** に変換する。PV 増だけを追わず、検索流入が集中する `/ranking` と `/blog` の収益密度を先に上げる。
- 原則: **計測 → 1 系統ずつ実装 → 4 週判定 → 次施策**。同じページ種別・同じデバイスに複数変更を同時投入しない。
- TODO の真実源: 実装着手・status・due は `03_改善バックログ.md` に記録する。本計画は「何をどう実装するか」の判断基準を定める。
- note は自サイトの代替ではなく、ドメイン評価を借りる **外部衛星ページ** として扱う。正典データ・比較体験・CV 導線は stats47 側に残す。

## 1. 実装判断

### 主戦場

| ページ | 役割 | 収益化方針 |
|---|---|---|
| `/ranking/[key]` | 検索集客エンジン① | AdSense in-content を主役にする。文脈一致する一部指標のみアフィを置く |
| `/blog/[slug]` | 検索集客エンジン② | AdSense viewability 最適化 + 高単価アフィ記事を少数作る |
| `/areas/[code]` | 県軸ハブ | ふるさと納税・引越しなど地域インテントのアフィを置く |
| `/themes/[slug]` | 回遊・比較面 | 収益化は後回し。内部リンクと体験品質を優先 |
| `/category/[key]` | ナビ面 | 広告・アフィを増やさない。ランキング導線を優先 |

### やらないこと

- 全ページ共通で広告枠を増やす。
- アフィ在庫を文脈なしに横展開する。
- GA4 / AdSense / ASP の計測が未整備のまま、アフィ枠を増やす。
- note / YouTube / SNS を収益化の主戦場にする。P3 ゲートまでは SEO + blog に集中する。ただし note は §4 の SEO 衛星ページ実験に限り、低工数で使う。

## 2. AdSense 実装方針

### P1-A: `/ranking` モバイル本文中広告

既存施策 `ADSENSE-MOBILE-INCONTENT-01` を主軸にする。モバイル読者が通過する本文中、特にチャート・ランキング表・考察の近辺を優先する。

| 項目 | 方針 |
|---|---|
| 対象 | `/ranking/[key]` mobile |
| 位置 | 考察直下またはチャート直下。折りたたみセクション下・最下部依存にしない |
| 実装条件 | CLS 予約を必須にする。`AdSenseAd` の予約高・統一レイアウト規約を維持 |
| 判定 | device=mobile × unit=ranking-incontent-mobile の viewable imp / CTR / RPM |
| 判定期間 | deploy 後 4 週 |

### P1-B: 低効率枠の整理

`ADSENSE-MOBILE-INCONTENT-01` の判定完了後に着手する。特に ranking 最下部枠のように CTR 0%・到達率が低い枠は、廃止または上方移設を検討する。

| 対象 | 判断 |
|---|---|
| ranking footer | mobile in-content の 4 週判定後に廃止 / 上方移設を比較 |
| desktop sidebar | viewability が低い場合は位置調整。desktop と mobile は別セグメントで評価 |
| home / category | 入口・ナビ面なので広告追加は優先しない |

### P1-C: `/blog` 枠最適化

blog は検索流入が大きいが、記事体験を壊すと CTR / 回遊に悪影響が出る。本文冒頭直後の過密配置は避け、読了前に 1-2 箇所の見える枠を置く。

| 項目 | 方針 |
|---|---|
| 対象 | 高流入 blog 記事から順に検証 |
| 位置 | 導入後すぐではなく、最初の実データ・解釈ブロック後を優先 |
| 判定 | blog page group の RPM / viewability / scroll depth / GSC CTR |

## 3. アフィリエイト実装方針

### 基本原則

アフィは「枠を増やす」ではなく「検索意図から自然に次の行動へ進める」設計にする。低文脈バナーは CTR を下げ、サイトの信頼も削るため置かない。

| インテント | 商材 | 配置先 | 優先度 |
|---|---|---|---|
| 地域を選びたい | ふるさと納税 | `/areas/[code]` | 高 |
| 引越し・移住を考える | 引越し比較 | `/areas/[code]`, 移住系 blog | 高 |
| 所得・年収を上げたい | 転職 / キャリア相談 | 年収・所得 ranking / blog | 高 |
| 子育て・教育環境を比べたい | 通信教育 / 学習サービス | 教育 ranking / blog | 中 |
| 住まいを検討する | 不動産査定 / 住宅相談 | 住宅・地価・人口移動系 blog | 中 |

### P1-AFF-01: 計測を先に通す

アフィ枠拡大の前提は計測。最低限、クリックイベント・リンク種別・ページ種別・商材カテゴリを追える状態にする。

| 計測項目 | 目的 |
|---|---|
| `affiliate_click` | 週次クリック数を見る |
| page type | `/areas` / `/ranking` / `/blog` のどこで効くか分ける |
| offer category | ふるさと納税 / 引越し / 転職 / 教育を分ける |
| placement | sidebar / in-content / CTA など位置別に見る |

### P1-AFF-02: `/areas` 地域インテント

最初に広げるなら `/areas/[code]`。県ページは「この地域を知りたい」という意図があり、ふるさと納税・引越しとの接続が自然。

| 商材 | 実装方針 |
|---|---|
| ふるさと納税 | 既存枠を維持し、県名・強み/弱みの文脈に近い位置で CTA を出す |
| 引越し比較 | ASP 提携リンク取得後、area sidebar または県別テーマ導線付近に追加 |

### P2-AFF: 高単価 blog 記事

P1 の計測が通った後に、少数の高単価アフィ記事を作る。データ起点の記事にして、商材のための記事にしない。

| 記事テーマ | 対象商材 | 狙い |
|---|---|---|
| 年収が高い都道府県と転職しやすい地域 | 転職 / キャリア相談 | 所得 ranking から高単価 CV へ接続 |
| 移住前に見るべき都道府県データ | 引越し比較 | 人口移動・住宅・所得・教育を束ねる |
| 子育てしやすい県の統計比較 | 通信教育 / 生活系 | 教育・医療・所得を束ねる |
| 住宅費と所得のバランスがよい地域 | 引越し / 不動産 | 住宅・地価・所得の複合意図 |

## 4. note SEO 衛星ページ方針

### 基本判断

note の強みはドメイン評価と読み物としての届きやすさにある。stats47 本体で正典データを持ち、note は広めの検索意図・問題提起・解釈で入口を作る。

| 役割 | 置くもの | 置かないもの |
|---|---|---|
| note | 問い、読み物、仮説、統計の見方、stats47 への文脈リンク | 47都道府県の完全データ表、ランキング全文、正典コンテンツ |
| stats47 | データ本体、ランキング、県ページ、比較体験、広告 / アフィ導線 | note 向けの軽い随筆だけの記事 |

### 実験条件

note は「月1誘導のみ」から、**高単価テーマに限り月2本までの SEO 実験** を許可する。ただし新規工数を増やしすぎないため、stats47 の既存 ranking / blog を再編集して作る。

| 条件 | 内容 |
|---|---|
| 対象テーマ | 移住、年収、子育て、教育、住宅、ふるさと納税 |
| 本数 | 月2本まで |
| 導線 | 本文中 2-4 箇所で stats47 の ranking / area / blog へ送る |
| 計測 | note → stats47 の流入、リンククリック、収益ページ到達を確認 |
| 禁止 | note だけで完結する有料記事化、stats47 本体との全文重複 |

### 候補テーマ

| note テーマ | stats47 導線 | 収益接続 |
|---|---|---|
| 年収が高い県に住めば豊かになれるのか | 所得 ranking / 住宅費 blog | 転職 / キャリア相談 |
| 地方移住で後悔しないために見るべき統計 | 人口移動 / 住宅 / 医療 / 教育 ranking | 引越し比較 |
| 子育てしやすい県ランキングは本当に信用できるのか | 教育 / 医療 / 所得 ranking | 教育 / 生活系 |
| ふるさと納税で人気の県と地域力は一致するのか | area ページ / ふるさと納税関連 ranking | ふるさと納税 |

### 判定

note views は主指標にしない。成功は **note から stats47 に流入し、収益ページまで進んだか** で判定する。

| 指標 | 判定 |
|---|---|
| note → stats47 sessions | 入口として機能したか |
| stats47 内の収益ページ到達 | `/ranking` / `/areas` / 高単価 blog へ送れたか |
| affiliate_click / AdSense RPM | 収益導線に接続できたか |
| GSC cannibalization | stats47 本体の ranking / blog を食っていないか |

## 5. 実装順序

| Step | 内容 | ゲート |
|---|---|---|
| 1 | AdSense mobile in-content の 4 週判定 | device=mobile の RPM / viewability を確認 |
| 2 | ranking 低効率枠の廃止 / 上方移設 | Step 1 の効果分離が完了 |
| 3 | アフィ計測の GA4 / ASP 確認 | `affiliate_click` が週次で見える |
| 4 | `/areas` に引越し比較を追加 | ASP 提携リンク取得 + 計測稼働 |
| 5 | 高単価 blog 記事を 2-4 本作成 | Step 3 の計測稼働 + blog 品質 gate PASS |
| 6 | note SEO 衛星ページを月2本まで実験 | stats47 への流入計測ができる |
| 7 | 効果が出た商材だけ `/ranking` に限定展開 | page type 別 CTR / CV が確認できる |

## 6. 成功指標

| 期間 | 主要指標 | 目安 |
|---|---|---|
| P1 | AdSense RPM | ¥100+ |
| P1 | AdSense カバレッジ | 50%+ |
| P1 | affiliate_click | 週次で安定計測できる |
| P2 | note → stats47 流入 | 高単価テーマで増加 |
| P2 | アフィ初成果 | 月 1-3 件 |
| P2 | 月間収益 | ¥15,000 を目指す |

評価は週次収益を主指標にし、補助指標として GSC clicks / AdSense RPM / affiliate_click を見る。PV 単体は成功指標にしない。

## 7. リスクと対処

| リスク | 対処 |
|---|---|
| 広告増で UX / CWV が悪化 | CLS 予約・PSI 日次・GSC CTR を同時監視する |
| 同時変更で効果分離できない | 同一 page type / device の変更は 4 週ごとに 1 系統に絞る |
| アフィが低 CTR のまま増殖する | クリック計測がない商材は増やさない。CTR が低い枠は撤去する |
| データサイトの信頼感を損なう | CTA は統計解釈の後に置く。商材ありきの見出しにしない |
| ASP 成果が管理画面でしか見えない | 月次で人間が成果額を確認し、週次収益に反映する |
| note が stats47 本体を cannibalize する | note は問い・解釈に限定し、完全データ表と比較体験は stats47 に置く |
