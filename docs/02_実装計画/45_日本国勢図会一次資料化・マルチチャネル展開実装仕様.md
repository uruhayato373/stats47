# 日本国勢図会一次資料化・マルチチャネル展開実装仕様

## 0. 文書の位置づけ

本書は、『日本国勢図会』で扱われる統計と論点を全件棚卸しし、数値は一次資料から再取得したうえで、
stats47 の既存データ・ページ・コンテンツへ展開するための実装契約である。進捗と次の実行単位は
`.claude/todo/backlog.md` の `JAPAN-ZUE-CONTENT-PIPELINE-01` を正典とする。

本書が新しい公開 taxonomy を定義することはない。公開分類は
[`03_情報設計.md`](../01_技術設計/03_情報設計.md) の Category / Theme / Tag を維持し、
『日本国勢図会』は内部の `evidence source` としてだけ扱う。調査への紐付けは
`.claude/rules/survey-linkage-standards.md`、観測値の出典は
`.claude/rules/data-provenance-standards.md`、SNS・動画展開は
`.claude/rules/sns-content-standards.md` を正典とし、本書へ規則を複製しない。

private Google Drive source vaultの版追加・差し替え、remote R2 write、git push、PR、本番 deploy、
YouTube / Instagram / X / note への公開は本書の自動承認範囲に含めない。差分・対象・検証結果を提示し、
各既存規約に従ってオーナー承認を得る。

## 1. ゴールと「全て活用」の定義

ゴールは、書籍に登場する定量的な表・図・本文中統計を漏れなく inventory 化し、各項目へ次のいずれかの
解決結果を与えることである。

| resolution | 意味 | 次の処理 |
| --- | --- | --- |
| `reuse-existing-metric` | stats47 に同じ定義の metric がある | 既存 metric と survey / theme / content を接続 |
| `new-metric` | 一次資料から再取得でき、独立 metric に値する | MetricConfig と R2 観測値を追加 |
| `combined-analysis` | 単独ページでは薄いが、複数指標の分析に使える | Theme / blog / video の構成要素へ統合 |
| `context-only` | 数値より背景・論点として価値がある | 一次資料で検証し、分析文脈だけに利用 |
| `primary-source-unavailable` | 一次資料を特定または再取得できない | 公開せず、代替資料の探索待ち |
| `rights-hold` | 民間資料等で再利用条件を確認できない | 許諾または代替資料が確定するまで停止 |
| `not-quantitative` | 写真・概念図・目次等で統計ではない | 母数から除外し、理由を保持 |

「全て活用」は、全項目を別々の Web ページへ量産することではない。全定量項目が inventory に存在し、
重複統合、既存 metric 再利用、複合分析、保留を含めて一つの解決結果を持つことを指す。
完了率は `resolution が確定した定量項目数 / 抽出した定量項目数` で計算し、100% を要求する。

新版は上書きせず差分として取り込む。

## 3. 著作権・表現・利用条件の境界

運用上の原則は「書籍から論点を発見し、事実と数値は一次資料から再取得し、構成と表現はstats47で作る」である。
単純な事実・データやアイデアは一般に著作権の保護対象ではない一方、書籍の文章、図表表現、見出し、
選択・配列には権利が成立し得る。これは法的断定ではなく、公開事故を避けるための制作境界である。

- inventory に書籍本文、表の数値列、画像データを複製しない。内部参照に必要な版・章・ページ・図表番号だけを持つ。
- 書籍の文章を言い換えるだけの原稿、図表デザインの模倣、章順を維持した連続公開を禁止する。
- 一次資料の利用条件、第三者権利、商用利用、出典表示、加工表示を確認する。
- 公開物は一次資料を出典にし、書籍スキャンやOCRをデータ出典として表示しない。
- 書籍を着想元として表示する場合も、必要最小限の書誌情報にとどめる。
- 民間調査、新聞社集計、有償データ、写真、地図は「公開されている」だけで再利用可と判断しない。

判断根拠は、[文化庁の著作権制度解説](https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/)、
[政府標準利用規約](https://www.digital.go.jp/resources/open_data/)、
[矢野恒太記念会 FAQ](https://yt-ms.jp/faq/) の最新版を一次確認する。規約が曖昧な項目は `rights-hold` で停止する。

## 4. データモデル

### 4.1 安定ID

候補 ID は `<source>-<edition>-p<page>-<kind><seq>` とする。

```text
japan-zue-2025-26-p026-table01
japan-zue-2025-26-p026-figure01
japan-zue-2025-26-p026-textstat01
```

ページをまたぐ同一表は開始ページのIDへ統合し、継続ページを `continuationPages` に持つ。OCRの抽出順や
ファイル名を変えてもIDが変わらないよう、再抽出時は版・ページ・図表番号で照合する。

### 4.2 Authored inventory

人が確認する判断は git TS の `packages/data-configs/src/evidence-inventory/japan-zue/` を SSOT とする。
候補抽出JSONと集計レポートは派生物であり、手編集しない。最小 contract は次とする。

```ts
type JapanZueEvidenceItem = {
  id: string;
  source: {
    key: "japan-zue";
    edition: "2025-26";
    chapter?: number;
    page: number;
    continuationPages?: number[];
    kind: "table" | "figure" | "text-stat";
    itemNumber?: string;
  };
  topicHint: string;
  resolution:
    | "unreviewed"
    | "reuse-existing-metric"
    | "new-metric"
    | "combined-analysis"
    | "context-only"
    | "primary-source-unavailable"
    | "rights-hold"
    | "not-quantitative";
  primarySource?: {
    organization: string;
    publicationOrDataset: string;
    datasetId?: string;
    url: string;
    termsUrl?: string;
    dataYears: string[];
    checkedAt: string;
    rights: "allowed" | "needs-review" | "blocked";
  };
  mapping?: {
    metricKeys?: string[];
    surveyIds?: string[];
    categoryKey?: string;
    themeSlugs?: string[];
    geoScopes: Array<
      "prefecture-set" | "prefecture" | "municipality-set" | "japan" | "world"
    >;
    contentRoles?: Array<
      "ranking" | "survey" | "theme" | "area" | "blog" | "note" | "youtube" | "instagram" | "x"
    >;
  };
};
```

実装時は既存export、型依存、命名を確認して最小の共通型へ置く。schema は書籍の数値、本文、画像パスを
保持できない形にし、書籍由来の値が誤って観測値へ昇格する経路を作らない。

### 4.3 保存先

| データ | SSOT / 出力 | 編集規則 |
| --- | --- | --- |
| 書籍source bundle | private Google Drive `stats47-private-sources/japan-zue/<edition>/` | 版ごとの不変分割archive。共有禁止 |
| source bundle manifest | `.claude/state/source-inventory/japan-zue/<edition>/source-bundle-manifest.json` | Git管理。bundle・part・全入力fileのSHA-256を保持 |
| OCR・スキャン作業コピー | `books/日本国勢図絵/` | private Driveから復元するgitignoredコピー。公開データへ直接流さない |
| 機械抽出候補 | `.claude/state/source-inventory/japan-zue/2025-26/candidates.json` | generator 出力、手編集禁止 |
| 人手確認済み判断 | `packages/data-configs/src/evidence-inventory/japan-zue/` | git TS、型・review・validator必須 |
| 統計メタ | `packages/data-configs/src/metrics/` | 既存 MetricConfig がSSOT |
| 観測値 | R2 `app/stats/`、`app/japan/`等 | 一次資料から取得・生成 |
| 調査taxonomy | 既存 surveys / provenance resolver | inventoryに独自resolverを作らない |
| Theme配置 | 既存 ThemeCatalog / page_components | evidence sourceから既存catalogへ写像 |
| 制作・公開状態 | 既存記事・SNS posts・experiment SSOT | inventoryに投稿台帳を複製しない |
| 機械集計 | `.claude/state/source-inventory/japan-zue/2025-26/summary.json` | coverage、未解決、重複の派生値 |

### 4.4 private Google Drive source vault

別PC共有はGoogle Drive MCPで接続したオーナーのprivate Driveを使う。既存のCloudflare R2 `stats47` bucketは
`https://storage.stats47.jp`から認証なしで読める公開配信用であり、書籍sourceを置いてはならない。
Drive側の固定階層は次とする。

```text
stats47-private-sources/
└── japan-zue/
    └── 2025-26/
        ├── stats47-japan-zue-2025-26-r1.manifest.json
        ├── stats47-japan-zue-2025-26-r1.tar.gz.part-001
        ├── ...
        └── stats47-japan-zue-2025-26-r1.tar.gz.part-006
```

Google Drive MCPの単一ファイル上限100MBを超えないよう、archiveは90MiB以下のpartへ分割する。版・revision単位で
不変とし、訂正や再OCRでは既存partを上書きせず新しいrevision名を発行する。Driveのfolder / file IDとURLは
公開Gitへ保存しない。別PCのagentはDrive MCPでMy Drive rootをlistし、観測したfolder URLを順に辿って
Git manifestの一意なファイル名と照合する。connectorの検索index反映を前提にしない。

manifestはDriveにも同名で複製するが、検証の正典はGit版とする。最小contractは次とする。

```ts
type SourceBundleManifest = {
  schemaVersion: 1;
  sourceKey: "japan-zue";
  edition: "2025-26";
  revision: number;
  sourceRootName: "日本国勢図絵";
  storage: {
    provider: "google-drive";
    visibility: "private";
    folderPath: string;
  };
  bundle: {
    fileName: string;
    format: "tar.gz";
    sha256: string;
    bytes: number;
    parts: Array<{ index: number; fileName: string; sha256: string; bytes: number }>;
  };
  fileCount: number;
  componentCounts: {
    markdown: number;
    figures: number;
    pageImages: number;
    ocrRaw: number;
    transcripts: number;
    pdfs: number;
    auxiliary: number;
  };
  createdAt: string;
  files: Array<{ path: string; bytes: number; sha256: string }>;
};
```

決定的なcreate / verify / restoreは次の入口に統一する。

```bash
npm run source-vault:japan-zue -- create
npm run source-vault:japan-zue -- verify --manifest <manifest> --parts-dir <download-dir>
npm run source-vault:japan-zue -- restore --manifest <manifest> --parts-dir <download-dir>
```

- createはarchiveをリポジトリ内へ出力しようとしたら停止し、symlinkを含むsourceも拒否する。
- Drive upload後は7ファイル（manifest 1 + part 6）の名前・size・`shared:false`をreadbackする。
- verifyはpartごとのsize / SHA-256と合計bytesをGit manifestへ照合する。
- restoreは既存`books/日本国勢図絵/`を上書きせず、partを一時archiveへ結合し、bundle SHA、1,746ファイルの
  path / size / SHAを検証してから同一filesystem上でatomicに配置する。
- source bundleはWeb、公開R2、SNS素材、デプロイartifact、公開共有リンクから参照しない。NotebookLMへ追加する場合も
  オーナー専用ノートブックに限定し、公開リンクを作らない。

## 5. 既存taxonomy・ページ・媒体への配置

| inventoryの性質 | 主配置 | 補助配置・導線 |
| --- | --- | --- |
| 47都道府県を同条件で比較できる単一指標 | `/ranking/[key]` | survey / category / theme / area |
| 同じ統計調査に属する複数指標 | `/survey/[key]` | rankingへの出典調査導線 |
| 複数指標で社会的な問いを説明できる | `/themes/[slug]` | evidence lens、ranking、area |
| 一つの県の特徴を補強する | `/areas/[code]` | ranking、themeへの要約リンク |
| 公式全国値・全国時系列 | `/japan/[slug]` | themeとの主語を分離 |
| 同一定義の国際比較 | 将来の `/world/[slug]` | Japanとの比較。基盤完成前は公開しない |
| 問い・意外性・背景を文章で説明する | blog / note | 根拠ranking・themeへ送客 |
| 複数指標を物語として説明する | YouTube通常動画 | Reels / Xへ派生、サイトへ送客 |

書籍の章名をCategoryやThemeへ機械変換しない。既存17 Category、ThemeCatalog、Tag、Evidence lensで
表現できない場合だけ既存ownerが採否を判断し、新しい第四分類軸は作らない。

## 6. 処理パイプライン

```text
全ページ列挙
  → 表・図・本文統計の候補抽出
  → 原本との存在・番号照合
  → 一次資料名候補の抽出
  → 一次資料の特定・利用条件確認
  → 既存metric / survey / themeとの重複解決
  → resolution確定
  → 一次資料から観測値取得・provenance記録
  → Webの責務へ配置
  → master記事・通常動画を制作
  → note / Reels / Instagram / Xへ派生
  → provenance・survey・内部導線・投稿台帳を横断監査
```

### NotebookLM / LLM の役割

NotebookLM は章単位の論点分類、一次資料名候補、関連項目のクラスタリングに使える。ただし、OCRやNotebookLMの
回答を数値の根拠にせず、`verified` 相当の判断を自動確定しない。列挙、ID採番、重複、status遷移、coverage計算は
決定的コードが担当し、モデルは論点、独自の問い、配置判断、文章制作にだけ使う。

## 7. 機械ゲート

### 7.1 inventory gate

- 504ページが一度ずつ走査され、欠番・重複ページがない。
- 表・図番号の章内連続性を検査し、欠番に理由がある。
- `id` は一意で、同一版の再生成で安定する。
- 定量項目の `resolution=unreviewed` が公開候補に残らない。
- `reuse-existing-metric` / `new-metric` / `combined-analysis` / `context-only` は一次資料を持つ。
- `primarySource.rights=allowed` 以外は production queue へ進まない。
- OCR値、書籍本文、スキャン画像パスを inventory schema が受け付けない。

### 7.2 data / taxonomy gate

- e-Statは `statsDataId`、非e-Stat手動抽出は provenance 9点セットを持つ。
- 年度、単位、地域粒度、母集団、集計方法が書籍ではなく一次資料で確定している。
- 既存 metric と同じ定義を新しい key で重複登録しない。
- 単位、値分布、47県coverage、欠測、0、負値、外れ値を既存validatorで検査する。
- surveyは共通resolverから導出し、theme / blogに手書き `surveyId` を追加しない。
- ThemeCatalog、ranking、blog、surveyの横断taxonomy監査を悪化させない。

### 7.3 expression / content gate

- 公開原稿とOCR本文の正規化n-gram比較を行い、長い連続一致を検出したら人間reviewへ送る。
- 統計調査名、法令名等の不可避な固有表現だけをallowlistにし、本文の機械言い換えを許可しない。
- 公開図表は一次資料の値から独自に生成し、書籍figureを素材にしない。
- 分析は独自の問い、比較軸、計算または地域差の説明を少なくとも一つ持つ。
- article / video / postは `metricKeys`、`surveyIds`、`provenanceUrls` を引き継ぐ。
- 同じ情報をranking / theme / blogへ全文複製せず、各ページ責務に合わせて要約とリンクで接続する。

### 7.4 proposed CLI contract

次のコマンドはWP1で実装する契約であり、2026-08-27時点では未実装である。

```bash
npm run evidence:extract -- --source japan-zue --edition 2025-26 --dry-run
npm run evidence:validate -- --source japan-zue --edition 2025-26
npm run evidence:coverage -- --source japan-zue --edition 2025-26 --check
npm run evidence:expression-audit -- --source japan-zue --edition 2025-26
```

個別の metric、survey、theme、blog は既存の検証入口を再利用し、同じvalidatorを本pipeline用に複製しない。

## 8. Work package

### WP0 — 設計と管理契約

1. 本実装仕様と単一backlogカードを作る。
2. 「書籍はevidence source、公開taxonomyではない」を固定する。
3. 全件活用、一次資料昇格、権利保留、外部公開の停止線を定義する。

Gate: `npm run docs:check` が成功し、実装仕様がTODOから一意に参照される。

### WP1 — schema・extractor・代表40ページpilot

1. source bundle manifest generatorとprivate R2のdry-run push/pullを実装し、通常配信bucketへ書けないtestを置く。
2. オーナー承認後にprivate bucketを作成し、2025/26版bundleを一度だけuploadしてHEAD / SHAを照合する。
3. p.26–65を対象に、table / figure / text-stat候補を決定的に列挙する。
4. typed inventory、schema validator、stable ID、summary generatorを実装する。
5. 表のページ継続、同一項目の図表併記、OCR見出し漏れをfixture化する。
6. 代表10項目を選び、既存metric、e-Stat、府省PDF/XLSX、国際・民間資料を少なくとも一つずつ含める。

Gate: private source bundleを別の一時ディレクトリへ復元して同じhash / 件数を再現でき、再抽出でIDと候補件数が
安定する。書籍の値はinventoryへ出力されない。

### WP2 — 全504ページinventory

1. 13範囲を分割処理し、921見出しを起点に全ページを走査する。
2. 章・表・図番号の欠落、重複、継続ページ、本文統計を監査する。
3. p.1–25の定量項目有無と、2025/26年版の訂正情報を確認する。
4. 全定量項目へ `resolution` の初期判断を付ける。

Gate: 抽出母数が確定し、unreviewed・欠番・重複の件数と対象IDを機械出力できる。

### WP3 — 一次資料照合と既存SSOTへの写像

1. 書籍記載の出典名から公式データセット、表、年度、利用条件を確認する。
2. MetricConfig registry、survey resolver、ThemeCatalog、Japan catalogとの重複を照合する。
3. 一次資料を特定できないもの、民間権利が不明なものをfail-closedで保留する。
4. 採択順は検索需要、地域粒度、更新性、既存不足、複数媒体への再利用性で決める。順番を落としてもinventoryから除外しない。

Gate: 採択候補100%に一次資料とrights判定があり、既存metricの重複新設が0。

### WP4 — 10項目end-to-end pilot

1. 既存metric再利用と新規metricを混ぜて10項目を一次資料から構築する。
2. ranking / survey / theme / area / japanのうち意味のある責務へ配置する。
3. provenance、unit、値分布、survey taxonomy、内部リンクを既存監査で検証する。
4. remote writeを行わず、local R2とlocalhostで確認する。

Gate: 10項目すべてが一次資料から再生成でき、書籍値・OCR・画像へのruntime依存が0。

### WP5 — master content pilot

1. pilot指標から、独自の問いを持つblogまたはnote原稿と通常動画briefを作る。
2. YouTubeは既存EXP-006の6週間3本上限と残枠を確認し、枠を増やさない。
3. 通常動画をマスターとし、Reels / Instagram / Xは同じ主張と出典を引き継ぐ派生にする。
4. 公開前に表現類似、事実、出典、説明欄、UTM、投稿台帳contractを確認する。

Gate: ローカル成果物と公開planまで。外部投稿はオーナー承認後に既存skillで行う。

### WP6 — 全件解決と段階展開

1. inventoryを一次資料の取得容易性と需要でwave分割する。
2. 各waveでmetric / contentを実装し、100%のresolution確定まで進める。
3. `rights-hold` と `primary-source-unavailable` は未解決理由と再開条件を保持し、推測で公開しない。
4. 版更新時はsource item差分を作り、既存metricと公開コンテンツの更新要否を生成する。

Gate: 全定量項目に解決結果があり、公開済み項目はすべて一次資料へ辿れる。

### WP7 — 定常監査と運用統合

1. coverage、primary source、rights、metric mapping、content lineageの監査をCIまたは週次運用へ統合する。
2. inventoryに採択済みなのにmetric/contentから孤立した項目と、公開済みなのにinventoryへ戻れない項目を検出する。
3. 新版検知時だけ更新queueを生成し、無条件の全再生成をしない。
4. 管理画面には件数・coverage・blocker・次waveを読み取り専用で表示し、別の進捗SSOTを作らない。
5. private source bucketのpublic access、object hash、版manifest、容量を監査し、通常配信bucketと分けて集計する。

Gate: 手作業の数え直しなしで、全体件数、解決率、保留理由、公開系譜、次の実行単位が分かる。

## 10. 別PC再開契約

一時handoff文書は作らない。別PCのagentはGit上の本書とbacklogカードを読み、次の順で再開する。

1. `develop`を`origin/develop`へfast-forwardし、`AGENTS.md`、本書、
   `JAPAN-ZUE-CONTENT-PIPELINE-01`を読む。
2. backlogの`lastCompleted` / `nextWorkPackage`を確認し、完了済みWPをやり直さない。
3. 同じオーナーGoogleアカウントでGoogle Drive MCPを接続する。`list_folder(url="root")`から
   `stats47-private-sources` → `japan-zue` → `2025-26`を、各readbackで観測したfolder URLだけを使って辿る。
   版folderの7件をGit manifestのmanifest名・6個のpart名・sizeへ照合し、共有状態が`not_shared`であることを確認する。
4. 各partをそのreadback URLから`download_raw_file=true`、`include_base64=false`で取得し、返されたfile referenceをOSの一時ディレクトリへ
   materializeする。MCPクライアントがlocal materializeに対応しない場合は、同じprivate folderからブラウザで取得する。
5. 次を実行し、part 6件、合計bytes、bundle SHA、全1,746ファイルのSHAが一致してから復元する。

   ```bash
   npm run source-vault:japan-zue -- verify \
     --manifest .claude/state/source-inventory/japan-zue/2025-26/source-bundle-manifest.json \
     --parts-dir <download-dir>
   npm run source-vault:japan-zue -- restore \
     --manifest .claude/state/source-inventory/japan-zue/2025-26/source-bundle-manifest.json \
     --parts-dir <download-dir>
   ```

   `books/日本国勢図絵/`が既に存在する場合は上書きせず停止する。
6. `git status --short --branch`と対象fileのdirty状態を確認し、他agentの変更を上書きしない。
7. `npm run docs:check`とWP固有gateを通してから対象カードへ`[進行中]`を付ける。

WPの節目では、検証が成功した後だけbacklogの`lastCompleted` / `nextWorkPackage`を更新する。設計判断が変わらない
限り本書の`updated`を動かさず、実行ログを追記し続けない。別PCへ渡す前に、対象差分を明示的にcommitして
`develop`へpushし、`books/`、Driveのfolder / file ID・URL、connector file reference、`.local/`をcommitしない。

停止条件:

- 本書またはbacklogカードが`origin/develop`にない。
- Drive itemが共有されている、manifest / partが欠ける、size / hash / 件数が一致しない。
- Gitの対象fileがdirtyで、変更ownerまたは内容を確定できない。
- Git manifestとDrive manifestのrevisionまたは内容が異なる。

## 11. 完了条件

- 全ページ・全定量項目の母数が確定し、resolution coverageが100%。
- production-ready / 公開済み項目に一次資料・利用条件・年度・単位・地域粒度の欠落が0。
- 新規metricのprovenance、unit、値分布、survey linkage、ThemeCatalog検証がgreen。
- 書籍スキャン、figure、OCR値、書籍文章をruntime・公開物が参照していない。
- ranking / survey / theme / area / japan / blog / note / YouTube / Instagram / Xの派生関係を既存SSOTから追跡できる。
- 外部公開は既存の承認境界と投稿上限を守り、全投稿が既存台帳へ記録される。
- 版更新時に、追加・変更・削除されたsource itemと影響するmetric/contentを機械列挙できる。
- private source bundleを別PCへ復元でき、公開アクセス・hash不一致・公開R2混入が0。
