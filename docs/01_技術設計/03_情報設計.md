# 情報設計

stats47 のページ責務、分類軸、内部導線、評価 KPI を定義する。各ページに何を置くかは本書、どう表示するかは [`04_デザインシステム.md`](./04_デザインシステム.md)、URL の実在判定は `apps/web/src/lib/url-policy.ts` と関連コードを正典とする。

## ページ責務

| ページ            | 主語               | 利用者の問い                   | 主な内容                                     | 主な次導線                        |
| ----------------- | ------------------ | ------------------------------ | -------------------------------------------- | --------------------------------- |
| `/`               | サイト全体         | 何を調べられるか               | 主要入口、カテゴリ、注目ランキング、新着記事 | ranking / category / area / blog  |
| `/ranking`        | 個別指標の集合     | 見たいランキングはどれか       | 検索、カテゴリ別代表、一覧                   | ranking detail                    |
| `/ranking/[key]`  | 単一指標           | どの地域が高い・低いか         | 順位、地図、値、出典、解説                   | related ranking / theme / area    |
| `/category/[key]` | 統計大分類         | この分類に何があるか           | 指標・ランキングの索引                       | ranking / survey                  |
| `/survey/[key]`   | 統計調査           | この調査で何が分かるか         | 調査説明、収録指標、出典                     | ranking                           |
| `/themes/[slug]`  | 人が理解するテーマ | 複数指標をどう読むか           | curated chart、関係、注意事項                | ranking / area                    |
| `/areas/[code]`   | 地域               | この地域の特徴は何か           | プロフィール、強弱、テーマ別入口             | ranking / area theme              |
| `/compare/*`      | 比較条件           | 地域や指標を比べると何が違うか | 比較 UI、差分                                | ranking / area                    |
| `/blog/[slug]`    | 問い・話題         | 背景や意味を理解したい         | 記事、図表、根拠                             | ranking / theme / related article |
| `/tag/[tag]`      | 記事トピック       | 同じ話題の記事を読みたい       | 記事一覧                                     | blog                              |
| `/search`         | 検索語             | 目的の情報はどこか             | 横断検索                                     | matching page                     |

同じ情報を複数ページへ複製せず、要約とリンクで責務を接続する。

## 三つの分類軸

### Category

e-Stat の統計大分類に近い、全指標を漏れなく探すための軸。

- 正典: `packages/data-configs/src/categories.ts`
- URL: `/category/[categoryKey]`
- 役割: 網羅的な索引、ナビゲーション
- category 数や表示順はコードから導出し、文書へ固定しない。

### Theme

利用者の関心に合わせ、複数指標とチャートを意味のある順番へ編成する軸。

- 指標集合: `packages/types/src/indicator-sets/`
- チャート統合: `packages/data-configs/src/theme-catalog/`
- URL: `/themes/[themeSlug]`
- 役割: 内部回遊後の深掘り、複数指標の解釈
- 定義・注意事項・選定根拠は `.claude/rules/theme-catalog-standards.md` に従う。

### Tag

ブログ記事をトピックで横断する軸。

- 正典: 記事 frontmatter の `tags`
- URL: `/tag/[tagKey]`
- 役割: 関連記事の発見
- thin content を避ける index 条件は route の実装と URL policy で管理する。

Category、Theme、Tag は似た語を持ち得るが責務が異なる。新しい `topic`、`subcategory` 等の第四分類軸を増やす前に、既存三軸で表現できない根拠をレビューする。

## page_components の配置

`page_components` はページに載せるチャートを宣言する。保存・配信経路はデータアーキテクチャ、component contract は `.claude/design-system/page-components.md` に従う。

| page type                         | 置く情報                             | 置かない情報                         |
| --------------------------------- | ------------------------------------ | ------------------------------------ |
| `theme`                           | 全国横断でテーマを説明する指標・関係 | 一県だけの個別事情                   |
| `area`                            | 一地域のプロフィール、他地域との差   | 全国テーマの一般説明だけの chart     |
| `area-category` / `city-category` | 地域 × 統計分類として意味がある比較  | 全国値をそのまま複製しただけの chart |
| ranking page card                 | 単一 ranking の理解を直接補う要約    | 別テーマの汎用 dashboard             |

配置判断:

1. ページの主語に答えるか。
2. 隣接 component と役割が重複しないか。
3. 出典、年度、単位、地域粒度を説明できるか。
4. データが無い場合にも誤解を生まないか。
5. 関連ページへ進む理由を作るか。

## ファネル上の役割

役割は固定的な優劣ではなく、施策を評価するための既定値である。現在の流入構成は最新の GSC / GA4 snapshot で再確認する。

| ページ群                 | 既定の役割                          | 主 KPI                         |
| ------------------------ | ----------------------------------- | ------------------------------ |
| ranking detail / blog    | 検索からの獲得                      | clicks、impressions、CTR、順位 |
| survey                   | 潜在的な検索獲得 + ranking へのハブ | CTR、順位、ranking 遷移        |
| category / ranking index | 発見・ナビゲーション                | 内部 CTR、目的ページ到達       |
| theme / area / compare   | 回遊・深掘り                        | engagement、次ページ遷移、滞在 |
| home                     | 入口の振り分け                      | 主要導線 CTR、到達率           |

過去 snapshot では ranking と blog への検索流入が中心だった。ただし、単一週や rolling 期間の値を恒久設計へ固定しない。集客配分の判断は `docs/00_プロジェクト管理/03_マーケティング戦略.md` と最新の計測を使う。

## 導線設計

```text
検索 / SNS
   ├─ ranking ──▶ related ranking / theme / area
   ├─ blog ─────▶ evidence ranking / theme
   └─ survey ───▶ ranking

home / global navigation
   ├─ category ─▶ ranking
   ├─ theme ────▶ ranking / area
   └─ area ─────▶ ranking / area-theme
```

- 獲得ページには、問いへの答えと根拠を先に置き、その後に深掘り導線を置く。
- 回遊ページには、単なるリンク数ではなく「次に何が分かるか」を示す。
- 自動生成リンクは URL allowlist と同じ key set を使う。
- 関連導線が存在しない場合に、存在しない route や soft 404 を生成しない。
- パンくずは URL 階層ではなく、利用者が戻る情報階層と一致させる。

## KPI の使い分け

- 回遊ページを検索 click だけで失敗判定しない。
- 検索露出があるページの CTR 問題と、露出そのものがない問題を分ける。
- `pages/session`、engagement、内部 click を使う場合は GA4 event / dimension の登録状況を確認する。
- 改善施策は `.claude/todo/improvements.md` に置き、時点依存の実測値を本書へ追記し続けない。

## アンチパターン

- Category と Theme を一つの URL 軸へ統合する。
- 同じ chart を主語の異なるページへ無条件に複製する。
- 検索需要が確認できないハブを、タイトル変更だけで集客ページ扱いする。
- 新しい分類軸を UI 都合で追加する。
- page component に出典・年度・単位の不明な値を置く。
- 現在の件数、CTR、ページ構成比を恒久仕様として固定する。
