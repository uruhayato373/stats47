# 情報設計

stats47 のページ責務、分類軸、内部導線、評価 KPI を定義する。各ページに何を置くかは本書、どう表示するかは [`04_デザインシステム.md`](./04_デザインシステム.md)、URL の実在判定は `apps/web/src/lib/url-policy.ts` と関連コードを正典とする。

## 地域分析レイヤの導入契約

問いベースの複合分析を、既存のランキング・テーマ・地域ハブから一段深い「地域分析」レイヤとして計画する。`/geo` や `/geo/<analysis-slug>` は予約された概念であり、実分析3本以上、一次資料・方法・単位・空間粒度・免責、GA4イベント登録、thin content監査が揃うまで公開ナビ・index対象にしない。

導線は `単一指標ランキング → テーマ/地域ハブ → 複数条件の地域分析 → 方法/データ/次行動`。市区町村・メッシュを単一指標ごとに機械複製せず、ユーザーの問いと更新可能なデータがある分析だけ作る。固定テンプレートは結論、対象年度・更新日、方法、地図、表、編集済み解釈、限界、データ、関連導線を必須とする。

## ページ責務

| ページ                            | 主語                   | 利用者の問い                     | 主な内容                                       | 主な次導線                          |
| --------------------------------- | ---------------------- | -------------------------------- | ---------------------------------------------- | ----------------------------------- |
| `/`                               | サイト全体             | 何を調べられるか                 | 主要入口、カテゴリ、注目ランキング、新着記事   | ranking / category / area / blog    |
| `/ranking`                        | 個別指標の集合         | 見たいランキングはどれか         | 検索、カテゴリ別代表、一覧                     | ranking detail                      |
| `/ranking/[key]`                  | 単一指標               | 何を測り、どの地域が高い・低いか | 定義、注釈、順位、地図、値、出典、関連記事     | related ranking / theme / area      |
| `/category/[key]`                 | 統計大分類             | この分類に何があるか             | 指標・ランキングの索引                         | ranking / survey                    |
| `/survey/[key]`                   | 統計調査               | この調査で何が分かるか           | 調査説明、収録指標、出典                       | ranking                             |
| `/themes/[slug]`                  | 人が理解するテーマ     | 複数指標をどう読むか             | curated chart、関係、注意事項                  | ranking / area                      |
| `/areas/[code]`                   | 地域                   | この地域の特徴は何か             | プロフィール、強弱、テーマ別入口               | ranking / area theme                |
| `/municipalities`                 | 市区町村の集合         | 市区町村統計をどこから見るか     | 市区町村向けテーマ・ランキングの索引           | municipality theme / ranking        |
| `/municipalities/themes/[slug]`   | 市区町村の一テーマ     | 市区町村間で何が違うか           | 市区町村向け curated chart、比較条件、注意事項 | municipality ranking / city profile |
| `/municipalities/ranking/[key]`   | 単一指標の市区町村集合 | どの市区町村が高い・低いか       | 順位、絞り込み、値、出典、解説                 | municipality theme / city profile   |
| `/areas/[code]/cities/[cityCode]` | 一つの市区町村         | この市区町村の特徴は何か         | プロフィール、強弱、カテゴリ別入口             | municipality ranking / prefecture   |
| `/japan`                          | 日本                   | 日本全体の統計をどこから見るか   | 全国値を持つテーマの索引                       | japan theme / source                |
| `/japan/[slug]`                   | 日本の一テーマ         | 日本全体ではどう変化したか       | 公式全国値、全国時系列、構成、出典             | theme / related japan theme         |
| `/world`（計画）                  | 世界                   | 国際比較をどこから見るか         | 国際統計テーマの索引                           | world theme                         |
| `/world/[slug]`（計画）           | 国の集合               | 日本は世界の中でどこにいるか     | 国別比較、日本の強調、国際出典                 | japan / related world theme         |
| `/compare/*`                      | 比較条件               | 地域や指標を比べると何が違うか   | 比較 UI、差分                                  | ranking / area                      |
| `/blog/[slug]`                    | 問い・話題             | 背景や意味を理解したい           | 記事、図表、根拠                               | ranking / theme / related article   |
| `/tag/[tag]`                      | 記事トピック           | 同じ話題の記事を読みたい         | 記事一覧                                       | blog                                |
| `/search`                         | 検索語                 | 目的の情報はどこか               | 横断検索                                       | matching page                       |

同じ情報を複数ページへ複製せず、要約とリンクで責務を接続する。

### 情報の配置

| 情報                                   | 置き場所                                      | 置かない場所                     |
| -------------------------------------- | --------------------------------------------- | -------------------------------- |
| ページ名、主語、非自明な要約           | `PageHeader`                                  | chart title と同じ説明の繰り返し |
| ページ内の切替・目次・全指標・出典調査 | `PageShell leftRail`。狭幅は本文上部の同等 UI | 広告用 right rail、本文末尾だけ  |
| 指標の定義・算出方法・一般注釈         | `/ranking/[key]` の指標ハブ                   | theme chart header への複製      |
| chart 固有の誤読防止条件               | 各 chart/table の近接 footer の `annotation`  | 汎用的な「見方」の定型文         |
| 年度・単位・出典・関連 ranking         | chart / table 本体と近接 footer               | パンくず、内部選定根拠           |
| 関連記事・関連ランキング               | 文脈のある section / rail widget              | 文脈のない広告だけの rail        |
| 選定理由・provenance の内部 rationale  | ThemeCatalog 等の SSOT                        | 読者向け本文へのそのまま露出     |

一覧・ハブで左レールが必要な場合も、列幅を page 内へ直書きせず `PageShell leftRail` を使う。
右レールは関連情報が主役である場合だけ使い、広告・販促だけを理由に本文幅を狭めない。

`/ranking/[key]` は順位表だけでなく、指標の定義、算出上の注意、出典、関連ランキング、関連記事を集約する
指標ハブである。テーマページは複数指標の関係を可視化する責務に集中し、同じ定義をチャートごとに複製せず
指標ハブへの導線で接続する。

## 地理スコープ

地理スコープは、URL、画面ラベル、データの意味を一致させる。地域未選択を表す UI 状態と、
統計上の日本全国を同じ `00000` センチネルで表現しない。

| スコープ           | UI の主語        | データ要件                                     | 主な URL                                                |
| ------------------ | ---------------- | ---------------------------------------------- | ------------------------------------------------------- |
| `prefecture-set`   | 47都道府県       | 47県を同条件で比較できる値                     | `/themes/*`、`/ranking/*`                               |
| `prefecture`       | 選択した都道府県 | 当該県の値と順位・推移                         | `/areas/*`、`/themes/*?pref=`                           |
| `municipality-set` | 市区町村の集合   | 同じ統計主体・年度・定義で比較できる市区町村値 | `/municipalities/themes/*`、`/municipalities/ranking/*` |
| `municipality`     | 選択した市区町村 | 当該市区町村の値、順位、推移                   | `/areas/*/cities/*`                                     |
| `japan`            | 日本             | 公式の全国行、または再現可能な全国集計         | `/japan/*`                                              |
| `world`            | 国の集合         | 同一定義で比較できる国別値                     | `/world/*`                                              |

実装上の地理スコープ型は `packages/data-configs/src/geo-scope/types.ts`、既存storageの `city` との変換は
同ディレクトリの `storage-adapter.ts`、市区町村指標・テーマの公開判断は `municipality-catalog.ts` を正典とする。
`MetricConfig.entities` の `city` は取得可能性であり、公開許可ではない。監査済みの
`published` だけから市区町村向け known ranking/theme 集合を導出する。

用語と表示の不変条件:

- `/themes/*` の未選択状態は「47都道府県」と表示し、「全国」と呼ばない。
- 47都道府県・市区町村・日本の切替は共通 `StatisticsScopeNav` を各スコープのハブと詳細で使い、
  Theme や Category の切替と同じ軸へ混ぜない。世界は公開データ契約が成立するまで準備中表示とする。
- 「日本」「全国値」は、公式の全国行または根拠を持つ全国集計だけに使う。
- 47県の単純平均を日本全国の値として表示しない。率、密度、1人当たり値は特に、単純平均で代替しない。
- 都道府県を選択した後の比較基準として平均を使う場合は「都道府県平均」と明記する。
- 日本に意味を持たない都道府県固有指標は、`0` へ変換せず `unsupported` として扱う。
- 市区町村は第四の分類軸ではなく地理スコープである。Category、Theme、Tagを市区町村用に複製しない。
- `/themes/*` と `/ranking/*` は47都道府県を主語とし、市区町村比較をquery stateとして同じcanonicalへ混在させない。
- 市区町村の比較集合は、市・町・村と東京23特別区を基本とする。政令指定都市の行政区は自治体と同一視せず、
  財政主体など指標固有の母集団規則を公開catalogで明示する。
- 公開エンティティ方針は `packages/area/src/municipalities/entity-policy.ts` から決定的に生成する。
  現行の地域マスタに東京23特別区の個別行はなく、`13100 特別区部` は23区の集約行なので公開集合から除外する。
  個別の特別区を公開するのは、個別コードの観測値とマスタを同時に検証できた後とする。
- 欠測を0に変換しない。市町村合併、コード変更、統計主体の違いを確認できない系列は公開対象にしない。
- 公開指標に固有の有効値範囲がある場合はmunicipality catalogの `valuePolicy` に置き、派生snapshot生成時に
  範囲外を欠測相当として除外する。2020年の双葉町のように分母人口が0の比率を0位相当へ順位付けしない。
- 個別市区町村ページの既存canonical `/areas/[pref]/cities/[city]` は維持し、比較ページから接続する。
- `/themes/*` は「どの県が高い・低いか」、`/japan/*` は「日本全体がどう変化したか」、
  `/world/*` は「日本が世界の中でどこにいるか」に答え、同じ本文やチャートを主役として複製しない。

実装手順と移行 gate は
[`43_地理スコープ分離・日本統計基盤実装仕様.md`](../02_実装計画/43_地理スコープ分離・日本統計基盤実装仕様.md)
および
[`44_市区町村統計スコープ分離・ランキング基盤実装仕様.md`](../02_実装計画/44_市区町村統計スコープ分離・ランキング基盤実装仕様.md)
を参照する。

## 三つの分類軸

### Category

e-Stat の統計大分類に近い、全指標を漏れなく探すための軸。

- 正典: `packages/data-configs/src/categories.ts`
- URL: `/category/[categoryKey]`
- 役割: 網羅的な索引、ナビゲーション
- category 数や表示順はコードから導出し、文書へ固定しない。

### Theme

利用者の関心に合わせ、複数指標とチャートを意味のある順番へ編成する軸。

- 指標集合: `packages/types/src/indicator-sets/`
- チャート統合: `packages/data-configs/src/theme-catalog/`
- URL: `/themes/[themeSlug]`
- 役割: 内部回遊後の深掘り、複数指標の解釈
- 定義・注意事項・選定根拠は `.claude/rules/theme-catalog-standards.md` に従う。

#### Evidence lens（Theme 従属メタデータ）

白書・報告書の論点を、複数テーマで再利用できる「地域アクセス」「供給・受け皿」等の観点へ正規化する。
これは独立 URL を持つ第四分類軸ではなく、ThemeCatalog の `evidenceTopics` として Theme に従属する。

- 正典: `packages/data-configs/src/theme-catalog/evidence-lenses.ts` と各 `ThemeCatalog.evidenceTopics`
- 白書・統計資料は taxonomy ではなく evidence source。保存と採用は `.claude/rules/reference-source-standards.md` に従い、NotebookLM は候補抽出に使い、公式資料で検証してから採択する。
- 用途: `/themes/*` から関連 ranking / theme / tag へ「なぜ次に読むか」を示して接続する。
- 同一 lens は複数 Theme で再利用できるが、問い・要約・関連 route は各 Theme の文脈で定義する。
- lens 一覧ページ、白書名別の量産ページ、空の tag ページは作らない。公開 taxonomy は Category / Theme / Tag の三軸を維持する。

### Tag

ブログ記事をトピックで横断する軸。

- 正典: 記事 frontmatter の `tags`
- URL: `/tag/[tagKey]`
- 役割: 関連記事の発見
- thin content を避ける index 条件は route の実装と URL policy で管理する。

Category、Theme、Tag は似た語を持ち得るが責務が異なる。Evidence lens は Theme の従属メタデータであり、この三軸には数えない。新しい `topic`、`subcategory` 等の第四分類軸を増やす前に、既存三軸で表現できない根拠をレビューする。

## page_components の配置

`page_components` はページに載せるチャートを宣言する。保存・配信経路はデータアーキテクチャ、component contract は `.claude/design-system/page-components.md` に従う。

| page type                         | 置く情報                                   | 置かない情報                              |
| --------------------------------- | ------------------------------------------ | ----------------------------------------- |
| `theme`                           | 47都道府県横断でテーマを説明する指標・関係 | 一県だけの個別事情、全国値だけの chart    |
| `area`                            | 一地域のプロフィール、他地域との差         | 全国テーマの一般説明だけの chart          |
| `area-category` / `city-category` | 地域 × 統計分類として意味がある比較        | 全国値をそのまま複製しただけの chart      |
| `municipality-theme`（計画）      | 市区町村集合で意味のある比較・分布・関係   | 47県chartの無条件な複製、行政区を混ぜた値 |
| `japan`（計画）                   | 公式全国値で日本の変化を説明する chart     | 47県平均、都道府県固有指標                |
| ranking page card                 | 単一 ranking の理解を直接補う要約          | 別テーマの汎用 dashboard                  |

配置判断:

1. ページの主語に答えるか。
2. 隣接 component と役割が重複しないか。
3. 出典、年度、単位、地域粒度を説明できるか。
4. データが無い場合にも誤解を生まないか。
5. 関連ページへ進む理由を作るか。

## ファネル上の役割

役割は固定的な優劣ではなく、施策を評価するための既定値である。現在の流入構成は最新の GSC / GA4 snapshot で再確認する。

| ページ群                 | 既定の役割                          | 主 KPI                         |
| ------------------------ | ----------------------------------- | ------------------------------ |
| ranking detail / blog    | 検索からの獲得                      | clicks、impressions、CTR、順位 |
| survey                   | 潜在的な検索獲得 + ranking へのハブ | CTR、順位、ranking 遷移        |
| category / ranking index | 発見・ナビゲーション                | 内部 CTR、目的ページ到達       |
| theme / area / compare   | 回遊・深掘り                        | engagement、次ページ遷移、滞在 |
| home                     | 入口の振り分け                      | 主要導線 CTR、到達率           |

過去 snapshot では ranking と blog への検索流入が中心だった。ただし、単一週や rolling 期間の値を恒久設計へ固定しない。集客配分の判断は `docs/00_プロジェクト管理/03_マーケティング戦略.md` と最新の計測を使う。

## 導線設計

```text
検索 / SNS
   ├─ ranking ──▶ related ranking / theme / area
   ├─ blog ─────▶ evidence ranking / theme
   └─ survey ───▶ ranking

home / global navigation
   ├─ category ─▶ ranking
   ├─ theme ────▶ ranking / area
   ├─ area ─────▶ ranking / area-theme
   ├─ municipalities ─▶ municipality-theme / municipality-ranking / city-profile
   ├─ japan ────▶ japan-theme / related theme
   └─ world ────▶ world-theme / japan
```

- 獲得ページには、問いへの答えと根拠を先に置き、その後に深掘り導線を置く。
- 回遊ページには、単なるリンク数ではなく「次に何が分かるか」を示す。
- 自動生成リンクは URL allowlist と同じ key set を使う。
- 関連導線が存在しない場合に、存在しない route や soft 404 を生成しない。
- パンくずは URL 階層ではなく、利用者が戻る情報階層と一致させる。

## KPI の使い分け

- 回遊ページを検索 click だけで失敗判定しない。
- 検索露出があるページの CTR 問題と、露出そのものがない問題を分ける。
- `pages/session`、engagement、内部 click を使う場合は GA4 event / dimension の登録状況を確認する。
- 改善施策は `.claude/todo/improvements.md` に置き、時点依存の実測値を本書へ追記し続けない。

## アンチパターン

- Category と Theme を一つの URL 軸へ統合する。
- 同じ chart を主語の異なるページへ無条件に複製する。
- 検索需要が確認できないハブを、タイトル変更だけで集客ページ扱いする。
- 新しい分類軸を UI 都合で追加する。
- page component に出典・年度・単位の不明な値を置く。
- 現在の件数、CTR、ページ構成比を恒久仕様として固定する。
