# 統一レイアウト設計 (Unified Layout System)

stats47 全ページのレイアウト土台を一本化する設計。横幅・サイドレール・余白・ナビゲーションの SSOT。
2026-06-02 にオーナー判断で確定（全面リデザイン）。

## 背景 (なぜ作るか)

リデザイン前は以下が三者三様だった:

- **基準幅の混在**: `container`(=1700px に上書き) / `max-w-[1400px]`(home) / `max-w-[1700px]`(blog) / `max-w-4xl`(terms) が混在し、ページ間で本文幅が揃わない。
- **右レール幅の不統一**: `360px` / `420px` / `320px` がページごとに手書き grid で散在。
- **PC の常設左サイドバー**: ヘッダーに既にナビがあるため役割が重複。トグル式（既定 closed）で UX も中途半端。中身は「ナビ重複 + AdSense + カテゴリ閲覧」。

→ 共通の土台（トークン + 単一 Shell コンポーネント）が無いことが根本原因。

## 決定事項 (オーナー選択 2026-06-02)

| 項目 | 決定 |
|---|---|
| 基準コンテンツ幅 | **1700px**（全ページ共通の外側 max） |
| PC 左サイドバー | **廃止**。カテゴリ閲覧はヘッダーのメガメニューへ集約 |
| モバイルナビ | ドロワー（Sheet）維持。ナビ + カテゴリを内包 |
| AdSense `MAIN_SIDEBAR` | 右レール（`RightRailWidgets`）へ移設 |
| スコープ | 一気に全面リデザイン（構造統一 → 見た目刷新の2フェーズ） |

## レイアウトトークン (SSOT)

`apps/web/src/components/layout/tokens.ts` に定数として定義し、Shell から参照する。

| トークン | 値 | 用途 |
|---|---|---|
| `SHELL_MAX` | `1700px` | ページ外側の最大幅 |
| `RAIL_RIGHT` | `360px` | 右レール幅（関連 widget / 広告）。xl+ でのみ表示 |
| `RAIL_LEFT` | `280px` | 左レール幅（blog 記事 TOC）。xl+ でのみ表示 |
| `READING_MAX` | `760px` | 記事本文の可読幅（measure）。`prose` に適用 |
| gutter | `px-4 sm:px-6` | 左右余白 |
| page padding | `py-8` | ページ上下余白 |
| section gap | `space-y-10` | セクション間の縦リズム |
| header height | `64px`(`h-16`) | 固定ヘッダー高（変更なし） |

## 単一 Shell コンポーネント

`apps/web/src/components/layout/PageShell.tsx` を**全ページ共通の唯一の幅制御**にする。
旧 `features/redesign/components/WidePageShell.tsx` は PageShell への re-export エイリアスに変更（後方互換）。

### API

```tsx
<PageShell
  variant="default" | "reading"   // default: ダッシュボード/一覧 / reading: 記事本文
  rightRail={<RightRailWidgets />} // 省略可。xl+ で右 360px に表示、未満は本文下へ
  leftRail={<ArticleTableOfContents />} // 省略可。blog 記事の TOC（xl+ で左 280px）
>
  {children}
</PageShell>
```

### グリッドパターン (xl: 1280px 以上)

| レール構成 | grid-template-columns |
|---|---|
| なし（1カラム） | `max-w-[1700px]` 中央寄せのみ |
| 右のみ | `[minmax(0,1fr)_360px]` gap-8 |
| 左+右（blog） | `[280px_minmax(0,1fr)_360px]` gap-8 |

- **xl 未満**: 常に 1 カラム。leftRail / rightRail は本文下に積み下ろす。
- `variant="reading"` は本文カラム内の `prose` を `READING_MAX` で制限し可読性を確保。

## ページヘッダー (PageHeader) — 2026-06-15 ミニマル化

`apps/web/src/components/layout/PageHeader.tsx`。**暗色グラデの hero バナーや page-top KPI タイルを置かず**、
`h1`（常に `text-2xl font-bold`）+ 1 行説明 +（任意）細い統計テキスト + 任意 CTA だけで構成する最小ヘッダー。
2026-06-15 の全面ミニマル化で旧 D案の `HeroShell` / `KpiGrid` / `KpiTile`（`features/redesign`）を退役させ、
全ページの見出しを本コンポーネントに統一した。

```tsx
<PageHeader
  eyebrow="ランキング"               // 任意の小ラベル
  title="都道府県ランキング一覧"       // h1（text-2xl font-bold 固定）
  description="気になるカテゴリを選んで…"  // 1 行説明
  stats={`全 2,043 ランキング ・ 17 カテゴリ ・ 47 都道府県`}  // KPI タイルではなくテキスト
  actions={<SearchButton />}          // 任意 CTA（h1 の右）
/>
```

- 統計値は **KPI タイルではなくテキスト 1 行**で表す（白基調・余白主導）。
- 専用ヘッダーを持つページ（`/ranking/[rankingKey]` の `RankingHeroCard`、`/areas/[code]`、
  `/themes/[slug]` の `ThemePageLayout`、`/blog/[slug]` の記事 h1）は PageHeader を使わず
  `PageShell` でラップしたまま据え置く。
- home も page-top ヒーローを撤去し PageHeader + 注目ランキング + discovery 3 枚 + 最新ブログに簡素化。

## ナビゲーション構成

### ヘッダー (`organisms/Header`)

Server ラッパー（`listCategories()` を取得）→ Client（`HeaderClient`）に渡す構成にする
（既存 `Sidebar.tsx` の server/client 分離パターンを踏襲。`cookies()/headers()` は呼ばない = SSG 維持）。

- ロゴ（左）
- **デスクトップナビ**（lg+）: `テーマ` / `ブログ` + **カテゴリ メガメニュー**（hover/click ドロップダウンでカテゴリ一覧）
- 検索フォーム（lg+）
- テーマ切替
- **モバイルメニューボタン**（lg 未満のみ表示）→ モバイルドロワーを開く

### モバイルドロワー (`organisms/MobileNavDrawer`)

旧 `SidebarClient` を mobile 専用に転用。`useSidebarStore` の `isOpen` で Sheet 開閉。
内容: 主要ナビリンク + カテゴリアコーディオン。**PC では何も描画しない**（`return null`）。

### 廃止するもの

- root `layout.tsx` の `flex` + `<Sidebar />` ラッパー（PC 常設パネル）
- `usePageType` / `useSidebarNavigation` / `SidebarPageSection` / `useSidebarSectionStore`（PC サイドバー専用ロジック）
- ヘッダーの「サイドバー開閉」ハンバーガー（PC）→ モバイル専用メニューボタンに置換

## 広告枠の扱い

- `MAIN_SIDEBAR`(slot 7716393084) は PC サイドバー廃止で行き場を失う → **退役**。
  `RightRailWidgets` は既に上下 2 枠（`RANKING_SIDEBAR_TOP` / `RANKING_PAGE_SIDEBAR`）を持つため、
  3 枠目を足すと UX・AdSense ポリシー上不利。右レール既存 2 枠で代替する。
- 右レールが無いページはページ内 `InfeedAd` に依存（既存）。
- 定数 `MAIN_SIDEBAR` 自体は定義のまま残置（再利用余地・無害）。

## ページ移行マップ

全ページを `container mx-auto` / `max-w-[…]` から PageShell へ移行する。

| ページ | 旧 | 新 |
|---|---|---|
| `/` (home) | `max-w-[1400px]` × セクション | PageShell (default) |
| `/ranking/[rankingKey]` | container | PageShell + rightRail |
| `/category/[categoryKey]` | container + 360 grid | PageShell + rightRail |
| `/category/[categoryKey]/compare` | container | PageShell |
| `/areas` / `/areas/[areaCode]` | container (+360 grid) | PageShell (+rightRail) |
| `/areas/[areaCode]/[themeSlug]` 他 area 下層 | container/未指定 | PageShell |
| `/themes` / `/themes/[themeSlug]` 他 | container (+360 grid) | PageShell (+rightRail) |
| `/blog/[slug]` | max-w-[1700] + 3col | PageShell variant=reading + leftRail(TOC) + rightRail |
| `/blog` / `/blog/tags` | container | PageShell |
| `/survey` / `/survey/[surveyKey]` | container (+420 grid) | PageShell (+rightRail) |
| `/tag/[tagKey]` | container + 320 grid | PageShell + rightRail |
| `/search` | container | PageShell |
| `/about` `/privacy` | lg:grid-cols-2 | PageShell（中身グリッドは維持） |
| `/terms` | max-w-4xl | PageShell variant=reading |

## 実装フェーズ

- **Phase 1（構造統一）**: tokens + PageShell / sidebar 廃止 + header メガメニュー + mobile drawer + 広告移設 + 全ページ移行。ビルド+型検証。
- **Phase 2（見た目刷新）**: ヘッダー/フッター/カードの視覚調整、余白リズム、design-system 準拠チェック（`/design-review`）。
- **Phase 3（ミニマル化 2026-06-15）**: page-top 暗色ヒーロー/KPI タイルを退役し `PageHeader` に統一（上記「ページヘッダー」節）。home 簡素化 + `/ranking` 索引ハブ再設置。
