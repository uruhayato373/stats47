# 統一レイアウト設計 (Unified Layout System)

stats47 全ページのレイアウト土台を一本化する設計。横幅・サイドレール・余白・ナビゲーションの SSOT。
2026-06-02 にオーナー判断で確定（全面リデザイン）。

> UI 判断ルール全体の正典は [`15_デザインシステムSSOT.md`](./15_デザインシステムSSOT.md)。
> 本文書は、そのうち横幅・レール・`PageShell`・`PageHeader`・ナビゲーションの詳細設計を担当する。

## 背景 (なぜ作るか)

リデザイン前は以下が三者三様だった:

- **基準幅の混在**: `container`(=1700px に上書き) / `max-w-[1400px]`(home) / `max-w-[1700px]`(blog) / `max-w-4xl`(terms) が混在し、ページ間で本文幅が揃わない。
- **右レール幅の不統一**: `360px` / `420px` / `320px` がページごとに手書き grid で散在。
- **PC の常設左サイドバー**: ヘッダーに既にナビがあるため役割が重複。トグル式（既定 closed）で UX も中途半端。中身は「ナビ重複 + AdSense + カテゴリ閲覧」。

→ 共通の土台（トークン + 単一 Shell コンポーネント）が無いことが根本原因。

## 決定事項 (オーナー選択 2026-06-02)

| 項目 | 決定 |
|---|---|
| 基準コンテンツ幅 | **1280px**（全ページ共通の外側 max。2026-07-11 に 1700px から統一 — ArticleShell/blog/ranking 詳細と同一幅の doboku-note スタイル固定幅） |
| PC 左サイドバー | **廃止**。カテゴリ閲覧はヘッダーのメガメニューへ集約 |
| モバイルナビ | ドロワー（Sheet）維持。ナビ + カテゴリを内包 |
| AdSense 右レール枠 | `RightRailWidgets`（`@/components/rail`）に集約 |
| スコープ | 一気に全面リデザイン（構造統一 → 見た目刷新の2フェーズ） |

## レイアウトトークン (SSOT)

`apps/web/src/components/layout/tokens.ts` に定数として定義し、Shell から参照する。

| トークン | 値 | 用途 |
|---|---|---|
| `SHELL_MAX` | `1280px` | ページ外側の最大幅（`PageShell`。ダッシュボード/一覧/hub。2026-07-11 に 1700px → 1280px） |
| `ARTICLE_MAX` | `1280px` | 記事系ページの外側幅（`ArticleShell` = reading zone） |
| `RAIL_RIGHT` | `360px` | 右レール幅（関連 widget / 広告）。xl+ でのみ表示 |
| `RAIL_LEFT` | `280px` | 左レール幅。xl+ でのみ表示。**2026-07-22 時点で利用ページなし**（テーマ詳細の常設左レールを撤去。`leftRail` prop は残置） |
| `READING_MAX` | `760px` | （旧）`PageShell variant="reading"` の本文可読幅。記事系は `ArticleShell` の flex-1 密着へ移行したため未使用（法務等の非レール読み物にのみ残存） |
| gutter | `px-4 sm:px-6` | 左右余白 |
| page padding | `py-8` | ページ上下余白 |
| section gap | `space-y-10` | セクション間の縦リズム |
| header height | `64px`(`h-16`) | 固定ヘッダー高（変更なし） |

> **記事系ページは `ArticleShell`（reading zone）を使う（2026-07-11）**。`PageShell reading variant` の
> 「1700px grid 内で本文を 760px に制限 → ワイド画面で本文と右レールが離れる」問題を、1280px コンテナ +
> flex 密着（本文 flex-1・レール 360px shrink-0）で根治した。Soft Editorial（角丸なし・薄グレー地・
> `shadow-sm`）の詳細は `15_デザインシステムSSOT.md`「reading zone」。

## 単一 Shell コンポーネント

`apps/web/src/components/layout/PageShell.tsx` を**全ページ共通の唯一の幅制御**にする。
旧 `features/redesign/components/WidePageShell.tsx`（PageShell への後方互換エイリアス）は全ページ移行完了により **2026-06-15 に削除**。以後は `@/components/layout` の `PageShell` のみを使う。

### API

```tsx
<PageShell
  variant="default" | "reading"   // default: ダッシュボード/一覧 / reading: 記事本文
  rightRail={<RightRailWidgets />} // 省略可。xl+ で右 360px に表示、未満は本文下へ
  // leftRail={...}                // 省略可（xl+ で左 280px）。2026-07-22 に唯一の利用だった
  //                                  テーマ詳細の左レールを撤去し、現在どのページも未使用（API のみ残置）
>
  {children}
</PageShell>

<PageShell
  rightRailBreakpoint="lg" // ブログ詳細など。右 rail は lg+ で表示
  rightRail={<BlogRelatedWidgets />}
>
  {children}
</PageShell>
```

### グリッドパターン

| レール構成 | grid-template-columns |
|---|---|
| なし（1カラム） | `max-w-[1280px]` 中央寄せのみ |
| 右のみ | `xl:[minmax(0,1fr)_360px]` gap-8 |
| 左のみ | `xl:[280px_minmax(0,1fr)]` gap-8 |
| 右のみ lg+ | `lg:[minmax(0,1fr)_360px]` gap-8 |

- 通常は **xl 未満**で 1 カラム。`rightRailBreakpoint="lg"` の場合は **lg 未満**で 1 カラム。
- `leftRail` と `rightRail` は同時利用しない。サイト全体の基本は本文 + 片側 rail の 2 列。
- `variant="reading"` は本文カラム内の `prose` を `READING_MAX` で制限し可読性を確保。

> **テーマ詳細ページの実効幅統一（2026-07-22）**: `/themes/[themeSlug]`・`/themes/local-finance`・
> `/themes/local-finance/cities` は Explore 系ページとして `/areas` と同じ **`PageShell` 全幅（1280px）**
> を使う。旧・常設左レール `ThemeSidebar`（280px）は本文を狭めるうえ `ui-components.md`「PC 常設左サイドバー
> は廃止」とも不整合だったため撤去し、テーマ切替をパンくず直後・H1/hero の前の**コンパクトなセレクター
> `ThemeSwitcher`**（`@stats47/components` の `Select`）へ移した。選択肢の SSOT は `ALL_THEMES`。
> `areaContext`（`/areas/[areaCode]/[themeSlug]` 経由）では都道府県文脈を維持して
> `/areas/{areaCode}/{themeKey}` へ遷移する。ただし都道府県ページで 410 になる Type B テーマ
> （ports/railway/roads/local-finance-city）は選択肢から除外し、存在しない/410 URL を生成しない
> （判定 SSOT: `theme-dashboard/config/area-theme-slugs.ts`＝middleware の `TYPE_A_THEME_SLUGS` と一致）。

## ページヘッダー (PageHeader) — 2026-06-15 ミニマル化

`apps/web/src/components/layout/PageHeader.tsx`。**暗色グラデの hero バナーや page-top KPI タイルを置かず**、
`h1`（常に `text-2xl font-bold`）+ 1 行説明 +（任意）細い統計テキスト + 任意 CTA だけで構成する最小ヘッダー。
2026-06-15 の全面ミニマル化で旧 D案の `HeroShell` / `KpiGrid` / `KpiTile`（`features/redesign`）を退役させ、
全ページの見出しを本コンポーネントに統一した。

```tsx
<PageHeader
  eyebrow="ランキング"               // 任意の小ラベル
  title="都道府県ランキング一覧"       // h1（text-2xl font-bold 固定）
  description="気になるカテゴリを選んで…"  // 1 行説明
  stats={`全 2,043 ランキング ・ 17 カテゴリ ・ 47 都道府県`}  // KPI タイルではなくテキスト
  actions={<SearchButton />}          // 任意 CTA（h1 の右）
/>
```

- 統計値は **KPI タイルではなくテキスト 1 行**で表す（白基調・余白主導）。
- 専用ヘッダーを持つページ（`/ranking/[rankingKey]` の `RankingHeroCard`、`/areas/[code]`、
  `/themes/[slug]` の `ThemePageLayout`、`/blog/[slug]` の記事 h1）は PageHeader を使わず
  `PageShell` でラップしたまま据え置く。
- home も page-top ヒーローを撤去し PageHeader + 注目ランキング + discovery 3 枚 + 最新ブログに簡素化。

## ナビゲーション構成

### ヘッダー (`organisms/Header`)

Server ラッパー（`listCategories()` を取得）→ Client（`HeaderClient`）に渡す構成にする
（既存 `Sidebar.tsx` の server/client 分離パターンを踏襲。`cookies()/headers()` は呼ばない = SSG 維持）。

- ロゴ（左）
- **デスクトップナビ**（lg+）: `テーマ` / `ブログ` + **カテゴリ メガメニュー**（hover/click ドロップダウンでカテゴリ一覧）
- 検索フォーム（lg+）
- テーマ切替
- **モバイルメニューボタン**（lg 未満のみ表示）→ モバイルドロワーを開く

### モバイルドロワー (`organisms/MobileNavDrawer`)

旧 `SidebarClient` を mobile 専用に転用。`useSidebarStore` の `isOpen` で Sheet 開閉。
内容: 主要ナビリンク + カテゴリアコーディオン。**PC では何も描画しない**（`return null`）。

### 廃止するもの

- root `layout.tsx` の `flex` + `<Sidebar />` ラッパー（PC 常設パネル）
- `usePageType` / `useSidebarNavigation` / `SidebarPageSection` / `useSidebarSectionStore`（PC サイドバー専用ロジック）
- ヘッダーの「サイドバー開閉」ハンバーガー（PC）→ モバイル専用メニューボタンに置換

## 広告枠の扱い

- 右レール広告は `RightRailWidgets`（`@/components/rail`）に集約。既定で上下 2 枠
  （`RANKING_SIDEBAR_TOP` / `RANKING_PAGE_SIDEBAR`）+ promo を供給する。
- 旧 `MAIN_SIDEBAR`(slot 7716393084) は **`RAIL_RECT` にリネームして現役化**（2026-07-05）。
  category / areas の右レール・本文の独立レクタングル枠（`RailAdSlot`、`@/features/ads`）に使い、
  同一ページ内の slot 重複を避ける。
- 本文中の記事内広告は `InContentAdSlot`（`@/features/ads`・fluid）、コンテンツ末尾は
  `FooterAdSlot`（Multiplex 全幅）に統一（旧 `InfeedAd` は廃止）。広告スロットの正典は
  `docs/01_技術設計/15_デザインシステムSSOT.md`「Surface / Card」節。

## 実装フェーズ

- **Phase 1（構造統一）**: tokens + PageShell / sidebar 廃止 + header メガメニュー + mobile drawer + 広告移設 + 全ページ移行。ビルド+型検証。
- **Phase 2（見た目刷新）**: ヘッダー/フッター/カードの視覚調整、余白リズム、design-system 準拠チェック（`/design-review`）。
- **Phase 3（ミニマル化 2026-06-15）**: page-top 暗色ヒーロー/KPI タイルを退役し `PageHeader` に統一（上記「ページヘッダー」節）。home 簡素化 + `/ranking` 索引ハブ再設置。
