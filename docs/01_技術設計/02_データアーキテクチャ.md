# データアーキテクチャ（完全DBレス）

stats47 は永続 DB を真実源または本番ランタイムの依存先にしない。データ層の正典は次の二つである。

1. **git** — 人が定義する設定、カタログ、記事、運用契約
2. **Cloudflare R2** — 観測値と公開アプリが読む配信用 snapshot

集計に SQLite / DuckDB を使う場合は、プロセス終了時に破棄できる一時領域に限る。リモート D1 や常駐 SQLite を SSOT として再導入しない。

## 不変条件

- 本番アプリは R2 snapshot を読み、DB query を実行しない。
- 観測値を永続 DB へ複製しない。
- 人が定義する低 volume の設定は git で review 可能にする。
- 派生値は入力とロジックから再生成できるようにする。
- R2 への公開手順は `.claude/rules/r2-storage-design.md` と `.claude/rules/branch-workflow.md` に従う。
- schema 定義や DB ライブラリが残っていても、それを永続 DB 利用の根拠にしない。

## データ分類

| 分類               | 真実源                                 | 配信先                               | 例                                                             |
| ------------------ | -------------------------------------- | ------------------------------------ | -------------------------------------------------------------- |
| Authored / config  | git 上の型付き定義                     | 必要に応じて R2 snapshot             | metrics、categories、ThemeCatalog、IndicatorSet、affiliate ads |
| Authored / content | git 上の原稿・frontmatter              | R2 snapshot                          | blog article                                                   |
| Operational state  | domain が定める git 管理 state         | 原則として agent / automation 内だけ | SNS 投稿台帳、改善候補、実験状態                               |
| Observation        | R2                                     | R2                                   | e-Stat 値、外部 API 取得値                                     |
| Reference          | 外部 API または再生成可能な git source | git または R2                        | e-Stat catalog、都道府県・市区町村 master                      |
| Derived            | 入力データ + 計算コード                | R2 snapshot                          | area profile、correlation、集計済み ranking                    |

`Operational state` を公開アプリの runtime SSOT に転用しない。`.claude/state/` はエージェントと自動化の状態であり、配信用 snapshot ではない。

### Authored definition の形式

TypeScript を既定とする。型検査、参照整合性、review が効くためである。

主な正典:

- metrics / categories: `packages/data-configs/src/`
- ThemeCatalog: `packages/data-configs/src/theme-catalog/`
- IndicatorSet: `packages/types/src/indicator-sets/`
- affiliate ads: `apps/web/scripts/affiliate-ads-data.ts`

`apps/web/scripts/data/page-components/**/*.json` は既存の domain exception である。git 管理、schema 検証、専用 exporter を一組として扱い、同型の手編集 JSON を別の場所へ増やさない。

## 標準フロー

### 設定・コンテンツ

```text
git definition
  ├─ type/schema validation
  ├─ cross-reference validation
  └─ deterministic exporter
          ↓
      R2 snapshot
          ↓
      runtime reader
```

生成物は手編集しない。変更は入力側へ戻し、同じコマンドで同じ出力を再現できるようにする。

### 観測値

```text
external API
  └─ fetch → provenance/shape validation → R2 observation
```

- 取得元、期間、単位、地域粒度を失わない。
- 欠損と 0 を同一視しない。
- 出典と再現性の契約は `.claude/rules/data-provenance-standards.md` に従う。

### 派生値

```text
R2 observations + git definitions
  └─ temporary compute (:memory: SQLite / DuckDB / pure code)
       └─ validate → R2 derived snapshot
```

一時 DB は cache または計算手段であり、復元不能な唯一のデータを保持してはならない。

## page_components

`page_components` はテーマ、エリア、ランキング等のチャート配置を宣言する。

| 役割           | 場所                                                  |
| -------------- | ----------------------------------------------------- |
| git source     | `apps/web/scripts/data/page-components/`              |
| exporter       | `apps/web/scripts/export-page-components-snapshot.ts` |
| runtime reader | `apps/web/src/components/stat-charts/services/`       |
| 配置判断       | [`03_情報設計.md`](./03_情報設計.md)                  |
| UI 契約        | `.claude/design-system/page-components.md`            |

定義追加時は key の存在、page type、metric 参照、重複、配信 snapshot との一致を専用 validator で確認する。

## R2 の責務

R2 は次の二役を持つ。

- **observation store** — 外部データの観測値
- **serving store** — 公開アプリが効率よく読む集約済み JSON

key、Content-Type、cache、差分 upload、削除の詳細は `.claude/rules/r2-storage-design.md` を正典とする。新しい prefix を追加する場合は、reader、writer、検証、保持期間、所有 domain を同時に定義する。

## D1 / SQLite の許容範囲

| 許容                        | 禁止                                        |
| --------------------------- | ------------------------------------------- |
| integration test の一時 DB  | リモート D1 を運用 SSOT にする              |
| build 中だけ存在する cache  | ローカル SQLite だけに authored data を置く |
| `:memory:` 集計             | 観測値・派生値を DB へ恒久保存する          |
| schema を型・テストに再利用 | 本番アプリから DB query する                |

`packages/database/src/schema/` と関連テストは、型ソースと検証基盤として残置できる。存在するだけで永続 DB を採用しているとはみなさない。

## 保存先の判断

```text
外部に真実源があるか
  ├─ yes → Reference / Observation として取得・再生成
  └─ no
      ├─ 入力から決定的に計算できるか
      │   ├─ yes → Derived。計算後 R2 へ出力
      │   └─ no  → Authored。git の型付き定義へ
      └─ agent の進捗・台帳か → .claude/state または .claude/todo
```

判断に迷う場合は `.claude/rules/data-storage.md` を使う。新しい永続層を追加して解決しない。

## 変更時の検証

1. 真実源、生成物、cache を区別したか。
2. writer と reader が同じ schema / key contract を使うか。
3. 欠損、空、0、not-found、upstream failure を区別するか。
4. 生成が決定的で、手編集した配信 JSONを必要としないか。
5. remote write を dry-run と差分確認なしで実行しないか。
6. runtime bundle または build が巨大な registry / 全量 R2 read を引き込まないか。
