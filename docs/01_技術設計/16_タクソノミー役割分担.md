# 3 タクソノミー役割分担 (category / theme / tag)

stats47 では分類概念として **category / theme / tag の 3 軸を意図的に並立** させる。本ファイルはそれぞれの役割・選択基準・実装上の住み分けを定義する。

## なぜ 3 並立か

過去 (~2026-05) は「category は deprecated、tag に統合中」とされていたが、実運用では 3 軸がそれぞれ異なる役割を果たしていることが GSC 実測 (2026-W21) で確認された:

| 軸 | ページ数 | 週次 imp | 週次 clicks | 役割 |
|---|---|---|---|---|
| `/category/*` | 11 | 39 | 2 | サイドバー主要ナビ。e-Stat 機械分類のブラウズ動線 |
| `/themes/*` | 15 | 152 | 4 | curated ダッシュボード。SEO 上の主力ハブ |
| `/tag/[key]` | (blog のみ) | (blog 経路) | (blog 経路) | ブログ記事の横断分類 |

→ themes が curated コンテンツとして 4 倍の imp を稼いでおり、category とは異なる SEO 価値を持つ。tag はブログに閉じた使い方で安定している。3 軸を統合すると役割が曖昧になり SEO 上もマイナス。

詳細議論: `~/.claude/plans/ok-validated-stroustrup.md` Context セクション。

## 3 タクソノミーの定義

### 1. `categories` — e-Stat 機械分類 (17 軸)

| 項目 | 内容 |
|---|---|
| 真実源 | D1 `categories` テーブル → R2 snapshot `app/categories/all.json` |
| URL | `/category/[categoryKey]` |
| 例 | `population`, `economy`, `laborwage`, `agriculture`, `tourism`, `safetyenvironment`, `administrativefinancial` ほか 17 件 |
| 由来 | e-Stat 統計大分類 |
| 用途 | サイドバー主要ナビ。「同じ統計分野の他の指標を見たい」用 |
| 実装 | `packages/category/`、`components/organisms/Sidebar/CategoryAccordion` |
| 表示メタ | `categoryKey`, `categoryName`, `icon`, `displayOrder` |

### 2. `themes` — curated ダッシュボード (24 軸)

| 項目 | 内容 |
|---|---|
| 真実源 | D1 `themes` + `theme_metrics` (284 行) + `page_components` (411 行) / TS-config `packages/types/src/indicator-sets/` |
| URL | `/themes/[themeSlug]` (動的ルート、Phase 3 で集約 2026-05-28) |
| 例 | `healthcare`, `aging-society`, `tourism`, `population-dynamics`, `local-finance` ほか 17 件本体 + 7 件 compare 系 |
| 由来 | 人間が curated した分析ダッシュボード (`packages/types/src/indicator-sets/registry.ts`) |
| 用途 | 「テーマで深掘り分析したい」用。chart 構成・description あり |
| 実装 | `apps/web/src/features/theme-dashboard/`、`apps/web/src/app/themes/[themeSlug]/page.tsx` |
| 表示メタ | `themeKey`, `title`, `description`, `keywords`, `chart_type`, `panel_label` ほか |
| 例外 | `themes/local-finance/page.tsx` と `cities/page.tsx` は static (都道府県/市区町村切替 UI) |

### 3. `tags` — ブログ記事の横断分類

| 項目 | 内容 |
|---|---|
| 真実源 | `articles.tags` JSON 列 (D1) — テーブル分離せず JSON 直接格納 (PR #215, 2026-05-05) |
| URL | `/tag/[tagKey]` (ブログ専用) |
| 例 | 日本語キー (例: `寿命`, `所得`, `教育`) |
| 由来 | blog 記事の curated タグ |
| 用途 | 「このトピックの他の記事を読みたい」用 |
| 実装 | `apps/web/src/features/blog/`、`apps/web/src/app/tag/[tagKey]/page.tsx` |
| 制約 | 記事 < 2 件のタグは `noindex` (thin content 回避) |
| 拡張余地 | 将来ランキング横断対応も検討可だが現時点では実施しない |

## 選択フロー (新規分類追加時)

新しい分類軸を追加したい時、以下のフローで判断する:

```
新規分類を追加したい
  ↓
e-Stat 統計大分類か?
  ├─ YES → categories に追加 (PR で D1 INSERT)
  └─ NO ↓

人間 curated の「テーマ別ダッシュボード」か (chart 構成持ち)?
  ├─ YES → themes / theme_metrics に追加 (packages/types/src/indicator-sets/ に TS config + seed-themes.ts)
  └─ NO ↓

ブログ記事の横断分類か?
  ├─ YES → articles.tags JSON 列に追加 (記事側で指定)
  └─ NO ↓

既存 3 タクソノミーに合わないなら、設計から見直す
  → 既存軸を拡張するか、新規軸を立てるかは critical-review で要相談
```

## アンチパターン (やってはいけないこと)

| ❌ NG | 理由 |
|---|---|
| category と theme で同じキー名を使う | 役割が違うため別キー空間にする (現状でも別) |
| `/tag` をランキング横断対応にすぐ拡張 | tag メタ (display_name / icon / order) 未整備、サイドバーが壊れる |
| `/category` を削除して `/themes` に統合 | サイドバー機能停止 + categoryKey 依存箇所 (areas / affiliate_ads) 多数 |
| 同じ概念を新たに「subcategories」「topics」等で追加 | 軸が増えるほど認知負荷が上がる、3 軸で固定 |
| themes のキーを compare-* で命名する新規追加 | compare-* は IndicatorSet 用 (実は compare 機能と無関係)、混乱の元 |

## 将来 tag 統合を検討する場合の前提条件

現時点では tag 統合は実施しない。将来検討する場合は以下を先に整備する:

1. tag テーブル復活 (`tag_key`, `display_name`, `icon`, `display_order`, `show_in_sidebar`) または同等の curated リスト
2. 17 categories → tag マッピング表 (1:N or N:1 の関係を明示)
3. `/category/[key]` → `/tag/[tagKey]` の 301 マッピング
4. `/areas/[code]/[categoryKey]` `affiliate_ads.categoryKey` 等の参照箇所の改修計画
5. サイドバー UI 維持の検証 (categoryKey → tagKey 切替時に UI が壊れないか)
