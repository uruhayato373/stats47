# 自動化インベントリ

stats47 で登録されている自動処理の入口を一覧化する。追加・削除時は本書も同じ変更で更新する。

本書は**存在と所有範囲の索引**である。cron、event filter、permissions、secret、処理手順の最終正典は Workflow / plist / remote trigger 本体とする。個々の script や package command をすべて複製しない。

## 実行基盤

| 基盤                 | 用途                                    | 登録の正典                                                  | 状態確認                           |
| -------------------- | --------------------------------------- | ----------------------------------------------------------- | ---------------------------------- |
| GitHub Actions       | CI、計測、snapshot、公開、監査          | `.github/workflows/*.yml`                                   | `gh workflow list`                 |
| launchd              | ローカル browser profile 等が必要な処理 | `scripts/scheduled/*.plist`                                 | `launchctl list`                   |
| Claude Code Routines | AI 判断を含む remote schedule           | Claude Code Routines + `.claude/state/triggers.json` の台帳 | Routines UI                        |
| 手動 CLI / skill     | 人の確認や承認が必要な処理              | `package.json`、`.claude/skills/*/SKILL.md`                 | 対象 command の `--help` / dry-run |

GitHub Actions で実行できる決定的処理を launchd へ置かない。ログイン済み browser や端末固有資源が必要な場合だけ launchd / Playwright を使う。外部公開、投稿、R2 write、設定変更は既存の承認ゲートに従う。

## ローカルガード

| 入口                                                          | 発火条件                       | 所有範囲                             |
| ------------------------------------------------------------- | ------------------------------ | ------------------------------------ |
| `.husky/pre-commit` → `apps/web/scripts/pre-commit-checks.sh` | commit前                       | 文書、設計、型、構成などの決定的検査 |
| `.husky/commit-msg` → `.claude/scripts/lib/check-commit-message.cjs` | commit メッセージ確定時 | CI skip トークン (`[skip ci]` 等) の混入を拒否。逃げ道は本文の `ALLOW-SKIP-CI: <理由>` |
| `npm run preflight` (`.claude/scripts/lib/preflight-commit.mjs`) | 手動 (commit 前に任意)      | 頻出 3 ゲートを**並列**実行し blocker を一度に列挙 (pre-commit は直列 all-or-nothing で 2 分超。実測 2.7〜11.6 秒) |
| `.claude/hooks/check-consistency-on-stop.js`                  | Claude Code Stop               | agent / skill / script変更の監査漏れ |
| `.claude/hooks/check-docs-on-stop.js`                         | 文書差分があるClaude Code Stop | 文書構造とリンク悪化                 |

Codexは`AGENTS.md`（`CLAUDE.md`へのsymlink）とpre-commit、PR gateで同じ文書契約を通る。

## launchd

git で管理する登録定義は現在二つ。

| plist                                                    | 実行 script                               | 用途                                                                                             |
| -------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `scripts/scheduled/com.stats47.scout-asp-weekly.plist`   | `scripts/scheduled/scout-asp-weekly.sh`   | ASP の browser 調査                                                                              |
| `scripts/scheduled/com.stats47.kdp-resume-daily.plist`   | `scripts/scheduled/kdp-resume-daily.sh`   | KDP 32 冊出版の再開 (作成数制限が空き次第 draft→verify→publish。全冊 listed で自動的に no-op。オーナー指示 2026-08-13) |

`scripts/scheduled/` に plist から参照されない helper があっても、登録済み task とはみなさない。`~/Library/LaunchAgents/` と `launchctl list` は端末の変動状態なので git 文書へ固定しない。

```bash
# 定義を読み込む
launchctl load scripts/scheduled/com.stats47.scout-asp-weekly.plist

# 定義を外す
launchctl unload scripts/scheduled/com.stats47.scout-asp-weekly.plist

# 登録状態
launchctl list | rg stats47
```

Playwright profile の扱いは [`07_Playwright認証プロファイル.md`](./07_Playwright認証プロファイル.md) に従う。

## Claude Code Routines

`.claude/state/triggers.json` は登録時の台帳であり、remote の live state ではない。実行可否は Routines UI で確認する。

| 台帳上の trigger               | schedule | 台帳上の状態       |
| ------------------------------ | -------- | ------------------ |
| stats47 weekly PDCA            | 月曜     | remote 確認が必要  |
| stats47 daily trend pipeline   | 毎日     | enabled            |
| stats47 weekly CWV PR          | 月曜     | enabled            |
| stats47 daily blog conformance | 毎日     | pending / disabled |

model 名、environment ID、最終実行時刻を本書へ複製しない。trigger の追加・削除時は `.claude/state/triggers.json` と本表を更新する。

## CI で鮮度を守る生成物

schedule 以外でも、手編集禁止の生成物は CI / pre-commit の check を自動化として扱う。

| generate / check                                                        | 入力                                         | 出力                                                        |
| ----------------------------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------- |
| `generate:runtime-summaries` / `check:runtime-summaries` (`apps/web`)   | metric definitions                           | `apps/web/src/config/runtime-metric-summaries.generated.ts` |
| `generate:ranking-prominence` / `check:ranking-prominence` (`apps/web`) | metric definitions + committed GSC snapshot  | `apps/web/src/config/ranking-prominence.generated.ts`       |
| `audit:ranking-hooks` (`apps/web`)                                      | ranking prominence                           | Workflow summary                                            |
| `export-page-components-snapshot.ts` / verify                           | page_components git source                   | R2 `app/page-components/`                                   |
| `export-affiliate-ads-snapshot.ts`                                      | affiliate ads git source                     | R2 affiliate snapshot                                       |
| `docs:fix` / `docs:check`（root）                                       | 文書ガバナンス設定 + docs実体                | 実装計画INDEX / 構造・鮮度・リンク検査                      |
| `state:snapshots:prune`（root）                                         | PSI / GSC URL Inspection / Cloudflare 生計測 | 固定保持（1 / 7 / 30件）。履歴・queue・台帳は対象外         |
| `test:alert-lifecycle`（root）                                          | domain alert Workflow                        | 固定Issue・upsert・復旧時Close契約                          |
| `lintScatterQuality` / `svg-lint.scatter.test.mjs`                      | 記事用 scatter SVG                           | 720×720・正方形プロット・単色・凡例なしを公開前に検査       |

生成規則は source module、実行条件は `package.json` / Workflow、保存先は [`02_データアーキテクチャ.md`](./02_データアーキテクチャ.md) を正典とする。

## 追加・変更・削除

1. 既存 Workflow、package script、skill と重複しないか検索する。
2. deterministic な処理か、人の承認または browser session が必要かを決める。
3. read / write、secret、branch、出力先、idempotency、timeout を定義する。
4. dry-run または fixture で意図を検証する。
5. 登録定義と本インベントリを同じ変更で更新する。
6. 廃止時は呼び出し元と生成物の consumer を確認してから定義を削除する。

外部状態を変える automation は、失敗時の再実行で二重投稿・二重書き込みを起こさない contract を持たせる。

## Alert と TODO

- 日次監視の異常は `auto-generated` と domain alert label（`psi-alert`、`cloudflare-alert`、`ogp-alert`、`link-alert` 等）を使う。
- domain alert は「1障害=1 open Issue」とし、タイトルへ日付を入れず最新bodyへ置換する。正常復帰を検知した実行で自動Closeする。
- 定期候補・日次作業キューは Issue を作らず、Workflow Summary と `.claude/todo/` / `.claude/state/` の正典へ出す。
- PR で close する修正は `bug` または `enhancement` Issue を使う。
- 未着手の自動化候補は `.claude/todo/backlog.md`、運用改善は `.claude/todo/improvements.md` に置く。
- `automation-broken` / `automation-candidate` のような独自 Issue 台帳を本書から要求しない。

## 定期監査

```bash
gh workflow list
launchctl list | rg stats47
jq '.triggers[] | {name, cron, enabled}' .claude/state/triggers.json
rg --files .github/workflows scripts/scheduled | sort
```

確認項目:

- 本書に無い登録定義、または実体の無い記載がないか。
- schedule が同時刻へ集中していないか。
- commit-back 同士が競合しないか。
- secret / token の期限切れを正常終了として扱っていないか。
- 生成物の consumer が廃止済みでないか。
- disabled / pending task を運用中と報告していないか。
