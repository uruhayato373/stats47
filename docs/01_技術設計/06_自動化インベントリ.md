# 自動化インベントリ

stats47 で登録されている自動処理の入口を一覧化する。追加・削除時は本書も同じ変更で更新する。

本書は**存在と所有範囲の索引**である。cron、event filter、permissions、secret、処理手順の最終正典は Workflow / plist / remote trigger 本体とする。個々の script や package command をすべて複製しない。

## 実行基盤

| 基盤                 | 用途                                    | 登録の正典                                                  | 状態確認                           |
| -------------------- | --------------------------------------- | ----------------------------------------------------------- | ---------------------------------- |
| GitHub Actions       | CI、計測、snapshot、公開、監査          | `.github/workflows/*.yml`                                   | `gh workflow list`                 |
| launchd              | ローカル browser profile 等が必要な処理 | `scripts/scheduled/*.plist`                                 | `launchctl list`                   |
| Windows Task Scheduler | 端末の容量・RAM計測と限定掃除 | `scripts/scheduled/local-resources.ps1` | `Get-ScheduledTask -TaskName stats47-local-resources` |
| Codex heartbeat | ローカル点検結果の異常・変化の通知 | Codex automation `stats47`（stats47 ローカル資源の点検結果を確認） | Codex Automations |
| Claude Code Routines | AI 判断を含む remote schedule           | Claude Code Routines + `.claude/state/triggers.json` の台帳 | Routines UI                        |
| 手動 CLI / skill     | 人の確認や承認が必要な処理              | `package.json`、`.claude/skills/*/SKILL.md`                 | 対象 command の `--help` / dry-run |

GitHub Actionsで実行できる決定的処理をlaunchdへ置かない。認証付きの読み取りもサービス別storageStateを安全に移送できるものはCIのPlaywrightへ載せる。初回ログイン・2FA・端末固有資源だけローカルへ残す。外部公開、投稿、R2 write、設定変更は既存の承認ゲートに従う。

認証付き計測は、拒否された本人認証世代の再接続を止めて他sourceを継続する。既存の日次healthがschedule未発火を6時間猶予で検知し、予定枠を永続予約して1回だけ補完起動する。補完起動・再認証待ち・noteの記事棚卸し限定利用を全件計測成功と区別する。契約と限界は[認証プロファイル](./07_Playwright認証プロファイル.md#ci-実行について)を参照。

## 追加・変更・削除

1. 既存 Workflow、package script、skill と重複しないか検索する。
2. deterministic な処理か、人の承認または browser session が必要かを決める。
3. read / write、secret、branch、出力先、idempotency、timeout を定義する。
4. dry-run または fixture で意図を検証する。
5. 登録定義と本インベントリを同じ変更で更新する。
6. 廃止時は呼び出し元と生成物の consumer を確認してから定義を削除する。

外部状態を変える automation は、失敗時の再実行で二重投稿・二重書き込みを起こさない contract を持たせる。

## Alert と TODO

- 日次監視の異常は `auto-generated` と domain alert label（`psi-alert`、`cloudflare-alert`、`ogp-alert`、`link-alert` 等）を使う。
- domain alert は「1障害=1 open Issue」とし、タイトルへ日付を入れず最新bodyへ置換する。正常復帰を検知した実行で自動Closeする。
- 定期候補・日次作業キューは Issue を作らず、Workflow Summary と `.claude/todo/` / `.claude/state/` の正典へ出す。
- PR で close する修正は `bug` または `enhancement` Issue を使う。
- 未着手の自動化候補は `.claude/todo/backlog.md`、運用改善は `.claude/todo/improvements.md` に置く。
- `automation-broken` / `automation-candidate` のような独自 Issue 台帳を本書から要求しない。
