# システムアーキテクチャ

stats47 は Next.js 15 App Router を Cloudflare Workers (OpenNext) 上で動かすフルスタック Web アプリ。
e-Stat API 等から 47 都道府県の統計を取得し、ランキング・ダッシュボード・チャートで可視化する。
本ドキュメントは**技術スタック・モノレポ構造・実行時アーキテクチャ**の概観をまとめる。

> **データ層の正典は [`12_完全DBレス設計.md`](./12_完全DBレス設計.md)。**
> SSOT は **git TS (設定・運用エンティティ) + R2 (観測値・配信) の二つだけ**。永続/リモート D1 は廃止。
> 本番アプリは R2 snapshot のみ読む。

## 技術スタック

| 領域 | 採用技術 |
|---|---|
| コア | Next.js 15 (App Router) / React 19 / TypeScript 5.9 |
| スタイリング・UI | Tailwind CSS 3 / shadcn/ui (Radix) / Lucide / next-themes / Sonner / KaTeX |
| 状態管理 | **Zustand** (グローバル: sidebar / area-code) / React State (ローカル) / Zod (バリデーション) |
| 可視化 | D3.js / topojson-client / @tanstack/react-table / Leaflet (GIS 地図) |
| 検索 | MiniSearch (クライアントサイド) |
| バックエンド | Next.js Route Handlers (CSV ダウンロード等) |
| データ層 | **Cloudflare R2** (観測値・配信 SSOT) / **git TS** (設定・運用 SSOT) / Drizzle schema (型ソース・テスト用) / Better SQLite3 (使い捨てビルドキャッシュ・エフェメラル集計)。永続 D1 なし |
| 外部 API | e-Stat API / 国土数値情報 (MLIT) / Google Gemini (Remotion の AI 機能) |
| 動画・画像 | Remotion (動画・SNS 静止画) / Sharp (画像処理) |
| インフラ | Cloudflare Workers / OpenNext Cloudflare / Cloudflare CDN・DNS |
| モノレポ | npm workspaces / Turborepo |
| コード品質 | ESLint / Prettier / TypeScript / Husky / Knip |
| テスト | Vitest / React Testing Library / Playwright (smoke 含む) / MSW |
| ツール | Wrangler / tsx / Obsidian (docs) |

技術選定の原則: **型安全性 / エッジ・CDN によるパフォーマンス / Cloudflare 無料枠での低コスト / モダンな開発体験 / シンプルな保守性**。

## プロジェクト構造 (モノレポ)

```
stats47/
├── apps/
│   ├── web/             # メインの Next.js アプリ (App Router) — 公開サイト
│   ├── remotion/        # 動画・SNS 静止画生成 (Remotion)
```

### apps/web の構造

```
apps/web/src/
├── app/           # App Router ルート定義
├── features/      # 機能別モジュール (主要なコード配置先)
├── components/    # 共有コンポーネント (organisms/molecules) + layout (PageShell)
├── hooks/ store/ lib/ config/ constants/ types/ providers/
└── middleware.ts  # 301/410・canonical (URL 構造の実装)
```

- **features/**: 機能ごとに `actions/ components/ services/ adapters/ types/ utils/ hooks/ lib/` を必要分だけ持つ。feature 一覧は [DDDドメイン分類](./02_DDDドメイン分類.md)。
- **ルート構造**: `ranking/[rankingKey]` (主力 SEO) / `category/[categoryKey]` (+/compare) / `themes/[themeSlug]` / `areas/[areaCode]` (+/[themeSlug] /cities) / `survey/[surveyKey]` / `blog/[slug]` + `tag/[tagKey]` / `search` / 静的 (about/privacy/terms)。URL 体系・301/410・canonical の正典は [URL 構造](./11_URL構造.md)。App Router の `dynamic` / `revalidate` / `generateStaticParams` 判断は [App Router レンダリング方針](./14_App_Routerレンダリング方針.md)。

## レンダリング戦略

| データ特性 | 方式 | 適用例 |
|---|---|---|
| git/static data だけで成立する SEO 対象 | SSG (`generateStaticParams`) | ranking 索引、cities SSG 対象、静的ページ |
| 更新が緩やかで runtime 初回生成できるページ | ISR (`revalidate`) | ranking 詳細、カテゴリ、survey、blog、area theme |
| build 時 R2 read が危険なページ | Runtime SSR (`force-dynamic`) | home、theme dashboard、local-finance |
| ユーザー操作依存 | CSR (Client Component) | 絞り込み、地図インタラクション、比較 UI |

- デフォルトは Server Component。`useState` / `useEffect` / イベントハンドラがある場合のみ `"use client"`。
- R2 取得失敗を薄い 200 HTML として返さない。存在しない resource は `notFound()`、一時的な R2 失敗は throw して error boundary に流す。
- **layout (またはその配下の Server Component) で `cookies()` / `headers()` を呼ぶと SSG が崩れる** →
  `.claude/rules/nextjs-ssg-preservation.md` 必読。

## データフロー (完全DBレス)

```
[git TS 定義 (設定・運用 SSOT)] ──生成スクリプト──▶ [R2 app/<domain>/...]
[e-Stat / MLIT API]            ──/page-data-batch──▶ [R2 app/stats/<metric>/*.json]
[R2 観測値]                    ──エフェメラル計算──▶ [R2 派生 snapshot (profile / 相関)]
                                                      ↓ fetchFromR2AsJson
                                            [Server Component → Page]
```

- 本番アプリは DB を一切 query しない (`getDrizzle()` 実行時 query = 0、Phase F 2026-05-30)。
- R2 書き込みは CI / クラウド専用 (`.claude/rules/r2-storage-design.md`)。
- 主要エンティティの SSOT 別分類は doc 12 §3 の決定表を参照。

## 動的ダッシュボードシステム (page_components)

テーマ / エリア / ランキング各ページのチャート構成は `page_components` で宣言的に管理する。

- **定義 (SSOT)**: git TS `apps/web/scripts/data/page-components/<pageType>/<key>.json`
  - pageType: `theme` / `area-category` / `area` / `ranking` / `city-category`
- **生成**: `apps/web/scripts/export-page-components-snapshot.ts` で R2 `app/page-components/all.json` を直接生成 (横断整合性はビルド時に検証)
- **配置の判定基準**: [情報設計 (ページ責務・タクソノミー・ファネル)](./07_情報設計.md)
- ダッシュボード追加はレコード追加のみ (コード変更ゼロ)

## キャッシュ階層

| 層 | 用途 | 実装 |
|---|---|---|
| CDN/Edge (Cloudflare) | 静的アセット + ページ配信 | Cache-Control。410 は 7 日キャッシュ (`/purge-cdn` で消去) |
| R2 snapshot | ビルド済みページデータ | 再生成 = `/sync-snapshots` (CI) |
| e-Stat API キャッシュ | API レスポンス再利用 | R2 (キーは statsDataId + cat。年度・地域でキャッシュ分断しない → `.claude/rules/estat-api.md`) |

## バンドル・パフォーマンス最適化

- **Dynamic Import**: 重い可視化 (Leaflet / D3 大型チャート) は `next/dynamic` で遅延ロード
- **TopoJSON**: GeoJSON より 30-80% 軽量。47 都道府県レベルは SVG レンダリング
- **コンテナクエリ**: ダッシュボードカードグリッドは `@sm:`/`@md:`/`@lg:` (右レール有無で本文幅が可変のため) → `.claude/rules/ui-components.md`
- 計測: PSI 日次 (`psi-audit-daily.yml`)、改善ルールは `.claude/rules/evidence-based-judgment.md` (LCP は要素特定が先)
