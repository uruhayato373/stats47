# システムアーキテクチャ

stats47 は、都道府県・市区町村の統計をランキング、ダッシュボード、記事で可視化する Web アプリケーションである。公開サイトは Next.js App Router を OpenNext 経由で Cloudflare Workers 上に配信する。

この文書はシステム境界と変更判断を扱う。ライブラリの正確なバージョン、ルートごとの `dynamic` / `revalidate`、R2 キーの詳細はコードを正典とし、ここへ複製しない。

## システム構成

```text
e-Stat / 国土数値情報 / その他の公開データ
                     │ 取得・検証
                     ▼
        生成スクリプト / CI / エフェメラル集計
          │                         │
          │ authored definitions    │ observations / snapshots
          ▼                         ▼
        git                         Cloudflare R2
                                      │
                                      │ runtime read
                                      ▼
                      Next.js App Router / Workers
                                      │
                                      ▼
                               Browser / Crawler
```

公開アプリのデータ読み取りは R2 snapshot に限定する。永続 DB をアプリの依存先または真実源にしない。

## モノレポの責務

```text
apps/
  web/       公開サイト、Route Handler、サイト固有 UI
  remotion/  動画・SNS 静止画の生成
  ges/       Google Earth Studio 用素材・処理
packages/
  */         再利用可能なドメインロジック、データ定義、可視化、外部 API、型
```

- `apps/web/src/app/` は routing、metadata、route params の組み立てに寄せる。
- ページ固有の loader、表示ロジック、UI は `apps/web/src/features/<feature>/` に置く。
- 複数 feature で使う UI は `apps/web/src/components/`、アプリをまたぐプリミティブは `packages/components/` に置く。
- 再利用可能な計算、データ取得、型は `packages/*` に置き、`apps/*` への逆依存を作らない。
- 詳細なディレクトリと開発コマンドは `.claude/rules/local-environment.md` を正典とする。

## ドメイン境界

| 境界              | 主な責務                                 | 主な配置                                                                             |
| ----------------- | ---------------------------------------- | ------------------------------------------------------------------------------------ |
| Ranking           | 指標単位の順位、地図、比較、関連導線     | `apps/web/src/features/ranking/`、`packages/ranking/`                                |
| Theme / Dashboard | 複数指標を意味のある順序で統合           | `apps/web/src/features/theme-dashboard/`、`packages/data-configs/src/theme-catalog/` |
| Area              | 都道府県・市区町村軸のプロフィールと比較 | `apps/web/src/features/area/`、`packages/area*`                                      |
| Survey            | 統計調査を軸にした指標の束               | `apps/web/src/features/survey/`                                                      |
| Blog              | 記事、タグ、記事内チャート               | `apps/web/src/features/blog/`、記事ソース                                            |
| Visualization     | チャート、地図、表示用変換               | `packages/visualization/`、`apps/web/src/components/charts/`                         |
| Data acquisition  | e-Stat、GIS、R2 の取得・変換             | `packages/estat-api/`、`packages/gis/`、`packages/r2-storage/`                       |

依存は、ページ層からドメイン層、ドメイン層から共有基盤へ向ける。feature 間の直接 import を増やさず、共有が必要なものは共有層へ昇格する。

## Web ランタイム

### Server / Client の分担

- Server Component を既定とする。
- state、effect、ブラウザ API、イベント処理が必要な範囲だけ Client Component にする。
- 重い地図・チャートは画面上の必要性と計測結果を確認して遅延読み込みする。
- 共通 Header など全 route に入るコードから、指標 registry や巨大な chart module を import しない。表示用の小さな生成物を読む。

### レンダリング方針

ルートごとの実際の設定は各 `app/**/page.tsx` を正典とする。選択原則は次のとおり。

| 条件                                           | 方針                     |
| ---------------------------------------------- | ------------------------ |
| git/static data だけで成立する SEO ページ      | SSG                      |
| 更新が緩やかで初回 runtime 生成できる          | ISR                      |
| build 時の R2 不在で主要内容が空焼き込みされる | Runtime SSR              |
| ユーザー操作または `searchParams` に依存       | CSR または dynamic route |

- `generateStaticParams` の key は、build 時の不安定な R2 list だけに依存させない。
- `cookies()` / `headers()` を共通 layout へ追加する場合は SSG への影響を先に確認する。
- build phase の fallback と runtime 障害を混同しない。runtime の取得失敗を空配列へ変換して薄い `200` を返さない。
- URL 上の resource 不在は `notFound()`、一時的な upstream 障害は throw して error boundary へ流す。

## データフロー

```text
git 上の authored definitions ── exporter ──▶ R2 serving snapshot
外部 API の観測値             ── fetch/validate ──▶ R2 observations
R2 observations               ── 一時集計 ──▶ R2 derived snapshot
R2 serving snapshot           ── reader ──▶ Server Component
```

テーマ、エリア、ランキングのチャート配置は `apps/web/scripts/data/page-components/` で定義し、`apps/web/scripts/export-page-components-snapshot.ts` で配信用 snapshot を生成する。配置判断は情報設計、保存判断はデータアーキテクチャに従う。

## キャッシュと性能

- Cloudflare CDN はページと静的アセット、R2 は配信用 snapshot を担う。
- cache duration はデータの更新契約に合わせ、値を文書へ固定せず route と reader のコードで管理する。
- ダッシュボードの列数は viewport ではなく実際の親幅に依存するため、必要な箇所では container query を使う。
- LCP、bundle、navigation の改善は推測で行わず、対象 route と遅延箇所を計測してから変更する。
- runtime 用の小さな要約は `generate:runtime-summaries`、ランキング掲載情報は `generate:ranking-prominence` で生成し、CI の鮮度検査を通す。

## 観測と運用

- GA4 / GSC は流入と行動、PSI は Web Vitals、Cloudflare は配信と利用量を観測する。
- snapshot と機械メトリクスは `.claude/state/metrics/`、改善 TODO は `.claude/todo/improvements.md` に置く。
- schedule と CI の登録一覧は自動化インベントリを参照する。処理内容と cron の最終正典は各 Workflow / plist / trigger 定義である。

## アーキテクチャ変更時の確認

1. 新しい責務が既存 feature または package に属さないか。
2. 公開アプリへ永続 DB または live 外部 API の必須依存を持ち込んでいないか。
3. build、runtime、client のどこで処理するかが明確か。
4. URL、sitemap、canonical、not-found の契約が同じ allowlist を参照するか。
5. 失敗時に空の `200` や古い snapshot を正常扱いしていないか。
6. 生成物の入力、出力、鮮度検査が定義されているか。
