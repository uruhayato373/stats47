# デザインシステム

stats47 の UI は、統計を迷わず探し、比較し、長時間読める道具として設計する。装飾より情報階層、派手な差別化より一貫性を優先する。

この文書は UI 判断の正典である。実際の class、props、token はコードを正典とし、数値を本書へ二重管理しない。

## 原則

1. **データファースト** — 主要な値、比較、出典へ短い距離で到達できる。
2. **テンプレートを正とする (2026-10-27 オーナー決定)** — 部品・色・角丸・余白はテンプレートに寄せ、独自の部品や値をできるだけ持たない。白基調・角丸なしのカード・細い線・影なし・詰めた余白。チャートは D3 のまま、見た目だけをテンプレートのチャートに合わせる (Recharts は gzip 約 119KB の上乗せになるため使わない)。
3. **一つの意味に一つの表現** — 同じ種類の header、card、rail を feature ごとに作り直さない。既存UIで目的を満たせる場合は、新しいUIを追加せず共通部品を使う。
4. **日本語の可読性** — system font、過度な letter spacing を避け、本文幅と行間を守る。
5. **responsive は情報優先度で決める** — desktop を縮小するだけでなく、mobile の読む順序を設計する。
6. **accessibility は見た目と同格** — heading、focus、contrast、keyboard、reduced motion を後付けにしない。
7. **目的地までの操作を減らす** — 探索用リンクは可能な限り常時表示し、表示領域に収まる一覧へ不要な折りたたみや中間操作を加えない。

## ブランドの視覚方針：地域のデータアトラス

stats47 の発行元としての印象は「地域を見つけ、データで確かめ、比較できる」に統一する。地理的な視点と統計の根拠を同時に伝える。都道府県ランキングに加え、テーマ、調査、地域、ブログ、実務向け資料にも通用する方針とし、「47」はサービス名の一部として扱い、対象地域数の上限を示す記号にはしない。

- 識別の核は `stats47` の文字と、**折りたたんだ地図に一地点の注目を示す**簡潔な記号とする。記号は小サイズ用に省略しても同じ輪郭を保つ。正式なベクターと 16/32px の視認性を確かめるまでは、生成画像中のロゴを正式資産として使わない。
- 色の軸は既存の藍・インク色・白に置く。UI の実値は `globals.css` の semantic token、OGP の実値は `apps/web/src/features/ogp/brand.ts` を正典とする。砂色などの暖色は地域を描く補助に限り、順位・増減・危険度などのデータ上の意味をブランド色で上書きしない。
- サイトの通常面は既存の白基調・フラットな設計を守る。地図の折り目や地域風景は、発行元の識別や内容理解を助ける場面に置き、ランキング表・チャート・出典を覆わない。全ページに同じ大きな地図画像を敷かない。
- 実際の地域形状、値、順位を示す図は根拠データから描画する。装飾用の地図風図案は精密な行政界や数値に見せず、統計図として読まれる位置に置かない。
- キャラクターはこの方針の必須要素にしない。発行元名、問い、図、出典の反復で識別を作る。

### 画像への展開

画像種別の寸法・保存先・配信は既存の画像規約を正典とし、見た目は以下の共通原則を適用する。

| 接点 | 共通原則 |
| --- | --- |
| favicon・サイトヘッダー・SNSプロフィール | 同じ記号の骨格を使う。サイトヘッダーと横長画像では `stats47` の文字を併記し、円形トリミングと 16/32px で判読できる省略版を用意する。 |
| サイト内カード・ページ hero | 地域や記事ごとに内容に即した図案を選ぶ。見出し・数値・出典は DOM テキストまたは決定的 renderer で描き、装飾画像に焼き込まない。 |
| OGP・note 表紙・X・Instagram | 一つの問いまたは発見を主題にし、記号・発行元名・藍系の色・文字階層を反復する。媒体ごとの比率と安全域に合わせて再構成し、同一画像の無理な切り抜きで済ませない。 |
| データ地図・チャート | データ、地域名、凡例、単位、期間、出典を保つ。強弱・カテゴリの色は意味を優先し、装飾の地図風図案と明確に区別する。 |

公開資産の切替は、正式記号、favicon、サイトヘッダー、代表的な OGP・note・X・Instagram の実寸試作を一組として見比べた後に行う。現行の favicon（47文字）、ヘッダーの棒グラフ、SNS の円形アイコンは形が異なるため、切替時に同じ版で揃える。画像の詳細な制作・検査契約は `.claude/rules/ogp-image-standards.md` を参照する。

統合用の画像試作 v1 とファイル一覧は `apps/web/public/brand/atlas-v1/manifest.json` に置く。公開 UI への参照変更と SNS プロフィール画像の更新は、この素材群を確認してから媒体ごとに行う。

## レイアウト

### 骨組み (サイドバー型)

骨組みはテンプレートのサイドバー型 (2026-10-27 オーナー決定)。寸法と DOM はコードが正典 (`apps/web/src/app/layout.tsx`・`components/organisms/{AppSidebar,SiteHeader,Footer}`)。

- ルートの `SidebarProvider` の中に `AppSidebar` (variant="inset") と `SidebarInset` を兄弟で置き、`SidebarInset` に `SiteHeader`・ページで唯一の `main#main-content` (p-4)・`Footer`・Cookie 同意の帯を並べる。lg (1024px) 未満のサイドバーは Sheet。サイドバー部品は Server Component から `AppSidebar/sidebar-shell.tsx` (1 つの client モジュール) 経由で import する。
- サイドバーのヘッダーはテンプレートの full-logo と同じ 2 段 (ロゴ + 名前 + 副題)。主要ナビは常に展開し、カテゴリとテーマのグループは既定で開く。テーマは navigation-only SSOT `THEME_NAV_GROUPS` の 5 系統を開閉できる項目 (テンプレートの nav-collapse) に分ける。項目はすべてアイコン付き、行の高さはテンプレートと同じ 1 行 40px。下端 (SidebarFooter) に一覧への出口 (すべてのテーマ) を置く。/ranking への出口は主要ナビの「ランキング」と重なるので置かない。
- ヘッダーは開閉ボタン・検索欄 (テンプレートと同じ text-sm)・右端のアイコンボタン群 (一覧への出口・配色の切り替え)。フッターは主要な入口数個・サイトの案内・著作表記の 1 段で、導線の一覧を持たない。
- Cookie 同意は `SidebarInset` の最後に置く `sticky bottom-0` の 1 行の帯。浮きカードにしない (本文・地図とテーブルのタブを覆うため)。トースト (sonner) は使わない。
- 部品の lyra スタイルは CSS として読まない。正本 `style-lyra.css` の `cn-*` 規則の中身を部品の className に書き込む (`npm run ui-theme:lyra`、`npm run ui-theme:lyra:test` が pre-commit と PR CI で書き込み漏れを検査。2026-10-28)。同じ見た目をユーティリティと lyra の規則の 2 通りで CSS に出さないため。lyra の値は呼び出し側の className より後ろで合成されて勝つ (CSS で読んでいたときと同じ。上書きは `!`)。

### LeftRailLayout (ページ内ナビ)

ページ内ナビ (旧 左レール) の置き場は `LeftRailLayout` を唯一の実装契約とし、`PageShell` と `ArticleShell` が共有する。

- ページ内ナビは列を作らず、どの幅でも本文の上の 1 か所に出す (2026-10-28。サイト全体のナビはサイドバーが持つので、サイドバーの右にもう 1 本の列を作らない)。幅で隠す分岐や、常に隠す代替 UI は持たない。
- パンくずとページ見出し (h1) は Shell の `header` (ArticleShell は `breadcrumb` と `header`) に渡し、ページ内ナビより先に出す (`check-design-system.mjs` の `left-rail-requires-header-first`)。
- 本文の列は `div[data-slot=shell-main]` で描く。ページで唯一の `<main>` はルートレイアウトの `main#main-content` が持ち、Shell や page は `<main>` を入れ子にしない（`check-design-system.mjs` の `no-nested-main-landmark`）。
- feature はナビの内容だけを所有し、grid、breakpoint、sticky を再定義しない。
- 機械監査は `check-design-system.mjs`、振る舞いは layout contract tests が固定する。

### PageShell

通常の一覧、検索、ダッシュボードは `PageShell` を使う。

- 横幅とレール境界のコンテナは `SHELL_CONTAINER_CLASS`（`@container/shell` + 1280px）が正典。余白はルートレイアウトの `main#main-content` の `p-4`（テンプレートと同じ 16px）に任せ、Shell 自身は余白を持たない。main の外にある chrome（Footer）は `SHELL_WIDTH_CLASS`（1280px。横の余白は持たない）に自分で `px-4` を足して同じ幅と余白に揃える。
- 右レールは `@min-[988px]/shell`（本文 656px + gap 16px + 316px）で右列に出す。`rightRailBreakpoint` は廃止し、全ページ同じ境界にした。
- `rightRail` は関連情報を主役にし、広告はその後に置く。広告・販促だけの rail で本文を狭めない。
- `leftRail` はそのページの探索・切替に限る。site 全体 nav を複製しない。Theme はグループ別テーマリンク・地域・全指標・出典調査、home / ranking / category はカテゴリ探索に使う。テーマグループは navigation-only SSOT とし、ranking category / ThemeCatalog taxonomy とは分離する。
- `leftRail` と `rightRail` は併用できない。両方渡した場合は右だけを描画する。
- `leftRail` は共有 `LeftRailLayout` を使い、`header` (パンくず + h1) の後・本文の上にどの幅でも出す。
- 右 rail は狭い画面で本文下へ積み、内容を消さない。
- `variant="reading"` は単純な読み物に限る。記事系の標準は `ArticleShell`。
- page 内で独自の `container mx-auto` や別の全体 `max-width` を作らない。

### ArticleShell

blog、ranking detail、survey、規約等の読むページは `ArticleShell` を使う。

- 本文と rail を同じ reading zone に置く。
- rail はページと一緒に流れる。追従する領域や独立した縦 scroll (`max-height` / `overflow-y`) を作らず、ページ本体の scroll だけで全 widget に到達できる自然フローとする。
- 右 rail は 1 回だけ描く。shell コンテナ 988px 未満は本文の後に積み、988px 以上は同じ要素を本文の右の列に置く (2 か所に描いて広告の計測画像・リンクを HTML に二重に出さない)。
- 見出し (h1 と操作の行) を `header` に渡すと、右 rail の先頭が本文の最初のカードと上端を揃える。
- ページ探索用の `leftRail` は `LeftRailLayout` の契約どおり本文の上に置く。左右を同時指定した場合は右 rail を優先する。
- survey の左 rail は「調査一覧・このページ・代表ランキング・関連する分類」に限定する。
  site 全体 nav や全ランキングを常時展開せず、調査の出典ハブとして読む順序を補助する。
- survey の狭幅のナビにも `/survey` の「調査一覧へ」を残し、上位ハブへの出口を失わない。

### PageHeader

標準ページ見出しは `PageHeader` を使う。

- `h1` はページに一つ置き、DOM 上でも主要コンテンツより先にする。
- `description`、`meta`、`stats` は役割を混ぜない。
- `description` はタイトルから推測できない対象範囲・定義・使い方だけを書く。画面を見れば分かる操作説明や、直下の chart と同じ説明は省略する。
- 操作は `actions` / `controls`、補助表示は `aside` slot を使う。
- header 本体を暗色 gradient や巨大 KPI 面にしない。
- feature 固有 header が必要な場合も、既存 header component を拡張または合成し、新しい hero 系統を増やさない。

## レール UI 契約

左右レールは配置・幅・sticky・responsive 非表示が異なっても、Surface・見出し・リンク行の視覚契約は共通とする。部品は `apps/web/src/components/surface/SurfaceCard.tsx` の `RailCard` / `RailNavRow` / `RailNavRowButton` と `apps/web/src/components/rail/{RailStack,RailCategoryList,RailLinksCard}.tsx` に集約する。

### 左右共通

- レール内の独立したまとまりは `RailCard` 1 枚 = 通常カードと同じ `CARD_SURFACE_CLASS`（角丸・線色はトークン）。見出し `h3` は `text-sm font-medium text-muted-foreground`（`border-b px-4 py-3`）、本文は `px-4 pb-4 pt-3`。折りたたみは `RailCard collapsible`（details/summary、summary `min-h-12`）。
- カード間の縦積みは `RailStack`（`flex flex-col gap-3`）だけを使う。`page.tsx` で `<aside>` を自前で描かない。landmark は `PageShell` / `ArticleShell` / `LeftRailLayout` が持つ。

### リンク行

- リンク行は `RailNavRow`（Link）/ `RailNavRowButton`（`aria-pressed`）。透明背景、`min-h-11 sm:min-h-9`（compact）/ `min-h-11 sm:min-h-10`（default）、`hover:bg-accent/50`、`focus-visible:ring-2 ring-inset`、右矢印、件数は `tabular-nums`。
- active は `aria-current="page"` + `bg-accent font-semibold text-primary`。カラーバー（inset shadow / `border-l`）で示さない。
- 末尾リンクは `text-xs font-medium text-primary hover:underline`（モバイル `min-h-11`）。

### 左右で異なってよいもの

配置（ページ内ナビは本文の上・右レールは幅 316px の右列）、responsive の移動、中身（操作ナビ vs 補助情報）は別契約のままでよい。右レールの境界 988px（shell コンテナ幅）と、視覚言語が共通であることは別の話。

### カテゴリ導線

- カテゴリ導線の正は `RailCategoryList`（`@/components/rail`）。単列・区切り線付き、件数は「ランキング数」で固定（sr-only「のランキング」）。枠は持たず `<RailCard title="カテゴリから探す">` で包む。
- props は意味ベース（`items` 必須 / `showCount` / `activeCategoryKey` / `density` / `trackingSurface` 必須 / `moreLink`）。`variant="home"` 等のページ名 variant は禁止。
- `/` `/ranking` `/category/*` `/areas/*` `/blog` `/blog/*` `/survey/*` が同じ部品を使う。旧 `PortalCategoryGrid` と `RailLinksCard layout="grid"` は廃止。

### タグ

`RailLinksCard layout="chips"` はピル 1 種（`rounded-full`、`min-h-11 sm:min-h-7`、`border-muted-foreground/40 bg-muted`）。タグ専用でカテゴリ一覧へ流用しない。`rounded-full` はタグ・バッジ・ピルのみ。`RailLinksCard.trackingSurface` は必須。

## 見本の実測値と部品の仕様 (2026-10-28)

公開サイトは見本 [demos.shadcndashboard.dev](https://demos.shadcndashboard.dev/) に寄せる (2026-10-27 オーナー決定「テンプレートを正としてサイトを寄せる」)。参考サイトの URL・採否と理由・撮影・反映先は台帳 `data/design-references/references.json` (管理画面「サイト > 参考サイト」) が持つ。新しい参考サイトはここに足してから設計に使う。
仕様は**画面の種類ではなく部品の種類ごと**に決める。1 つの部品を見本に合わせると、その部品を使うすべての画面に効き、検査も部品ごとに 1 つで済む。

- **正は見本サイトの値。** 写したテンプレートのソース (`next-shadcn-dashboard@91deb102` の lyra) は、パネルの文字が 12px (`text-xs`)・ボタンが角 0 で、見本サイト (14px・角丸 8px) と違う。食い違ったら見本サイトに合わせる。
- **撮影と実測値の保存先:** `assets/design-reference/shadcndashboard/2026-10-28/` (見本 12 画面 × 1440・390px の撮影と、部品 (`data-slot`) ごとの計算後スタイル)。同じ方法で測った stats47 の起点は `assets/design-reference/stats47-baseline/2026-10-28/`。
- **測り直し:** `node scripts/ui-theme/measure-design-reference.mjs <出力先> --measure [基準 URL] [画面一覧.json]` で撮影と実測、`node scripts/ui-theme/compare-design-slots.mjs <見本の実測> <stats47 の実測> 1440` で部品ごとに並べる。
- **読み物も同じ部品で組む:** ブログ本文・AI の解説・FAQ も、見出し・余白・線は下の表の部品を使う。読みやすさのために変えてよいのは、本文の文字の大きさと行の高さ (下表「記事本文」) だけ。

## Surface

共有 surface は `SurfaceCard`、`SurfaceSection`、`SurfaceLinkCard` と primitive `Card` を基底にする。

- Surface は 3 段階で管理する: ページ `bg-background` / カード `bg-card` / hover・選択中・補助要素（タグピル・バッジ・サムネ地）だけ `bg-muted` または `bg-accent`。
- 通常の行・リンク群に理由なく `bg-muted` を使わない（詳細は「レール UI 契約」）。
- カード外枠の単一定義は `CARD_SURFACE_CLASS`（`packages/components/src/atoms/ui/card.tsx`）。primitive `Card` と `SurfaceCard` / `SurfaceSection` / `SurfaceLinkCard` / `RailCard` / `ArticleCard` はすべてこれを合成し、外枠クラスを別に書かない。
- 外枠の見た目はアプリごとのトークンで決める: 角丸 `--card-radius`（`rounded-card`）、線色 `--card-outline`（`border-card-outline`）。Web は角丸 0・線 `--border` (テンプレートの lyra カードと同じ白地・細い線・影なし。2026-10-27 に 2026-09-25 の「線なし・薄グレー地」から変更)。ページ地 (`--background`) もテンプレートの白で、記事ゾーンを含めサイト全体で 1 値。管理画面は `--card-outline: hsl(var(--border))` で線ありの角丸カード。border 幅は残るので、レイアウトと interactive card の hover 枠色 (`hover:border-primary/40`) が保たれる。表・グリッド・入力欄・ボタンの線は残す。
- 角丸はクラスを役割で選び、値はトークンで決める: カード外枠・その仮表示・地図/チャート枠は `rounded-card`、ボタン・ドロップダウンは `rounded-md`、カード内の小タイル・バッジ・サムネは `rounded-sm`（`--radius`。値はテンプレートの 0.625rem。部品自体の角は lyra スタイルがほぼ `rounded-none` で決める）。形として四角であるべきもの（凡例の色見本、タイル地図のマス、下線タブ、一覧行）だけ `rounded-none`、円形 icon・avatar・pill だけ `rounded-full`。`cn` は `rounded-card` / `rounded-content` を角丸として解決する（`packages/components/src/lib/cn.ts`）。
- **本文の中に置く部品は `rounded-content`（`--content-radius`、Web は 6px。2026-09-25 採択）**。ページを区切るカード外枠（レイアウト）と、記事本文の中に置くまとまり（callout・本文内のランキングカード・コードブロック）は役割が別なので、別トークンにする。レイアウトはフラットのまま、本文内の部品だけ少し丸めて「本文の一部」と分かるようにする。本文内の部品は白いカードを重ねず（カード内カード禁止）、地の色で区切る。
  - `--content-radius` は `:root` に 1 か所だけ定義する（ページ種別ごとに上書きしない）。
  - `rounded-content` を使えるのは本文を描く部品のファイルだけで、そのファイルでは `rounded-card` / `rounded-lg` を使わない。対象ファイルの一覧は `check-design-system.mjs` の `ARTICLE_BODY_COMPONENT_FILES`。本文内に部品を足したらこの一覧へ足す。
  - callout（`> [!NOTE]` 等）はアイコン + 日本語ラベル（補足 / 読み解きのポイント / 注意 / 重要 / 要注意）の 1 行と本文で組み、左の色バーは使わない。種類ごとのラベル・色・優先度の単一定義は `apps/web/src/features/blog/components/callout-config.ts`、表示は `Callout.tsx`。
- clickable card は card 全体の click target、focus-visible、hover を一致させる。
- 色付きの順位チップ（「N位」）は `RankBadge`（`apps/web/src/components/atoms/RankBadge.tsx`）で描く。幅は固定せず最小幅 4em で揃え、折り返さない。色は意味の `tone`（`positive` / `negative`、向きのない順位は `rankToneByPosition`）。表のセル・補足の文字・文章中の「N位」は文字のまま書く。機械ゲートは `design-system:check` の `rank-chip-must-use-rank-badge`。
- portal card の縦横比は `PORTAL_CARD_ASPECT_CLASS` を使う。
- feature 内で border / shadow / padding をまとめた独自 card shell を複製しない。
- card / section surface の内側に別の card surface を置かない。まとまりが必要なら外側を通常の `section`、内側を区切り線付き list / table にする。

### 色

- `background` / `foreground` / `muted` / `border` / `primary` 等の semantic token を使う。
- データの状態は状態トークンで表す: `positive`（上位・良い値）/ `negative`（下位・悪い値）/ `warning`（注意）/ `info`（補足）。各 `DEFAULT` は文字・線、`-soft` は淡い地。light/dark の値は `globals.css` だけが持つ。
- category や chart series の色は意味の識別に使い、装飾的なカラーバーを増やさない。カテゴリ・地域・性別・メダル・SNS ブランドなど識別のための配色は `*.palette.ts` モジュールに集め、そこだけで Tailwind の生パレット色を使う。
- 生パレット色（`slate-500` / `emerald-600` 等）を UI に直書きしない。`npm run design-system:check -w apps/web` の `no-raw-palette-color` が apps/web と packages/components・packages/visualization を検査する。`black` も使わない。
- positive / negative の色だけで意味を伝えず、label、symbol、値を併用する。

### カラーモード（light / dark）

- 既定は light。dark は利用者が明示的に選ぶ opt-in とし、OS 設定へ自動追従しない。
- 選択状態は `next-themes` が保持する。実装の正典は `apps/web/src/providers/theme-provider.tsx`。
- component は両 mode の semantic token と contrast を確認する。
- mode 別画像が必要な場合は `ThemeAwareImage` 等の既存 component を使い、同じ画像を二重表示しない。

### Typography

- 本文は system font stack を使い、Web font を表示の必須依存にしない。
- 通常ページの `h1` は既存 `PageHeader` の scale に合わせる。
- `h2` / `h3` は見た目ではなく文書構造で選ぶ。
- 数値表では桁、単位、小数点の比較しやすさを優先する。
- `tracking-tight` 等、日本語の可読性を落とす指定を避ける。

## Component の三層

| tier              | 配置                                          | 例                                | ルール                                        |
| ----------------- | --------------------------------------------- | --------------------------------- | --------------------------------------------- |
| Primitive         | `packages/components/src/`                    | Button、Card、Select、Table       | 先に既存 primitive を探す                     |
| Shared composite  | `apps/web/src/components/`                    | PageShell、SurfaceCard、StatTile | 複数 feature で使う UI                        |
| Feature component | `apps/web/src/features/<feature>/components/` | ranking header、theme section     | feature 固有。別 feature から直 import しない |

同じ UI が二つ以上の feature で必要になったら shared composite への昇格を検討する。将来使うかもしれないという理由だけで抽象化しない。

### 本文コンテンツの開閉 UI

- FAQ は共有 `FaqSection`、統計の定義・AI考察など単一本文は共有 `ContentDisclosure`（`apps/web/src/components/content/`）を使う。feature ごとに Accordion や三角文字を再実装しない。
- 操作は native `details/summary` を基底とし、閉じた本文も SSR DOM に保持する。見出し・質問・本文は 14px（見出しは semibold、質問・本文は normal）、操作高 44px 以上、状態表示は 12px の細線 + / − に統一する。
- hover / tooltip は補助説明に限り、開閉や主要導線を hover のみに依存させない。ナビゲーション用の `details` は本文開閉と責務が異なるため、この部品へ無理に統合しない。

## ページ別の契約

### Home

- 白基調のポータルとして、主要な探索入口を短く提示する。
- 暗色の巨大 hero を既定へ戻さない。
- category、ranking、area、blog の優先順位は `apps/web/src/features/home-portal/README.md` に従う。

### Ranking

- ranking detail は既存の `RankingHeader/` 系を使う。
- `h1`、操作、統計、地図、table の順序は mobile / desktop の利用目的を踏まえて既存 feature contract に揃える。
- mobile では主要可視化へ早く到達できるようにする一方、`h1` は DOM 先頭を維持する。
- 一位だけを巨大な暗色 KPI 面で特別扱いせず、上位、最下位、全国値を通常 surface で比較できるようにする。

### Theme / Area

- Theme は複数指標の意味的な順序、Area は一地域の特徴を主語にする。
- chart の配置は [`03_情報設計.md`](./03_情報設計.md) と ThemeCatalog / page_components の定義に従う。
- Theme の左 rail はグループ別テーマリンク、地域、全指標、出典調査をこの順で整理する。テーマと出典調査には `/themes`・`/survey` の上位ハブリンクを1件ずつ置く。現在テーマのグループだけ初期展開し、現在リンクを明示する。
- 地域では「比較単位（47都道府県 / 市区町村 / 日本）」と「表示する都道府県」を別の操作として示す。比較単位は共有 `StatisticsScopeNav` の rail variant、都道府県は `PrefectureSelect` を使い、リンクや状態定義を複製しない。
- 狭幅では左 rail を隠し、共有 `StatisticsScopeNav` の横タブ・テーマ Select・地域・ページ内クイックリンク・全指標・出典調査を本文上部へ置く。同じ操作を同時表示しない。
- Theme / Japan / Municipality の地理スコープ切替には共有 `StatisticsScopeNav` を使う。
- 関連情報が無い dashboard / hub は全幅とし、広告だけの right rail を作らない。

#### 選択 UI と集合レイアウトの件数規則

- 選択 UI（checkbox・tab・選択タイル・`ScrollableRow`）は、フィルタ後に有効な選択肢が 2 件以上あるときだけ表示する。0 件はセクションごと非表示、1 件は選択 UI を出さず指標名・値・単位・年次・順位・ランキング導線を直接並べる。外せない checked 状態や、カード見出しと唯一の選択肢ラベルの重複を作らない。
- 集合レイアウト（指標カードの grid）は 0 件で wrapper を描かず、1 件でも複数列 grid wrapper を作らない。2 件以上のときだけ container query の grid（`grid grid-cols-1 gap-4 @md:grid-cols-2`）で包む。desktop の compact card は複数あるときだけ 2 列、mobile は常に 1 列。詳細チャート・複数指標切替パネル・固定年比較は全幅を維持する。
- 単一指標の推移は、都道府県選択時に異なる年が 2 件以上あるときだけ小さな折れ線（`MiniLineChart`、84px）を描く。単年は自然高の 1 行テキストにし、空の折れ線枠・ローディング風の大面積・「時系列データがありません」だけの固定高領域を置かない。
- 時系列データの取得は指標 1 件分の遅延取得（自地域 + 全国）を再利用し、47 都道府県一覧表示のための一括取得へ戻さない。

### Blog / Survey / 規約

- `ArticleShell` と reading zone を使う。
- 本文、出典、図表、CTA、rail の優先度を分ける。
- 記事 card 内へ別の大きな card shell を重ねない。

## Chart と table

- 新規 chart の前に既存 catalog を確認する。
- title、unit、period、source、legend を chart 単体でも理解できるようにする。
- title・凡例・軸から自明な reader description を自動生成しない。Theme chart header は短い title に絞る。
- 系列断絶、母集団差、比較不能条件など chart 固有の誤読防止条件だけを近接 footer の `annotation` に置く。
- 指標の定義・算出方法・一般注釈は `/ranking/[key]` の指標ハブへ集約し、chart からリンクする。
- 指標の選定理由や内部 provenance は reader UI と混ぜず、SSOT に保持する。
- loading、empty、partial、error を同じ表示にしない。
- color scale と axis は指標間で意味が変わる場合に使い回さない。
- table は header scope、数値 alignment、mobile overflow、sort state を確認する。
- visualization を decoration として置かず、ページの問いへ答えるものだけを置く。

## データ出典

| 層 | 部品 | 役割 |
|---|---|---|
| ページ全体の出典 | `DataSourceList` (`apps/web/src/components/molecules/DataSourceList.tsx`) | ページ末尾の「データ出典」。ブログ記事・ランキング・市区町村ランキング・Geo レイヤー |
| 図ごとの出典 | `ChartFooter` | 図の直下の短い出典リンク。テーマ・エリア・stat-charts |
| 調査ハブへの回遊 | `SurveyTaxonomyCard` | 右レール等の「この記事の出典調査」。出典の表記ではなく導線 |

- 1 行は「調査名 (サイト内の `/survey/<id>` へ)・(機関)・[統計表 ↗] (e-Stat 等の実データ表)」。
  調査ではないデータセットは名前を外部ページへリンクし、ライセンスがあれば行末に出す。
  地図の行政区域データのような補助データは `note` (例: 「地図データ:」) を付けて同じ一覧に並べる。
- 行はデータ (`DataSourceEntry`) から派生させる。ブログは図の `source.json`、ランキングは `item.json` の
  `sourceConfig` と `attribution` が入力で、解決は `@stats47/ranking` の `resolve*DataSources` だけが行う。
  画面側で出典の文字列や e-Stat の URL を組み立てない (`buildEstatTableUrl` だけが URL を作る)。
- ブログ本文に手書きの「データ出典」節を書かない。計算方法や定義の説明は「データについて」節に書く。
- 機械ゲート: `apps/web/src/__tests__/data-source-contract.test.ts` (「データ出典」見出しは `DataSourceList` だけ・
  e-Stat URL の直書き禁止・旧 `item.source` 参照禁止)、`quality-gate.mjs` (記事の手書き節を blocker)、
  週次のタクソノミー監査 (手書き節・出典 0 件・未焼き込みの件数)、ページ品質監査
  (`duplicate_data_source_sections`)。

## 外部リンク

外部サイトへのリンクは新しいタブで開く (2026-09-25)。読者が出典や原典を確かめたあと、元のページへ戻れるようにするため。

- コードでは `ExternalAnchor` (`apps/web/src/components/atoms/ExternalAnchor.tsx`) を使う。`target="_blank"` と
  `rel="noopener noreferrer"` を必ず付け、`sponsored` などの用途別の値だけを追加で渡す。サイト内のページは `next/link` の `Link` を使う。
- 記事本文 (markdown) のリンクは `md-content` が外部 URL に自動で付ける。記事側で個別に書かない。
- 例外はサイト内を指すもの (ページ内アンカー・サイト内 API のダウンロード・転送用の中継ページ) だけで、
  契約テストの許可リストに理由付きで載せる。
- 機械ゲート: `apps/web/src/__tests__/external-link-contract.test.ts` (手書きの外部 `<a>`・変数 URL の同タブ・
  `noopener` 欠落を PR とコミットで止める)、週次のページ品質監査 `external_links_same_tab` (サイトマップ全 URL の
  描画後 HTML で数える。違反は UI 指摘キューからカード化され、既存の backlog ループが直す)。

## 禁止事項

- ページごとの独自 outer container。
- page 内での rail 列幅の直書きと、広告だけの `RightRailWidgets`。
- feature ごとの独自 Card / Button / Table 基底。
- 通常ページへの巨大 gradient hero、暗色 KPI panel、過剰な shadow。
- 装飾だけの色帯、色だけに依存した状態表現。
- `h1` より前に主要コンテンツを DOM 配置する。
- rail の内容を狭い画面で無条件に非表示にする。
- component query が必要な grid を viewport 幅だけで決める。
- UI の件数、色、寸法を文書とコードの両方で個別管理する。
- 選択肢が 1 件しかないセレクタ（checkbox・tab・選択タイル）を置く。
- 時系列が 2 時点未満なのに空の固定高チャート枠・ローディング風の枠を置く。
- `page.tsx` で `<aside>` を自前で描く。
- 選択肢のカードに理由なく `bg-muted`。
- カテゴリ導線の独自 grid・独自行。
- ページ名依存の variant（`variant="home"` 等）。

## UI 変更時の確認

1. 既存 primitive / shared component で実現できないか。
2. PageShell / ArticleShell / PageHeader のどれに従うか。
3. mobile の DOM 順、keyboard、focus、contrast が成立するか。
4. loading、empty、error、long text、最大値で崩れないか。
5. chart と page_components の既存契約を再利用したか。
6. 変更前後を同じ viewport で目視し、意図しない UI 差分がないか。
7. UI 変更でない作業では class、DOM、asset を変更しない。
