## 評価サマリ

Claude Code 実例集 Part 9（レーダーチャート × 複数指標正規化）のチュートリアル記事。取得 → min-max 正規化（低い方が良い指標の反転）→ D3 極座標描画 → 2 県オーバーレイ → 数値併記 → つまずきポイントまで、対象ペルソナ（Claude Code 未経験エンジニア）に対して密度の高い実用ノウハウを一貫した ですます調で提供できており、水増しや図表重複は無い。curiosity gap（タイトルの「多角的に / 正規化を頼む」）は本文で確実に回収され、内部リンク 8 本はすべて本番 200 で実在する。最大の弱点は、**「チャートの作り方」を解説する記事でありながら完成チャート（レーダー SVG）を 1 枚も載せていない**こと。同シリーズの兄弟記事（Part 6/7/8）はいずれもチュートリアルでありながら実データ由来の SSOT 付き SVG を本文に埋め込んでおり、Part 9 だけ `data/` ディレクトリが空でビジュアル成果物がゼロという series 不整合がある。

## 指摘

- [MAJOR] **完成レーダー SVG が 0 枚（`data/` 空）。視覚化チュートリアルに視覚化が無い。** 兄弟記事 06（散布図 `income-education-scatter.svg`）・07（時系列 + ランキング 2 枚）・08（出荷額ランキング SVG）はすべて `.source.json` 系譜付きの**実データ SVG** を本文に持つ。本記事は radar の作り方を 5 ステップで説明しながら、読者が最も見たい「で、その radar はどう見えるのか」を一度も提示しない。修正案: 最終成果である東京 vs 京都の 2 県オーバーレイ radar を 1 枚 SVG 化して Step 4 直下に埋め込む。データは架空例でなく、本文が既にリンクしている実在 ranking（`japanese-population` / `criminal-recognition-count` / `per-capita-education-expenditure-pref-municipal` 等）の確定値で正規化して描けば、Part 7 と同じ「教育チャート + 実データ」の型に揃い、series 一貫性と読者価値の両方が回復する。

- [MINOR] **記事全体が架空（例）数値に依存。** statsDataId・生値・正規化値がすべて 架空例で、[!NOTE] と「データ出典」で誠実に開示している点は評価できる（読者の誤読を防ぐ良い callout）。ただし少なくとも最終 radar 1 枚は実データで描くことで、「作り方を学んだ手を動かす前に、本物の到達点を見せる」効果が出る。MAJOR の修正で同時に解消可能。

- [MINOR] **「方法 B / 方法 C」の数値併記が文章説明のみで図がない。** 軸ラベル併記・頂点ラベル・ホバーツールチップの 3 方式は有用だが、方法 A の完成形を 1 枚見せると「静止画だからラベルに数値を載せる」という設計判断が一目で伝わる。MAJOR の SVG に方法 A（軸ラベルに min〜max 併記）を適用すれば例示とセクションが連動する。

## 判定理由

意味的品質（curiosity gap の真正性・解釈の厚み・callout の情報量・文体一貫性・内部リンク妥当性）はいずれも基準を満たし、文章としては公開に値する完成度。しかし「視覚化の作り方」というテーマの記事が完成ビジュアルを 1 枚も持たず、同シリーズの全兄弟記事が満たしている「実データ SVG を本文に置く」型から外れている点は、読者価値・series 一貫性の両面で看過できない MAJOR ギャップ。BLOCK ではない（文章単体で論理破綻はなく、致命的な誤情報・図表重複も無い）が、最終 radar を実データ SVG で 1 枚追加するまでは PASS にできない。article-writer 側で SVG を 1 枚追加・埋め込み後、再 review で PASS に更新する。
