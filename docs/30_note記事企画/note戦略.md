# note 戦略（note.com）

> 更新: 2026-10-16
> **このファイルは note の戦略の SSOT**。記事メタ（vertical/series/**magazine**/有料無料/送客先/公開URL）の機械的な
> 真実源は **`data/note/articles.json`**。本文・図版の正本はR2（正典: `.claude/scripts/note/catalog/README.md`）。
> 各記事の状態・公開数はカタログとダッシュボード（`data/note/dashboard/`）を見る。収益上の位置づけは
> [収益化戦略](../00_プロジェクト管理/02_収益化戦略.md) §3.3・§3.5。管理者: note-manager agent。

## 全体戦略

### 役割と、有料・無料の線引き（2026-10-07 オーナー決定）

note は **無料が基本**。ランキング・読み物・調査ガイド・分析（A/B/C/D シリーズ）は無料で公開し、認知の獲得と
stats47.jp への送客に使う。**有料にするのはノウハウ商品だけ**（AI×公的統計の実務。`KNOWHOW-PRODUCT-PILOT-01`）。

- 根拠: ランキング型の有料記事 47 本は通算（〜2026-09-11）売上 ¥0。通算売上 ¥900 は Claude Code の実務記事 3 件（2026-05〜07）。
- 既存の雑学・ランキングの有料記事の無料化と、その前後の計測は `NOTE-FREE-DEFAULT-01`。
- メンバーシップ（定期購読）は作らない。旧計画 `membership-strategy.md` と `membership-articles/` の下書きは 2026-10-07 に
  削除した（`git log --diff-filter=D -- docs/30_note記事企画/` で復元できる）。

### ファネル構造

```
無料記事（A/B/C/D）
  Google 検索・note のレコメンド・マガジンで流入
  → 同テーマの「次の1本」・マガジンで回遊
  → 記事内の stats47.jp の素 URL で送客 → ランキング・地図・比較（収益は広告・物販 = 収益化戦略 §3.5 の経路 a）

ノウハウ記事・マガジン（有料）
  note の検索・レコメンドと、実務記事の無料部分から流入 → 購入（経路 b）
```

2026-07-18 以降は「すべての記事から直接 stats47 へ送る」一辺倒ではなく、読者の意図により主 CTA を分ける。

| 記事の役割 | 主 CTA | 副 CTA | 成功条件 |
|---|---|---|---|
| 検索・レコメンド入口 | 同テーマの「次の1本」 | マガジン | 2記事目へ移る |
| シリーズの無料ハブ | マガジンの全体案内 | 有料の次ステップ1本 | マガジン詳細に到達する |
| 実務手順・連載中盤 | 直前または次の必要記事 | マガジン | 手順を継続する |
| stats47 データの活用意図が強い記事 | 対応する ranking / area / blog | 関連 note 1本 | stats47 の対応ページに到達する |

記事末に同等の選択肢を並べない。主 CTA は1つ、副 CTA は最大2つとし、「次に何が得られるか」をリンク直前に書く。

### コンテンツ棲み分けルール

stats47.jp と note で**同じテーマを扱ってもよい**。それぞれの強みで差別化する。

| | note（A シリーズ） | note（B/C/D シリーズ） | stats47.jp |
|---|---|---|---|
| **内容** | ランキング要約 + 簡単な考察 | ストーリー・考察・調査ガイド | 全47都道府県データ + インタラクティブ |
| **文字数** | 800〜1,200字 | 1,500〜5,000字 | — |
| **CTA** | 「全県版は stats47 で →」 | 「詳細データは stats47 で →」 | 本体 |
| **制作** | `/post-note-ranking` で生成 | 5 ステップのスキル連携 (下記) | — |

> **canonical URL**: note.com ではcanonicalタグを自由に設定できないため、noteの記事は「独立コンテンツ」として設計する。

### 投稿ルール

- stats47.jp へのリンクは `.claude/rules/sns-content-standards.md` に従い、**素 URL を本文中2〜4箇所**に置く。UTM は付けない
- 公開時のハッシュタグは **95〜99個**（既定99個）。`note:circulation:audit` で全公開記事を検査する
- 記事末は全記事共通の固定文にせず、記事役割ごとの主 CTA 1つ + 副 CTA 最大2つにする
- シリーズ記事は「前へ/次へ」を機械的に出さず、読者の次の仕事に必要な1本を `nextBestArticle` として選ぶ
- マガジンは「記事の保管場所」ではなく、悩み別の読書順を示す無料ハブとして編集する
- 実記事が3本未満のマガジンは「薄い」と判定し、47都道府県値・公開中ランキング・重複なしを満たすサイト指標からAシリーズを補充して3本以上にする
- A シリーズは `/post-note-ranking` スキルで自動生成
- B/C/D シリーズは `/validate-note-idea` → `/investigate-note-data` → `/design-note-structure` → `/write-note-section` → `/edit-note-draft` のフローで作成

### KPI

記事数やビューだけで判定しない。

| 指標 | 取得元 | 使い方 |
|---|---|---|
| note → stats47 参照セッション | GA4 `sessionSource = note.com` × 着地ページ（Japan・28 日） | 無料記事の主指標。2026-08-09〜09-05 は 502 セッション・2,437 PV・エンゲージ率 74% |
| ノウハウの有料記事・マガジンの購入 | note ダッシュボードの売上（`data/note/dashboard/`）と販売台帳 | 有料の主指標（KPI ツリーの `paid-purchases`） |
| 次の候補記事のPV | note ダッシュボード | 回遊の参考値。前記事からの遷移件数やマガジン到達数とは扱わない |

UTM は付けず、着地ページごとの送客を見る。同じURLへ複数のnote記事がリンクする場合、
GA4の着地ページだけでは送信元の記事やカードを特定できない。

### 本文品質の改善方針

カバーの残りを一巡する前に、閲覧の多い記事と異なる図の型で本文品質を試すことを推奨する。
狙いは、開いた読者が拡大せず結論と根拠を読み、必要な次のページへ進めること。
対象・順番・公開境界は `NOTE-ARTICLE-QUALITY-PILOT-01`、調査値は
[`本文品質の調査記録`](../../data/note/evidence/note-article-quality-audit-20261016.json)を参照する。
カバーの未着手分は `NOTE-COVER-IMAGEGEN-ROLLOUT-01` の計画を保持する。

#### 読者の困りごとと導入

- ランキング・読み物は、冒頭で問いと短い答えを伝え、対象年・地域粒度・何を比較するかを続ける。
  「こんな人」「わかること」を全記事に二重に挿入せず、短い記事は1〜2文にまとめる。
- 手順・調査ガイド・再現パックは「対象読者 → 読後にできること → 必要な前提 → 最初の操作」を明確にする。
  長い著者紹介、宣伝カード、目次で最初の答えが押し下がらないかをスマホで確認する。
- doboku-noteから取り入れるのは、資格・作業段階と成果物を結ぶ設計。販売実績があっても、
  導入見出しや画像単独の効果は証明されていない。資格受験と統計の読み物の需要を同一視しない。
- 家計・所得など生活の判断支援はMoney、自治体実務の手順はAmbitionに接続しうる。
  雑学として読む記事は無理にHARMへ分類せず、実際の利用場面を確かめる。
  無料記事は理解と送客、有料ノウハウは再現・加工に要する時間の削減を価値とし、画像数を課金理由にしない。

#### 図の型とスマホでの役割

最初の試作では390px幅のブラウザ（本文約343px）で主ラベル・数値が15px程度以上になることを目標にし、
320px幅でも結論・軸・単位が読めるか目視する。この値は試作の受入目安で、既存の機械ゲート実装済みという意味ではない。
高解像度化だけで済ませず、1枚の情報量と縮小後の文字寸法を変える。

| 図の型 | 初回の改善案 | 確認する意味 |
|---|---|---|
| 上位・下位 | 左右2列を上下または別画像へ分割。順位・県名・値を大きくし、比較軸・棒の尺度を統一 | 上下を別尺度で誇張しない。同値順位・全国基準を保持 |
| 散布図・相関 | 軸名・単位・凡例を大きくし、注目県だけ直接ラベル。問いに必要なら図を分ける | 対象年・件数・欠測・集計単位を確認。相関を因果の証明にしない |
| コロプレス地図 | 地図を主役にし、数値の列挙は図外へ。凡例と階級境界を読める大きさにする | 元の値か偏差値かを明示。境界・色・欠測・離島・極端値の扱いを照合 |
| 家計・多項目比較 | まず十大費目などの全体像、次に特徴のある少数品目。密な一覧は詳細リンクへ | 対象市と県、世帯区分、月額/年額、47市単純平均と公表全国平均を区別 |
| 操作手順・データ見本 | 全画面の縮小から、操作部分の拡大＋手順番号へ。CSV画像だけでなく結果の見本も検討 | 実際に使う画面・データ版と一致。必要な文脈・注意点を切り落とさない |

統計図は観測値と固定した記事データから決定的に描く。カバーの文字込みimagegen方針を統計図へ適用しない。
現行の本文renderer・版管理・保存の正典は[画像契約](../../.claude/rules/note-image-assets.md)。
試作で分割枚数や寸法を変える場合はrender-specとvalidatorも整合させ、現行の3枚契約を黙って迂回しない。

#### 画像の配置

見出し → 読むポイント1文 → 対応する図 → 観測事実・解釈・限界、の順を基本にする。
各図に「どの問いへ答えるか」を持たせ、同じ上位・下位の図を別見出しで重複掲載しない。
図を増やす場合も文章との対応があるものだけにし、リンクカードが説明と図の間へ割り込まないようにする。
元の図の年・値と自動更新されるリンク先の最新版が異なる場合は、リンク前にその違いを明記する。
配色や尺度を変えた場合は、「赤いほど高い」などの本文の読み方も同じ版へ合わせる。

#### リンクカードと出典の使い分け

2026-10-16に確認した[公式の埋め込み説明](https://www.help-note.com/hc/ja/articles/360019596133)では、
URLの貼り付けとEnter/Returnで一般のWebページをカード化できる。
[文章リンク](https://www.help-note.com/hc/ja/articles/360008882854)と
[画像へのリンク](https://www.help-note.com/hc/ja/articles/360009035593)も利用できる。
note記事・外部記事・画像リンクを区別し、「カードの大小を任意に切り替えられる」とは未確認のため案内しない。

- 次に読む1記事・対応する全県データ・シリーズ入口は、何が得られるか1文＋カードを基本案にする。
  末尾は既存の主CTA1つ・副CTA最大2つを守り、同じリンクや別テーマの商品を重ねない。
- 出典、定義、補足は短い文章リンクにする。出典をすべて大きなカードにして本文を分断しない。
  本文に保存されたembedがあるだけでは成功とせず、公開ブラウザでタイトル・画像・クリック先を確認する。
- 原典の詳細は記事末の「出典・データについて」へ集約し、調査名（原典リンク）・対象年・対象・加工の説明を簡潔に置く。
  指標ごとの原典が違う場合は対応を失わない。再現に必要な表ID・取得日・算式・manifestへの経路も保持する。
  図や本文の近くには年・単位・分母・重要な限界を残し、記事末へすべて追いやらない。
- 「元データを使う」と案内する商品は、対象指標・年・粒度・収録ファイルの一致を確認する。
  同じ大分類に属するだけの別データを、当該記事の元データとして紹介しない。

マガジンは「家計を比較する」「気候と暮らしを知る」「自治体実務でデータを使う」など、
読者の目的を入口に編集する。表紙用の制作カテゴリとマガジンを1対1に強制しない。
既存マガジンの実所属・重複・読書順を確認し、入口1本から必要な次の記事へ案内する。

#### 検証と再発防止

まず少数記事の修正前後を同じ画面幅で比較する。図の寸法・入力SHA・renderer版・値/年/単位の一致・
欠けたリンク・重複画像・CTA件数は機械検査の対象とし、図の意義・読みやすさ・適切な位置・
リンク先との意味の一致は目視レビューする。既存検査を再利用し、未実装の検査を合格済みと扱わない。

公開前には対象記事と画像版・本文差分を固定し、既存下書きの有無を確認する。
画像の操作だけで本文の別の変更を公開しない。本文・図の保存先と旧版の保持は画像契約に従う。

効果を見る前にstats47の最新の完全な期間集計を取り直す。失敗したlatestと最後の正常取得は分けて表示する。
前後14日を基本とし、近いテーマ・流入規模の維持記事も参照する。カバー・タイトル・価格・外部告知を
同時に変える場合は交絡として記録する。複数の本文要素を一緒に直した場合も、個々の要素の効果と断定しない。
note上の記事内クリック・読了が取れない間は、PVや次記事PVをクリック率・読了率へ読み替えない。
カード化のクリック改善は仮説とし、公開表示の修復と効果測定を別に判定する。

### カバーの制作・改善方針

カバーは「誰の、何が、どう違うか」を一覧で伝える。記事の内容で裏付けられる発見を1つに絞り、
クリック後に本文との落差を作らない。画像の生成数は成果指標にしない。

| 記事の型 | カバーの主役 | コピーの原則 |
|---|---|---|
| 県別家計・地域紹介 | 既存の県SVG・地理データ | 地域名 + 支出などの特徴1つ。調査対象都市も明記 |
| 全国ランキング | 日本地図・既存チャート | 何の順位か + 結果や差1つ。出典のない最上級を使わない |
| 背景・読み物 | 主題の図・イラスト | 本文が答える具体的な問い1つ。無理に数字を置かない |
| ガイド・有料商品 | 手順図・成果物の見本 | 読後にできること、または収録物。無料・有料の約束を正確にする |

- 地域差を伝える数字は比較対象を隣に書く。「1.27倍」だけでなく「47都市平均より27％多い」、
  「2.09倍」なら「47都市平均の約2倍」のように主張に合う精度へ丸める。生活費の規模が主題なら絶対額を使い、月額/年額と世帯区分を明記する。
- 家計調査では県全体と県庁所在市を混同しない。47都市の単純平均と公表全国平均を区別し、
  小さい基準額による大倍率を優先しない。元の金額・基準額も確認して採用する。
- カバーは制作IDとカテゴリ別方針に従い、Codex imagegenで文字込みの候補を作って目視照合する。
  正確な県形状が必要なカテゴリは参照輪郭を渡す。実データの統計図はこの例外に含めない。
  プロンプトと生成・保存・採用の正典は[画像契約](../../.claude/rules/note-image-assets.md)と
  `data/note/cover-policies.json`。旧SVG・Remotionによるカバー制作へ戻さない。
- 配色・書体・ロゴ・注記位置は型ごとに共通化する。1280×670、幅320pxのプレビュー、
  文字の重なり・はみ出し、地図の対象範囲、本文との一致を確認する。寸法等は機械検査、読みやすさと約束の妥当性は目視で分けて判定する。
- 作成済み画像の有無とnoteへの設定状態を別々に確認する。設定状態の正典は `npm run note:covers:audit` の
  v3記事詳細 `eyecatch`。一覧に本文画像が出ているだけなら設定済みと判定しない。

### カバー改善のKPIと比較方法

noteは2026-09-08に旧「ビュー」をインプレッションとページビューへ分離し、記事別の数値と期間指定を
提供した。旧viewsを新PVへ読み替えず、比較前後とも新しい定義で取得する。
根拠: [note公式の変更案内](https://note.com/info/n/n39880d8a9c57)、
[指標の定義と確定時刻](https://www.help-note.com/hc/ja/articles/360010324194)、
[流入元の定義](https://www.help-note.com/hc/ja/articles/61983634535449)（確認: 2026-09-12）。

| 層 | 指標 | 判断できること・制限 |
|---|---|---|
| 品質 | 公開対象のカバー未設定数・判定不能数、表記違反数 | 是正の完了条件はそれぞれ0。クリック効果とは別に管理 |
| 露出 | 記事別インプレッション | 読者に表示された量。カバーが良いかを単独では決めない |
| 閲覧 | 記事別PV、取得できる粒度の流入元別PV | 改善の主な観測値。検索・SNS・note内の構成変化も見る |
| 事業成果 | note由来のStats47着地・engaged sessions、対象商品の購入・売上 | カバーの効果だけには帰属させず、閲覧増が目的行動につながったかを確認 |

**CTRは同じ表示機会に対応するクリック数と表示回数を取得できたときだけ算出する。**
総PVには複数の流入経路があるため `総PV / note内インプレッション` をカバーCTRと呼ばない。
note内由来PVでも個々のカバー表示との対応を確認できなければ代替指標に留める。
流入元がアカウント全体でしか取得できない場合、その比率を各記事に配分しない。
`GA4参照セッション / noteビュー` もクリック率ではない。読了率・記事内クリックなど未取得の項目は欠測とし、0で補完しない。

運用は次の順に行う。新指標の収集・比較の自動化は、以下の契約を満たした実測で受け入れる。

1. **計測を成立させる**: stats47アカウント、実際の選択期間・タイムゾーン・集計時刻、指標名、記事IDを記録する。
   全ページを取得してカタログと突合し、欠測・非公開・未登録を説明可能にする。列位置の決め打ち、期間ラベルの固定、桁区切りの誤読を禁止する。
   当日を含めず、指標ごとの確定時刻が対象期間を覆うことを確認する。週次の重複した28日窓同士を差し引いて週間値を作らない。
2. **未設定を是正する**: カバーがない記事は基本品質の是正対象とし、設定済みカバーのデザイン比較とは分ける。
   原稿と出典が確認できるものから用意し、画像生成後とnote設定後の両方を検査する。
3. **比較対象を先に固定する**: 設定済みで一定の露出がある記事から、同じ型・近い公開時期・近い事前PV/表示量・同じ無料/有料区分で組を作る。
   初回は変更5記事と維持5記事を作業量の上限案とする（必要標本数を保証する数字ではない）。
   タイトル、本文、タグ、CTA、宣伝頻度を同時に変えない。2026-09-06のCTA施策など観測中の対象は除外するか、交絡として記録する。
4. **前後を同条件で比べる**: 公開前の0埋めをせず、実在する変更前14日と変更後14日の同じ曜日構成を比較する。
   旧カバー・新カバーのSHA、実際の差し替え時刻、型と版、コピー、根拠データを残す。
   変更群と維持群の変化を記事別・組別で併記し、露出や流入元の変化をカバー効果と取り違えない。
5. **採用・再試作・判定不能を分ける**: 開始前のデータから最低母数、採用に値する改善幅、悪化時の戻し条件を決める。
   母数不足・欠測・他施策混在なら自動で勝者にしない。14日で不足なら最大28日までとし、それでも不足なら判定不能で終了する。
   検索流入増や1記事だけの突出による差はデザインの勝利と扱わない。改善が複数の組で続いた型を次の小規模群で再確認してから広げる。

制作入力・型の定義は既存の原稿/カタログと生成器へ集約し、取得値と実験の観測履歴は `data/note/` に置く。
対象・期日・進捗は既存TODO台帳で管理する。収集入口は`npm run note:metrics:fetch`、
期間・完全性・欠測の契約は[fetch-note-metrics](../../.claude/skills/analytics/fetch-note-metrics/SKILL.md)を参照する。
棚卸し結果の`baselineEligible`は全期間公開・表示ありの粗い条件であり、実験参加・必要母数・交絡除外の判定ではない。
画像差し替えと比較群の登録をするまでは実験開始と扱わない。
