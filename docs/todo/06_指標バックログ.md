## P0 公開データの訂正

### [IND-DATA-CORRUPTION-01] 婚姻率・離婚率の公開誤値

- **priority**: P0
- **status**: in-progress
- **owner**: open-data-curator
- **対象**: `marriages-per-total-population` / `divorces-per-total-population`
- **症状**: 離婚率側に婚姻率相当の値が入り、婚姻率側も人口千対として不自然な値になっている。
- **次**: 下記「処置方針」の (1) を実施する（W33）。(2) は別 ID を立ててから着手する。
- **完了条件**: 2 key の `seoTitle` / `seoDescription` が実データと一致し、旧誤値が本番の `<title>` / meta description に残らない。
- **禁止**: 現在の誤値を計算補正だけで推測修正しない。

#### 照合結果（2026-08-03 実施・W32 Must）

**観測値は誤っていない。誤りは SEO メタデータに閉じている。** 当初の「次」が指していた
人口動態調査 `0003411835` 系との突合は不要だった。両 config が使っているのは
SSDS `0000010201` の `cdCat01=#A06601`（婚姻）/ `#A06602`（離婚）で、R2 の値は
人口動態統計の公表値と一致する（2022年: 全国婚姻率 4.1・離婚率 1.47 に対し
東京の婚姻率 5.36・離婚率 1.37、沖縄の離婚率 2.10）。`app/stats` と `app/ranking`
の両層で 1975-2022 各年 47 件・単位「人口千対」で揃っており、系列の取り違えもない。

誤っているのは config の `seoTitle` / `seoDescription` で、これがそのまま本番の
`<title>` と `<meta name="description">` として配信されている。

| 面 | SEO の主張 | 実データ | 判定 |
|---|---|---|---|
| 婚姻率 | 2014年 1位東京都 6.49 | 2014 東京 6.49 | 一致（ただし最新は 2022） |
| 婚姻率 | 最下位 沖縄県 0.9 | 2014 最下位は秋田県 3.70。沖縄は 5.94 | **県も値も誤り** |
| 婚姻率 | 7.2倍の格差 | 6.49 / 3.70 = 1.75倍 | **誤り**（0.9 起因） |
| 離婚率 | 2024年 | データは 1975-2022。2024 は存在しない | **誤り** |
| 離婚率 | 東京 5.7 が最多 | 離婚率 東京 2022 = 1.37。最多は沖縄 2.10 | **誤り**（婚姻率の桁） |
| 離婚率 | 最下位 秋田 2.5 | 最下位は富山 1.06。秋田は 1.15 | **誤り** |
| 離婚率 | 沖縄は2015年の6.1から急落 | 離婚率 沖縄 2015 = 2.51。**婚姻率 沖縄 2015 = 6.07** | **誤り**（婚姻率を離婚率として記述） |

最後の行が「離婚率側に婚姻率相当の値が入っている」という症状の実体で、
値の出どころは婚姻率の系列だった。両 key とも単位を「‐」と表記している点も誤り
（正しくは人口千対）。

#### 処置方針（1 つに決定）

**(1) 既存 key の SEO 文字列を実データから作り直す。canonical key への置換はしない**
（観測値が正しいので置換する理由がない）。年は最新の 2022 に揃え、単位は人口千対にする。

**(2) ただし同じ穴が最大 2,027 件ある。** SEO 文字列は決定的に生成されておらず
実データとの照合ゲートも無い。実測: config 2,295 件のうち `seoTitle` に数値を含むものが
2,027 件、`seoDescription` に「倍」を含むものが 1,769 件。2 件を手で直すだけでは
同じ誤りが他に何件あるか分からないため、`validate-metric-config.ts` に
「SEO 文字列中の数値・年・県名が `app/stats/<key>/values.json` と一致するか」を
検査する lint を足し、既存違反は baseline に固定して新規混入だけを止める
（`check-value-format.cjs` と同じ縮小専用ラチェット方式）。**この (2) は本 ID の
スコープ外で、`05_機能バックログ.md#SEO-META-FACTUAL-GATE-01` として起票済み。**

2. e-Statメタと代表値を再確認し、`metric-config-standards.md` と `data-provenance-standards.md` に従ってconfigを作る。

5. 完了した行は削除する。
