# TODO インボックス

> セッション中に出た「やりたいこと・改善すべきこと」を**素早く捕捉する staging 置き場**。
> ここは SSOT ではない。整理（triage）のタイミングで適切なバックログへ振り分け、振り分けたら行を削除する（記録は git 履歴）。

## 運用フロー

```
セッション中に思いついた TODO
  → このインボックスの表に1行 append（種別は推定で可、空でもよい）
  → 月初の /monthly-plan（または随時）で triage:
      改善施策      → docs/todo/01_改善バックログ.md
      機能・自動化  → docs/todo/02_機能バックログ.md
      指標拡充      → docs/todo/03_指標バックログ.md
      コンテンツ    → docs/30_note記事企画/backlog/ ほか
      PR で閉じる改修/バグ → GitHub Issues (enhancement/bug)
  → 振り分けたら行を削除（実体は移動先が真実源。解決済みと確認できた行も削除）
```

- **真実源は移動先のバックログ**。インボックスは「まだ分類していない受信箱」。溜めない。
- 種別の推定: `改善` / `機能` / `指標` / `コンテンツ` / `バグ` / `?`(不明)。
- 緊急度・サイズが分かれば備考に書く（後の優先順位付けに使う）。
