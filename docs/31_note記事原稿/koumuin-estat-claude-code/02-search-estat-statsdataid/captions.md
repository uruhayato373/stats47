「目的のデータがどの統計表に入っているか分からない」という状況です。

e-Stat には膨大な統計表が登録されており、同じ「人口」でも「国勢調査」「人口推計」「住民基本台帳人口移動報告」など複数の調査に分かれます。

本記事では、Claude Code の /search-estat スキルを使って e-Stat の統計表 ID (statsDataId) を 1 分で特定するワークフローを扱いました。

執筆者は元自治体職員。現在は Claude Code で 47 都道府県の統計サイト stats47.jp (約 2,000 のランキングを毎日自動更新) を個人で開発・運用しています。

ポイント:

1. e-Stat の統計表は「政府統計コード → 統計表 → statsDataId → カテゴリ → 値」の 4 層構造
2. 本当に必要なのは Layer 3 の statsDataId (10 桁)
3. /search-estat はキーワード・分野コード・政府統計コードの 3 ルートで検索
4. 「探す → 中身を把握する → 取得する」の 3 ステップが標準形
5. ローカルカタログ (estat_metainfo) 併用で 2 回目以降は API 不要

実例 3 ケーススタディ:
・待機児童数 (社会保障・衛生)
・人口移動 (人口・世帯)
・県民所得 (企業・家計・経済)

人口 10-30 万人規模の自治体では、企画課・統計担当が月 5-10 件のデータ取得依頼を受け、その半分以上の時間が statsDataId 探索に消えるケースが少なくありません。本記事はこの探索時間を月単位で 5-10 時間圧縮することを目的としています。
