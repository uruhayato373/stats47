## 概要

Stats47 のユーザー獲得戦略。**Two-track + 意思決定レイヤ** とする (2026-07-07 STP 分析で S2 を明示昇格):

- **Track A (ペルソナ 1, 雑学エンタメ層)**: プログラマティック SEO（自動生成ランキングページ 2,000+）と SNS。PV・AdSense **基盤として維持** — ただし AI 直答に最も侵食されやすいセグメントのため、成長をここに依存しない
- **Track A+ (生活意思決定層, S2)** ★2026-07-07 昇格: 移住・引越し・子育て環境・転職年収の**比較検討層**。AI 耐性中 × アフィリ収益性高 × 競合弱 (とどラン/uub は意思決定支援 UI を持たない)。ブログ型ポートフォリオ (D2 食品/F 市区町村/G 移動フロー、[`blog-seo-strategist`](../../.claude/agents/blog-seo-strategist.md)) とアフィリ意図軸 (housing/mobility/labor) が実行面
- **Track B (ペルソナ 3, 行政・自治体関係者)**: 公務員 × AI 活用記事 (note + ブログ)、内部リンク強化、公務員系タグページの index 復活。出典・年次・定義の正確性が必須のため **AI 耐性が最も高い**濃いニッチ

手動コンテンツ量産は行わない。Track B も「月 1-2 本の高品質記事」上限とする。

> **SNS戦略**の実行規約・撤退チャネル・頻度上限は [SNS content standards](../../.claude/rules/sns-content-standards.md) を参照。

### 1. 競合分析マップ (2026-07-07 刷新)

### 1.5 AI 検索環境の構造変化 (2026-07 時点)

- SERP の約 58% に AI Overviews が表示され、informational クエリのオーガニック流入は 30-40% 減 (出典: [thestacc.com](https://thestacc.com/blog/google-ai-overview-statistics/) / [velacore.au](https://velacore.au/traffic-lost-to-google-ai-overviews/)、アクセス 2026-07-07)
- 「うどん消費量 1位はどこ?」型の**単一事実クエリ (Track A の主流入) は AI が直答して終わる**リスクが構造化した
- 一方 **AI Overviews に引用されたブランドはオーガニッククリック +35%** ([quickseo.ai](https://quickseo.ai/blog/google-ai-overviews-statistics-2026-60-data-points-every-seo-should-know)、アクセス 2026-07-07)

**方針: 「AI に引用される一次加工ソース」ポジションを取る。** 出典・年次・定義の明示 (metric config の note/description)・構造化データ・安定 URL は既に引用適性が高い。実行は本書「トラフィック成長ロードマップ」の技術 SEO レバー、定点観測は改善バックログ STP-AI-WATCH-01 が担う。

### 2. 差別化戦略

エンジニア1人で技術力によって構築できる参入障壁にフォーカスする。コンテンツ量産の人海戦術には引きずり込まれない。

**差別化の第1軸: 更新速度**
- 公的統計のリリースから24時間以内にランキングページを自動更新する
- とどランの最大の弱点「データ更新の遅れ」で圧倒的な差を作る
- データパイプラインの自動化がエンジニアの技術力で直接構築可能な参入障壁

**差別化の第2軸: UI体験**
- モバイルファーストで、ランキングをスワイプで比較・フィルタリングできるインタラクティブUI
- とどランの「UIがモダンではない」という弱点を突く

**相関分析はおまけ機能**
- 作ること自体は否定しないが、差別化の主軸にはしない
- N=47の統計的限界を考慮し、SNSで話題にする程度の位置づけに留める

## 編集ガイドライン（ランキングの倫理）

データを扱うメディアとしての信頼性を維持するため、以下のルールをすべてのコンテンツに適用する。

### 1. 相関表現のルール
- **「相関がある」と「因果関係がある」は明確に区別する**。相関分析の結果は「〜と相関がある」「〜と関連がみられる」と表現し、「〜が原因で」「〜のおかげで」等の因果表現は使用しない
- 相関係数を提示する場合は、サンプルサイズ（N=47）の限界にも言及する
- 疑似相関の可能性がある場合は「第三の変数の影響も考えられる」旨を注記する

### 2. ワーストランキングの扱い
- 犯罪率・離婚率・生活保護率など、地域スティグマにつながりうる指標は**「ワースト」という表現を避ける**
- 構造的要因（都市化度・高齢化率・統計の取り方の違い等）を必ず補足し、数値の一面的な解釈を防ぐ
- タイトルで煽る表現（「最悪の県」「ダメな県」等）は禁止

### 3. 出典・データソースの明記
- すべてのランキング・統計データに**一次ソースへのリンクを付与**する
- データの調査年・調査主体・調査方法を明記する
- 複数年のデータを比較する場合、調査方法の変更があれば注記する

## トラフィック成長ロードマップ（T1〜T4・SSOT）

### 計測契約

- フェーズ判定の検索主指標は **GSC finalized7d clicks/週**。取得遅延後の連続 7 日と、その直前の重複しない 7 日を比較する
- 100万 PV は **GA4 Japan-only の bot 除外済み月間 PV** で判定する。GA4 PV はフェーズ中間では従指標とする
- 重複する rolling 28d は page/query/device の機会発見にのみ使い、WoW やゲート判定に使わない
- 詳細は [`weekly-cycle-contract.md`](../../.claude/skills/analytics/search-growth/reference/weekly-cycle-contract.md)。欠損・partial・期間不整合があればゲート判定を保留する

### PV 内訳モデル

以下は **[仮説]** であり、固定ノルマではない。四半期末に ranking / blog / 回遊・配信の面別実測で再計算する。

| 面 | 到達時のページ規模 | 平均 PV/月/ページ | 月間 PV 寄与 |
|---|---:|---:|---:|
| ranking | 約 5,000 | 約 120 | 約 60万 |
| blog | 約 800〜1,000 | 約 300 | 約 25〜30万 |
| 回遊・配信・その他 | theme / area / compare + 外部送客 | — | 約 10万 |
| **合計** | — | — | **約 95〜100万** |

検索流入の主エンジンは ranking と blog。theme / area / compare は主に回遊・深掘り面として扱う。
ページ数だけでなく、インデックス率、CTR、検索順位、PV/セッションを同時に改善する。プロジェクト KPI の
月20万 PV は T2 から T3 へ進む途中のチェックポイントとして接続する。

### T1〜T4 のフェーズゲート

| Phase | 到達ゲート | 中心課題 |
|---|---|---|
| **T1 基盤固め** | 月3万 PV かつ GSC finalized7d 4,000 clicks/週 | 既存在庫の品質・カバレッジ・CTR を是正し、ranking / blog の供給ループを安定稼働させる |
| **T2 供給拡大** | 月10万 PV | `[仮説]` metric 約3,000・記事約400を目安に、検証済み指標、norm 派生 SSG、記事ポートフォリオを拡張する |
| **T3 スケール** | 月30万 PV | `[仮説]` metric 約5,000・記事約700を目安に、市区町村面を収益・品質ゲート後に展開し、content graph で回遊を強化する |
| **T4 100万PV** | 月100万 PV | e-Stat 指標の体系的消化、市区町村×テーマの非重複面、自動更新、検索外流入を組み合わせる |

ゲート未達なら次フェーズへ進まない。市区町村面・大量 SSG は thin/duplicate/index bloat を機械検証できることを前提とする。
2026-07-18 の KAIYU-HUB-01 前倒し判断は Phase 0 の read-only 監査に限る例外で、T3 全体の前倒しではない。
YouTube は T1 の**実験的配信面**として6週間・通常動画3本だけ検証する。成功判定までは成長レバーや収益予測へ算入しない。
TikTok は完全撤退済みであり、T2 以降も再開レバーに含めない。

### 成長レバー

1. **SEO 供給** — [`backlog.md`](../todo/backlog.md) から検証済み指標を増やし、norm 派生 SSG・市区町村面は品質ゲート後に展開する。ブログの生産ペースと型は [`blog-seo-strategist`](../../.claude/agents/blog-seo-strategist.md) を参照する
2. **SEO 品質** — 高 impressions・低 CTR の title/snippet、ブログ品質是正、ranking editorial、出典リンク、内部リンクを優先する
3. **技術 SEO** — GSC カバレッジ、canonical、sitemap、構造化データ、Core Web Vitals、SSG を保全する。AI 引用最適化は出典・年次・定義・安定 URL の引用適性を監査し、STP-AI-WATCH-01 で四半期観測する
4. **配信** — X / Instagram / note と YouTube pilot は [SNS content standards](../../.claude/rules/sns-content-standards.md) と [`note戦略.md`](../30_note記事企画/note戦略.md) の範囲で送客と指名検索を補助する。YouTube は通常動画をマスターにして派生クリップを X / Instagram へ展開する。SNS 依存の成長モデルにはしない
5. **回遊** — theme / area / compare を深掘りハブとして接続し、入口別の 2 ページ目到達率と PV/セッションを上げる。詳細・status は [`KAIYU-HUB-01`](../todo/backlog.md#kaiyu-hub-01) を参照する
6. **時事・季節連動** — 公的統計で補足できるニュースと、引越し等の季節需要に ranking / blog / SNS を接続する
7. **計測 PDCA** — 週次は search-growth、月次は重点レバーとゲート、四半期は PV 内訳モデルを更新する

### 月次チェックポイント

1. GSC finalized7d clicks/週と前期間比
2. GA4 Japan-only 月間 PV
3. ranking / blog の面別 clicks とインデックス率
4. 新規 metric・記事の供給数と、公開後のインデックス・流入
5. X / Instagram / note の投稿数・送客、および pilot 中は YouTube の30秒維持率・平均視聴率・UTM送客
6. PV/セッションと入口別 2 ページ目到達率

同じ面のゲート未達が 2 か月続いた場合、その面のボトルネックを次月の重点候補にする。数字が不足している場合は
施策実装ではなく計測復旧を先に行う。

### リスクと抑制策

| リスク | 抑制策 |
|---|---|
| Google コアアップデート | 出典・専門性・品質是正を継続し、ranking / blog / 指名流入へ分散する |
| AI Overviews による CTR 低下 | curiosity gap と独自比較を強化し、「AI に引用される一次加工ソース」を四半期観測する |
| ページ増加による thin / duplicate / index bloat | 供給と同時に provenance・canonical・内部リンク・index 状態を検証し、不合格面を公開しない |
| 単独運営の稼働制約 | 月次重点を 1〜2 テーマに絞り、決定的処理を自動化し、フェーズを飛ばさない |
