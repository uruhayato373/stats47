# 収益化戦略（SSOT）

## 0. 本文書の位置づけ

Stats47 の**収益モデル、チャネル配分、広告・アフィリエイトの配置判断、収益ゲートの唯一の真実源**。
トラフィック成長は [`03_マーケティング戦略.md`](./03_マーケティング戦略.md)、施策の status・期日・担当は
[`.claude/todo/`](../todo/todo-standards.md)、実装規約は `.claude/rules/` と各 analytics skill を優先する。

本書には変動する在庫数、週次実測、完了済み工程、モデル別担当を固定しない。現在値は `.claude/state/metrics/` と
広告 state、当月の重点は [`monthly.md`](../todo/monthly.md) から読む。

## 1. 目的と North Star Metric

HARM・需要確認の共通原則は [共通事業方針の配布版](../../.claude/shared-policy/POLICY.md) を参照する。
stats47への適用は [application.json](../../.claude/shared-policy/application.json) に置き、本書が収益モデル・KPI・優先順位を引き続き管理する。共通原則の正本はObsidian vault `.claude/共通事業方針SSOT.md` だけで編集する。

目的は、**地域の統計を広く届け、議会答弁・計画策定の資料づくりで繰り返される統計の収集・整理作業を減らし、
運営費と継続改善の工数を回収できる状態を作ること**。
短期的な売上最大化のために、統計の解釈、公平性、表示速度、読者体験を犠牲にしない。

**North Star Metric（NSM）は週次収益**とする。

```text
週次収益 = AdSense 確定額 + アフィリエイト発生額 + 商品の実売額
```

PV は収益の先行指標であって NSM ではない。主な先行指標は次のとおり。

| 領域 | 先行指標 | 主な参照先 |
|---|---|---|
| 集客 | GSC finalized7d clicks、GA4 Japan-only PV | search-growth / `.claude/state/metrics/` |
| AdSense | 恒久停止（2026-09-20）につき先行指標を持たない。確定額は ¥0 固定 | §3.1 |
| アフィリエイト | `affiliate_impression`、`affiliate_click`、CTR、CV、EPC、発生額 | affiliate-improvement / ASP 管理画面 |
| 商品 | 無料需要、pilot 購入数、返金、制作・運用工数 | product skill / 販売台帳 |
| 行政実務の価値 | 同じ資料の収集・整形・照合に要した時間、手直し、実務利用、再利用 | §3.4・§5 の業務検証。DL数だけで代用しない |
| 地域意思決定 | 比較・地図操作・データDL等を含む地域意思決定セッション | GA4 / business-plan state |

重複する rolling 28d の差を WoW と呼ばない。検索の期間契約は
[`weekly-cycle-contract.md`](../../.claude/skills/analytics/search-growth/reference/weekly-cycle-contract.md)、
効果判定は [`evidence-based-judgment.md`](../../.claude/rules/evidence-based-judgment.md) に従う。

## 2. 戦略の中心

### 2.1 誰の、どんな課題を解決するか（2026-09-18 採択）

**「多くの人が訪れる統計メディア」と「行政の統計処理の負担を減らす実務支援」を両立する。**
一般読者には地域の違いを発見・理解する価値を、行政実務者には資料作成に必要なデータが整理されている価値を届ける。
一般読者の全員を業務商品の購入者へ転換する前提は置かない。両者は同じ検証済みデータを利用するが、獲得経路と成果を分けて測る。

| 対象 | 具体的な課題 | 提供価値 | HARMと理由 |
|---|---|---|---|
| 地域の違いや身近な話題を知りたい一般読者 | 数字だけでは地域の特徴や背景が分からない | ランキング・記事・比較・地図で発見と理解を届ける | 好奇心は対象外でも価値がある。生活判断を扱う場合だけ家計のM・家族生活のR等を確認 |
| 議会答弁・計画策定の資料を作る行政実務者 | 各所の統計を探し、Excelへ集め、地域・年次・単位・定義を照合する作業を繰り返す | 複数統計を用途別に整理した編集可能な資料と、その更新 | A：仕事の達成・技能。M：所属組織の作業費用削減は実測できた場合のみ |

オーナーとの議論で課題と事業の意図は確認した。複数の実務者による利用、削減時間、支払者、購入価格、
反復需要は**未検証**であり、事業の意図と市場の実証を混同しない。
「公務員向けAI講座」「移住アフィリエイト」は、該当する利用意図が確認された場合の個別手段とする。

### 2.2 競合との比較基準

RESAS・e-Stat・自治体ダッシュボード・統計書は、実務者が選べる代替手段として扱う。
「官製サービスは使いにくい」「編集・可視化すれば売れる」という前提は置かない。

| 代替手段 | 公式資料で確認した提供価値 | stats47の検証対象 |
|---|---|---|
| [RESAS](https://resas.go.jp/) | 無料・登録不要の地域経済データ分析・可視化 | 同じ資料を作る際に残る収集・加工・照合を減らせるか |
| [静岡県の観光データ公開](https://www.pref.shizuoka.jp/_res/projects/default_project/_page_/001/081/589/05_0417kankou2.pdf) | 観光統計を集約・可視化し、自治体・事業者の戦略策定へ提供 | 対象業務で既存の公開物だけでは完了しない作業は何か |
| [東洋経済『地域経済総覧』](https://str.toyokeizai.net/databook/dbs_chiikikeizai/) | 自治体別の経済・社会データを編集した書籍と法人向けデータベース | 利用者が現在使う本・サービスと比べて残作業や費用を減らせるか |

確認日：2026-09-18。機能の存在は確認したが、同一業務での比較試験・販売実績は未取得。
優位性は、同じ完成条件の資料について**総作業時間・手直し・出典追跡・費用**を比較して判断する。
既存手段で十分なら、類似商品の開発は見送る。

### 2.3 収益モデルと投資順序

| 位置づけ | 誰が何に支払うか | 現在の判断・開始条件 |
|---|---|---|
| 無料メディアの継続 | 閲覧者は無料。文脈に合うサービスの広告主が成果に対して支払う | ランキング・記事の品質と既存アフィリエイトの計測を維持。統計閲覧から購入意図を推測しない |
| **新規収益の主検証：用途別Excel資料** | 職員本人または所属組織が、複数統計の収集・整形・照合を省く成果物に支払う | 支払者は未確定。1業務・1商品・1販売面で、無料試用による実務価値の確認後に有料pilot |
| 更新版・継続利用 | 同じ資料を再利用する購入者が、確認済みの更新版に支払う | 初回実売と反復需要の確認後。統計の公表周期と利用頻度に合わせ、月額を先に決めない |
| 個別支援・法人利用 | 個別要件を持つ組織が、範囲を固定した追加作業に支払う | 具体相談、納品範囲、工数、採算の確認後。無制限の個別対応を商品本体に含めない |
| 広告・スポンサー | 広告主が読者への接点に支払う | AdSenseは恒久停止（2026-09-20）。スポンサーは適合する読者・案件を確認してから。編集判断を販売しない |

**既存の集客・品質・計測を維持しつつ、新規商品投資は行政資料1件の検証へ集中する。**
アフィリエイト実験の成功を行政商品の検証開始条件にしない。note・ココナラ・Kindleは販売・配信手段であり、
チャネル数や商品在庫数を目標にしない。既存商品は使える素材として評価し、カタログにあることを需要の証拠にしない。

事業計画の「地域意思決定セッション」は先行指標として維持する。git TSの5収益レイヤー・企画候補は
選択肢の在庫であり、新規投資の優先順位は本節、開始条件は§5を優先する。
既存のM3/M6/M12の売上・アクセス値を今回の戦略の予測として流用しない。

## 3. 収益レーン別方針

### 3.1 AdSense（恒久停止）

#### 恒久停止（2026-08-16 一時停止 → 2026-09-20 恒久化を決定）

オーナーは読者体験を優先し、**AdSense のスクリプト、Auto ads、手動枠、fallback、広告用の空カード・
予約高を全ページで停止する**と 2026-08-16 に決定し、2026-08-29（PR #849 の main マージ）に本番反映した。
2026-09-18 に `curl -s https://stats47.jp/ | grep -c "adsbygoogle\|pagead2"` = 0 で配信停止を確認している。
アフィリエイト広告は停止対象に含めない。

**2026-09-20、オーナーはこれを恒久停止とすることを決定した。** 根拠は金額の規模である。停止直前の
通常週（2026-W33）は収益 ¥118 / 3,152 PV でページ RPM ¥37 だった。現在のトラフィック（GA4 週 11,090 PV）
に同じ RPM を当てても月 ¥1,400〜1,800 にしかならず、読者体験と表示速度を対価に見合わない。
**PV が伸びてもこの結論は変わらない**（月 20 万 PV でも月 ¥6,000〜7,400 の水準）。

実装の全体スイッチは `apps/web/src/lib/google-adsense/constants.ts` の `ADSENSE_DISPLAY_ENABLED`
（`false` 固定）。恒久停止の判断はこの 1 行に集約されているので、再開を前提とした配置原則・
週次計測手順・改善ループは撤去する。再開するなら、それは本書の改訂を伴う新しい判断である。

**28 日判定（期日 2026-09-26）で確定できなかったこと**を明記する。停止の代替収益として比較する
はずだったアフィリエイト実測が 2026-08-28 以降欠測しており、**代替収益の比較はできなかった**。
Core Web Vitals と回遊への効果も、スクリプト停止による LCP 改善は過去の計測で確定していないため
主張しない。恒久停止は「停止して良かったと実証できたから」ではなく、**上限金額が読者体験に
見合わないと判断したから**である。

停止に伴い、次の運用を止める（2026-09-20）。

- `weekly-review` / `weekly-plan` の計器一覧から AdSense を外し、§1 の NSM に置き換える
- `/fetch-adsense-data` の週次呼び出しと `/adsense-improvement` の改善ループを止める
- 過去の AdSense 実測（`.claude/state/metrics/adsense/`）は凍結記録として残す

#### （凍結記録）モバイルの手置き枠を撤去した根拠（2026-08-04・W31 実測）

placement 別の実測で、**手置き枠と Auto ads の RPM が 1 桁違う**ことが分かった。

| placement | 収益 | imp | RPM | viewability | requests | 充足 |
|---|---:|---:|---:|---:|---:|---:|
| AUTO_ADS Desktop | ¥73 | 681 | ¥107 | 86.3% | 2,734 | 60.0% |
| AUTO_ADS Mobile | ¥33 | 287 | ¥114 | 74.0% | 1,207 | 80.5% |
| MANUAL Desktop | ¥34 | 2,640 | ¥13 | 48.9% | 9,333 | 28.9% |
| **MANUAL Mobile** | **¥4** | 495 | **¥8** | **28.6%** | 2,037 | 25.7% |

モバイルの手置き枠は週 ¥4（全収益の 2.7%）のために 2,037 リクエストと 495 の描画を消費し、
表示できた分の 7 割が視認されていない。実ユーザー LCP は p75 = 2,476ms で閾値 2,500ms まで
24ms しか余裕がなく、モバイルが最も苦しい。**収益レーンの入れ替えではなく不良在庫の整理**として
撤去する（上記「低 viewability / 低 imp RPM の枠は撤去を比較する」の実行）。

デスクトップの手置き枠は週 ¥34（23%）あるため同じ理屈では切れない。枠単位の内訳
（unit_id ↔ コード側 slot_id）が要るが、その ad-units inventory は 2026-08-04 まで
**一度も取得に成功していなかった**（`fetch-adsense-snapshot.mjs` を同日修正）。inventory が
入ってから個別に判断する。

**未検証**: 手置き枠を外した領域に Auto ads がどう反応するかは測っていない。確実なのは
「週 ¥4 を失う」ことだけで、それ以外は撤去後の実測を待つ。画面が確定するまでは
baseline 自体がノイズなので、判定は UI が落ち着いてから行う。

実装・計測の正典は `apps/web/src/lib/google-adsense/`、
ビューポート方針は `apps/web/src/features/ads/constants/manual-ad-policy.ts`、
`.claude/skills/analytics/adsense-improvement/`、Google 管理画面の安全契約は
`.claude/scripts/google-admin/README.md`。

### 3.2 文脈一致アフィリエイト

広告は**ページ分類 → vertical → 広告**で解決し、在庫都合で無関係な商材を出さない。
vertical、提携状況、配置、計測の詳細は
[`affiliate-ads-standards.md`](../../.claude/rules/affiliate-ads-standards.md) が実装 SSOT。

案件の種類 (高単価案件・無料登録型の低ハードル案件) は、広告の数を増やさずに **CTR が出ている 1 枠で 2 週間ずつ順番に入れ替えて**確定収益 / 1,000 viewable impression で比べる (2026-09-26 オーナー判断、実行は backlog `AFF-OFFER-ROTATION-01`)。複数案件の同時入れ替えは効果を分離できないので行わない。

| 読者の意図 | 主な vertical | 主な配置面 |
|---|---|---|
| 年収・仕事を比較したい | `labor` / `economy` | 年収・所得・求人 ranking / blog |
| 移住・地域を選びたい | `housing` / `furusato` | area、人口移動・住宅 blog |
| 住まい・移動手段を検討したい | `housing` / `mobility` | 地価・住宅・交通 ranking / blog |
| 教育・子育て環境を比べたい | `education` / `population` | 教育・子育て ranking / blog |

配置拡大は `affiliate_impression` と `affiliate_click` が page type / vertical / placement 別に取得でき、
ASP の発生額と照合できることが前提。クリックだけで効果を主張しない。

案件は報酬単価の高低ではなく、読者の行動段階に合わせて二層で運用する。

1. **探索レーン** — 無料閲覧・ダウンロード・アプリ・無料登録など、購入前の比較中でも実行できる案件。
   広い情報探索ページへ無差別に増やさず、文脈が一致する一つの導線として検証する。
2. **意思決定レーン** — 資料請求・見積もり・相談・購入など、具体的な意思決定を伴う案件。
   対象 ranking key または記事文脈を明示できる高意図ページだけに置く。

「無料」という表示だけで低負担と判定しない。個人情報、電話連絡、面談、支払いの有無を含む成果条件を
ASP の確認日付き情報から記録し、条件不明の案件は探索レーンへ自動採用しない。クリック報酬も、クリック数ではなく
確定収益まで取得できる場合だけ他方式と比較する。評価の主指標は**確定収益 / 1,000 viewable impression**、
補助指標は CTR、CVR、確定率、`affiliate_impression / pageview` とする。ASP の成果を広告単位へ結べない場合は
0円ではなく判定不能として扱う。機械契約と実装順は `.claude/rules/affiliate-ads-standards.md`、進捗は
`.claude/state/ads/affiliate-portfolio-latest.json` と
`.claude/state/ads/affiliate-pilot-readiness-latest.json` を正典とする。

運用の現在地は`.claude/state/ads/affiliate-portfolio-latest.json`、公開pilotの開始可否と観測判定は
`.claude/state/ads/affiliate-pilot-readiness-latest.json`を読む。週次自動化は観測・候補提示までで、ASP申請、
priority変更、勝者反映、push/deployを行わない。pilotは既存配信中の1案件・既存の1枠・ranking/blogの1ページに限定し、
必要click/impと最大期間内の実現可能性を開始前に計算する。CTRが高くても確定収益が成熟するまでは勝者としない。
readiness が `blocked` の間は公開pilotを進めず、再開するときだけ新しい期限付き改善カードを起票する。

AdSense 恒久停止後の第一段階は、新規ASP申請や在庫追加より先に、**既存在庫を文脈一致のまま
視認される位置へ配線すること**とする。在庫が10 verticalすべてを満たしている間は、停止した枠のうち
検索需要がある ranking と地域意図が明確な area の本文・右レールを優先する。バナーは画像だけを表示し、
PR見出し、説明、Card装飾は加えない。home や `other` から意図を推測して無関係な案件を出さず、
viewable impression の 50% × 1秒閾値も緩めない。評価は `affiliate_impression / pageview` と
placement別CTRを、デプロイ前後の重複しない期間で比較する。

### 3.3 note と外部送客

- 無料noteは問い・物語・統計の読み方を提供し、Stats47の比較・出典・関連データへつなぐ
- noteを商品の販売面に選ぶ場合は、§3.4の納品仕様・試用・購入条件を確認し、1商品・1販売面のpilotとして扱う
- 本文を Stats47 と重複させず、関連する ranking / area / blog へ自然に接続する
- 無料noteはStats47流入と利用、商品noteは実売・実務利用・運用工数を評価する。viewsだけで成果を判定しない
- 投稿頻度・実行規約は [`sns-content-standards.md`](../../.claude/rules/sns-content-standards.md) と
  [`note戦略.md`](../30_note記事企画/note戦略.md) を優先する

### 3.4 商品・データ販売

課金対象は、**特定の資料づくりに必要な複数統計の選定・整形・照合・編集用成果物・更新**とする。
基本のランキング・出典・比較データ・既存の基本CSVは無料で維持する。正確な解釈に必要な定義・注意事項も隠さない。
Excel拡張子であることや、公開データをまとめ直したことだけを支払う理由にしない。

#### 最初の商品仮説：議会答弁・計画策定の基礎資料パック

1つの実在業務を選び、その完成資料から必要な統計を逆算する。人口・子育て等は候補であり、
必要な業務・指標・地理粒度を確認する前に採択しない。県・市区町村・県庁所在市のデータを混ぜず、
対象業務に必要な粒度が提供できなければ対象を狭めるか見送る。

| 無料で提供するもの | 有料候補として検証するもの |
|---|---|
| 統計の閲覧、基本の比較・CSV、出典、読み方 | 指定した業務に必要な複数統計をまとめた編集可能なExcel一式 |
| 収録内容、対象地域・年次、サンプル、欠測・比較限界 | 比較表、推移表、図、出典一覧を同じ版に揃えた納品物 |
| 更新日と訂正情報。購入済み版の誤りは新規購入へ誘導しない | 新しい公表データへの更新版、差分確認、検証済みの更新手順 |

納品単位は、完成見本・比較対象・収録期間・指標定義・欠測の扱い・編集可能範囲・更新とサポートの範囲を
事前に明示する。年次や定義を揃えられない箇所は差異として残す。利用者のExcel環境で開き、
編集し、出典まで戻れることを確認する。答弁の結論・政策判断の妥当性まで保証する商品にはしない。

直接の利用者は職員だが、支払者は未確定。職員の個人購入、所属組織による購入、同じ資料を作る外部受託者を
候補として分け、誰に予算と購入判断があるか、納品・支払条件、購入までの期間を確認する。
職員の好意的な感想を組織の購入意思へ置き換えない。

#### 価格と採算

価格・販売数・月次売上は、現段階では未設定。価格提示前に、代替手段の費用、削減できた作業、
支払者の予算、制作・更新・問い合わせ工数を確認し、1つの試験価格と対象範囲を固定する。
価格の安さを優先してサポートで赤字になる商品は横展開しない。

```text
期間収入 = メディアの実収入 + 商品の実売収入（税・返金・確定/未確定を区別）
商品1件の限界利益 = 1件の売上 - 返金 - 販売/決済手数料 - 納品/対応の変動費
期間の事業収支 = 期間収入 - 手数料等 - 制作/更新/対応費 - 共通運営費
工数込み採算 = 期間の事業収支 - 運営者の実作業時間 × 採択した時間単価
```

運営者の時間単価とpilotの工数上限は開始前に決め、無給扱いしない。費用と作業時間を二重計上しない。
制作費を回収できる販売数は、1件当たりの利益が正の場合にだけ計算する。メディア収益が商品開発を賄えるとも
未確認の段階で想定しない。更新周期ごとの収支が不明なら、買い切りpilotに留める。

進行条件は次の順序に固定する。

1. 無料コンテンツで関心を観測し、対象業務の利用者が無料サンプルを実際に使って残作業と削減時間を確認する
2. 支払者と購入条件を確認し、1業務・1商品・1販売面の買い切りpilotを作る
3. 外部公開・価格設定・出品は人間が承認する
4. 実売と運用工数を確認する
5. 勝った商品だけ別チャネルへ展開する

検索・DL・アンケート上の好意だけでは業務需要や購入需要を証明しない。
無料需要を通らない商品、同文大量展開、AI 無審査公開、複数チャネル同時 pilot は禁止する。

### 行政向け商品の検証順序

以下の件数・期間は市場規模や効果の予測ではなく、個人運営で判断を先延ばしにしないための暫定的な実験上限・
進行条件とする。実行期日・担当・状態はバックログの `ADMIN-STAT-PILOT-01` に集約する。

| 段階 | 実施・記録すること | 次へ進む条件 | 止める・見直す条件 |
|---|---|---|---|
| 1. 業務を選ぶ | オーナーの実例を起点に、対象業務の担当者3人を目安に直近の資料作成手順・出典・所要時間・再実施頻度・既存手段を確認 | 複数の担当者で同じ収集・整理作業が残り、1つの納品仕様にできる | 協力者が集まらなければ未検証とする。既存手段で十分、または個別要件ばかりなら汎用商品化を見送る |
| 2. 無料試用 | 1業務・1地域条件のサンプルを既存資産から作り、同じ完成条件の作業を比較。回顧による時間と実測を区別 | 2人以上が実務用資料に利用でき、照合・手直し込みの総時間が減る。出典と値の検証に阻害要因がない | 時間削減がない、品質確認に余計な工数がかかる、必要な粒度を揃えられない場合は修正または見送り |
| 3. 有料pilot | 支払者・予算・購入経路を確認し、価格・納品範囲・工数上限を固定。見本を提示し既存販売面で実売を確認 | 身内・自己購入を除く実売2件以上、実務利用、正の限界利益を確認 | 試験開始後30日を初回判断点とし、利用はあるが購入がない場合は支払者・予算・価格・経路を切り分ける。購入手続き待ちは予定日を確認し、期限なしに延長しない |
| 4. 更新・横展開 | 初回利用と次回用途を確認し、更新とサポートを含む工数込み採算を測る | 同じ仕様の再利用需要と工数込み採算が確認できた商品だけ更新版や隣接用途へ | 調達・サポート工数が採算を超える、毎回作り直しになる場合は範囲縮小・価格見直し・停止 |

実売2件は次の小規模試験へ進むための条件であり、継続的な事業成立の証明ではない。
メディア側は検索流入・再訪・引用と収益、業務側は総作業時間・実務利用・再利用と収支をそれぞれ評価する。
アフィリエイト計測は継続するが、その完了を聞き取り・無料試用の前提にしない。
商品カタログ全件の制作、会員制、API、新しい決済基盤、無制限の個別受託はこの検証を先回りして開始しない。

## 7. 検証規律

- 全領域の active WIP は **5以下**。AdSense の配置実験は恒久停止につき **0件**とする
- 同一ページ・同一指標に複数変更を重ねず、何が効いたか分離できる状態を保つ
- effect 未確定の同系統へ新施策を積まない
- 想定値、根拠、判定日、取得コマンド、実測値が揃うまで `effect/full` 等を付けない
- rolling 28d 同士の差、bot 混入値、未登録 custom dimension をゲート判定に使わない
- 人間承認が必要な OAuth、管理画面設定、ASP申請、外部出品はTODOで追跡し、文書へ期限を重複記載しない

週次候補の収集・承認は search-growth / adsense-improvement / affiliate-improvement、
施策 status は [`improvements.md`](../todo/improvements.md) を正典とする。

## 8. 禁止事項と倫理

- 全 ranking へ同じアフィリエイト広告を置かない
- アフィリエイト未計測のまま枠・商材を拡大しない
- 47都道府県分の薄い記事・商品を一括生成しない
- note と Stats47 に同じ本文を複製しない
- 統計結果を商材・スポンサーに都合よく解釈しない
- 公的統計サイトとしての信頼を損なう商材（精力・マカ等の強壮サプリ、アダルト、情報商材など）を
  収益を理由に置かない。判定は `.claude/scripts/ads/data/a8-curated.json` の `blocklistKeywords` と
  `AFFILIATE_DELIVERY_HOLDS` で機械的に行う（2026-09-18 オーナー判断・AFF-BRAND-FIT-01）
- 広告クリックを促す表現や視覚誘導を置かない
- 公的統計の基本閲覧を有料化しない
- 需要未検証の会員制、API、法人営業基盤を先に作らない
- 収益密度施策を飛ばして、PV や商品数だけを追わない
