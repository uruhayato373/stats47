# 収益化戦略（SSOT）

## 0. 本文書の位置づけ

Stats47 の**収益モデル、チャネル配分、広告・アフィリエイトの配置判断、収益ゲートの唯一の真実源**。
トラフィック成長は [`03_マーケティング戦略.md`](./03_マーケティング戦略.md)、施策の status・期日・担当は
[`.claude/todo/`](../todo/todo-standards.md)、実装規約は `.claude/rules/` と各 analytics skill を優先する。

本書には変動する在庫数、週次実測、完了済み工程、モデル別担当を固定しない。現在値は `data/<取得元>/` と
広告 state、当月の重点は [`monthly.md`](../todo/monthly.md) から読む。

## 1. 目的と North Star Metric

HARM・需要確認の共通原則は [共通事業方針の配布版](../../.claude/shared-policy/POLICY.md) を参照する。
stats47への適用は [application.json](../../.claude/shared-policy/application.json) に置き、本書が収益モデル・KPI・優先順位を引き続き管理する。共通原則の正本はObsidian vault `.claude/共通事業方針SSOT.md` だけで編集する。

目的は、**地域の統計を広く届け、議会答弁・計画策定の資料づくりで繰り返される統計の収集・整理作業を減らし、
運営費と継続改善の工数を回収できる状態を作ること**。
短期的な売上最大化のために、統計の解釈、公平性、表示速度、読者体験を犠牲にしない。

**North Star Metric（NSM）は週次収益**とする。

```text
週次収益 = AdSense 確定額 + アフィリエイト発生額 + 商品の実売額
```

PV は収益の先行指標であって NSM ではない。主な先行指標は次のとおり。

| 領域 | 先行指標 | 主な参照先 |
|---|---|---|
| 集客 | GSC finalized7d clicks、GA4 Japan-only PV | search-growth / `data/gsc`・`data/ga4` |
| AdSense | 2026-10-11 に手動枠で再開。広告ユニット別の収益・表示・視認率と、GA4 の PV で割った `ad-yield`（API 認証の復旧までは判定不能） | §3.1 |
| アフィリエイト | `affiliate_impression`、`affiliate_click`、CTR、CV、EPC、発生額 | affiliate-improvement / ASP 管理画面 |
| 商品 | 無料需要、pilot 購入数、返金、制作・運用工数 | product skill / 販売台帳 |
| 行政実務の価値 | 同じ資料の収集・整形・照合に要した時間、手直し、実務利用、再利用 | §3.4・§5 の業務検証。DL数だけで代用しない |
| 地域意思決定 | 比較・地図操作・データDL等を含む地域意思決定セッション | GA4 / business-plan state |

### 1.1 KPI ツリー（計測 → 記録 → 改善サイクルの舵）

週次収益は金額が小さく、週ごとの変化がノイズに埋もれるため、週次の判断には使えない
（アフィリエイトは 28 日で 13 クリック、2026-09 実測）。そこで KPI を 3 階層に分け、見る頻度を変える。

| 階層 | 役割 | 見る頻度 | 使う場面 |
|---|---|---|---|
| NSM | 週次収益。最終成果 | 月次 | `/monthly-plan` の振り返りで重点レーンを選び直す |
| 駆動 KPI | 週単位で動き、NSM のどれかの項につながる指標 | 週次 | `/weekly-review` で重点レーンの KPI を判定し、`/weekly-plan` の Must を選ぶ |
| ガードレール | 悪化させてはいけない守りの指標（データ品質・サイト健全性・運用コスト・計測の鮮度・インデックス登録率） | 週次 | 悪化したら重点に関係なく是正を Must に入れる |

KPI の一覧・定義・計測状態の正典は事業計画 catalog（`packages/data-configs/src/business-plan/catalog.ts` の
`kpiTier` 付き metric）で、本書に写しを持たない。`npm run business-plan:build-state` が
`data/business-plan/kpi-tree.json` を生成し、`npm run business-plan:check` が catalog とのずれを拒否する。
今週の値と比較値は週次メトリクス Issue と `data/measurement-cycle/LATEST.md` の「KPI ツリー」節に出る。

配線の規則は次のとおりで、`npm run docs:check`（DG079 / DG080）と週次の無人 triage のゲートが検査する。

1. §5 のレーン表の KPI 列は、そのレーンの構えを変える判断に使う KPI を書く。
2. `improvements.md` の各施策はタイトルに `[kpi: <id>]` を持つ。どの KPI を動かすか言えない施策は台帳に入れず、backlog のカードにする。
3. 新しい施策は根拠のある `[target: ±N 単位]` を持つ。根拠（過去事例か計算式）が書けない施策は効果を判定できない。
4. 同時に判定まで回す施策は 10 件まで（`strategy-lanes.cjs` の `MAX_ACTIVE_IMPROVEMENTS`）。超えている間は新しい施策を足さず、月次計画で判定・降格して削る。
5. rolling28d の値は 4 週前（窓が重ならない週）と比べる。値が取れない KPI は 0 と書かず、理由（未接続・欠測・認証切れ）を書く。

重複する rolling 28d の差を WoW と呼ばない。検索の期間契約は
[`weekly-cycle-contract.md`](../../.claude/skills/analytics/search-growth/reference/weekly-cycle-contract.md)、
効果判定は [`evidence-based-judgment.md`](../../.claude/rules/evidence-based-judgment.md) に従う。

## 2. 戦略の中心

今の主イシューと仮説の正本は `data/business/issue-map.json`（管理画面 `/strategy/issue-map`）。

### 2.1 誰の、どんな課題を解決するか（2026-09-18 採択）

**「多くの人が訪れる統計メディア」と「行政の統計処理の負担を減らす実務支援」を両立する。**
一般読者には地域の違いを発見・理解する価値を、行政実務者には資料作成に必要なデータが整理されている価値を届ける。
一般読者の全員を業務商品の購入者へ転換する前提は置かない。両者は同じ検証済みデータを利用するが、獲得経路と成果を分けて測る。

| 対象 | 具体的な課題 | 提供価値 | HARMと理由 |
|---|---|---|---|
| 地域の違いや身近な話題を知りたい一般読者 | 数字だけでは地域の特徴や背景が分からない | ランキング・記事・比較・地図で発見と理解を届ける | 好奇心は対象外でも価値がある。生活判断を扱う場合だけ家計のM・家族生活のR等を確認 |
| 議会答弁・計画策定の資料を作る行政実務者 | 各所の統計を探し、Excelへ集め、地域・年次・単位・定義を照合する作業を繰り返す | 複数統計を用途別に整理した編集可能な資料と、その更新 | A：仕事の達成・技能。M：所属組織の作業費用削減は実測できた場合のみ |

オーナーとの議論で課題と事業の意図は確認した。複数の実務者による利用、削減時間、支払者、購入価格、
反復需要は**未検証**であり、事業の意図と市場の実証を混同しない。
「公務員向けAI講座」「移住アフィリエイト」は、該当する利用意図が確認された場合の個別手段とする。

### 2.3 収益モデルと投資順序

| 位置づけ | 誰が何に支払うか | 現在の判断・開始条件 |
|---|---|---|
| 無料メディアの継続 | 閲覧者は無料。多くの読者に共通する商品の広告主が成果に対して支払う (§3.2) | ランキング・記事の品質と既存アフィリエイトの計測を維持。統計閲覧から購入意図を推測しない |
| **新規収益の主検証：用途別Excel資料** | 職員本人または所属組織が、複数統計の収集・整形・照合を省く成果物に支払う | 支払者は未確定。1業務・1商品・1販売面で、無料試用による実務価値の確認後に有料pilot |
| 更新版・継続利用 | 同じ資料を再利用する購入者が、確認済みの更新版に支払う | 初回実売と反復需要の確認後。統計の公表周期と利用頻度に合わせ、月額を先に決めない |
| 個別支援・法人利用 | 個別要件を持つ組織が、範囲を固定した追加作業に支払う | 具体相談、納品範囲、工数、採算の確認後。無制限の個別対応を商品本体に含めない |
| 広告・スポンサー | 広告主が読者への接点に支払う | AdSenseは維持費の相殺として2026-10-11に手動枠だけで再開。スポンサーは適合する読者・案件を確認してから。編集判断を販売しない |

**既存の集客・品質・計測を維持しつつ、新規商品投資は行政資料1件の検証へ集中する。**
アフィリエイト実験の成功を行政商品の検証開始条件にしない。note・ココナラ・Kindleは販売・配信手段であり、
チャネル数や商品在庫数を目標にしない。既存商品は使える素材として評価し、カタログにあることを需要の証拠にしない。
2026-10-07 に、雑学の流入とコンテンツ販売の回収経路を §3.5 に整理した。行政資料 pilot の優先は変えず、
ノウハウ商品と KDP は売上を計測できる状態で 1 商品ずつ試す。

事業計画の「地域意思決定セッション」は先行指標として維持する。git TSの5収益レイヤー・企画候補は
選択肢の在庫であり、新規投資の優先順位は本節、開始条件は§5を優先する。
既存のM3/M6/M12の売上・アクセス値を今回の戦略の予測として流用しない。

### 3.2 アフィリエイト — 共通的で収益性の高い商品 (2026-11-03 オーナー変更)

**現行の決定（2026-11-03 オーナー）**: アフィリエイトは、ページの文脈に合わせて分野ごとの案件を出す方式をやめ、
**多くの読者に共通し、報酬単価か成約率が高い商品**に切り替える。
「共通」は 2 つの条件を両方満たすものを指す (2026-11-03 オーナー確認): ① 対象者が広い (分野・地域・年齢を問わず多くの読者に当てはまる)、
② いつでも気軽に始められる (無料・数分の申し込みで済み、検討の時期を選ばない)。年会費無料のクレジットカード・銀行口座・無料体験が当たる。
携帯・電気・光回線の乗り換えは①を満たしても、契約の手続きと検討の時期が要るので②を満たさない。読者の大半は雑学を読みに来ていて、ページの分野から
購入意図は決まらない (共通事業方針の application)。分野ごとに案件を分けると 1 案件あたりの表示が細かく割れ、成果の判定に
届かない。共通の商品なら同じ案件に表示とクリックが集まり、早くデータが取れる。金融 (口座) に限らない。

**変更の根拠 (実測)**:
- 2026-10-04〜10-31 の 4 週で、アフィリエイトは 16,594 表示・21 クリック (0.13%)。12 の分野に割れ、最も多い分野でも 5,644 表示。ふるさと納税は 1,135 表示・2 クリック (`data/affiliate/ga4-affiliate-history.csv`)
- A8 の成果は 2026-08〜10 の 3 か月で 690 クリック・成約 0 件・¥0 (doboku-note と共用の口座。`data/affiliate/a8-results.json`)
- 同じ時期の AdSense の本文中の枠は 1,000 表示あたり ¥43〜45 (2026-W43。`data/adsense/history-units.csv`)

**案件の選び方**: 候補は「1,000 表示あたりの見込み収益 = クリック率 × 成約率 × 確定率 × 報酬単価 × 1,000」で並べる。
報酬単価だけ・クリック率だけで選ばない。比べる基準は、**同じ枠に AdSense を置いたときの 1,000 表示あたりの収益**
(本文中の枠で ¥43。週次の `history-units.csv` で更新する)。基準を下回る見込みの案件は、その枠に入れない。
例: 報酬 ¥5,000 の案件がクリック率 0.13% で本文中の AdSense に並ぶには、クリックの約 0.7% が成約する必要がある
(¥43 ÷ 1,000 表示 → 11.6 万表示に 1 件)。成約率・確定率は ASP の公表値か過去の実績を確認日付きで記録し、
不明なら「未確認」として試験で測る。

**置き方**: 共通の案件は本文の中段・下段の広告の段に置き、ページの分野で出し分けない。ページの文脈に合う案件は、
その文脈のページで共通の案件を上回ると実測できた場合だけ残す (ふるさと納税・地域の住まいなど)。

**守ること (変更しない)**:
- 評価の主指標は**確定収益 / 1,000 viewable impression**、補助指標は CTR・CVR・確定率・`affiliate_impression / pageview`。
  クリックだけで効果を主張しない。ASP の成果を広告単位へ結べない場合は 0 円ではなく判定不能として扱う。
- 「無料」という表示だけで低負担と判定しない。個人情報・電話連絡・面談・支払いの有無を含む成果条件を ASP の確認日付き情報から
  記録する。不安を煽る文言・誤解を招く訴求の案件は単価が高くても使わない (共通事業方針の原則)。
- 金融は無料の口座開設までにし、保険の見積もり・相談など「重い行動で読者が当事者でない」案件は単価が高くても出さない
  (2026-10-27 オーナー判断・backlog `AFF-HEAVY-FINANCE-STOP-01`)。
- 複数案件の同時入れ替えは効果を分離できないので行わない。比べるときは 1 つの枠で期間を区切って入れ替える。
- 公開pilotは事前に必要な表示・クリック数と最大期間を計算してから始める。CTRが高くても確定収益が成熟するまでは勝者としない。

vertical (分野の軸)・提携状況・配置・計測の実装は [`affiliate-ads-standards.md`](../../.claude/rules/affiliate-ads-standards.md) が持つ。
共通の案件への切り替えの実装と、本文の広告の段 (広い画面は横 3 枠・モバイルは 1 枠) の試験は backlog `AFFILIATE-COMMON-PRODUCTS-01`。
運用の現在地は`data/affiliate/affiliate-portfolio-latest.json`、公開pilotの開始可否と観測判定は
`data/affiliate/affiliate-pilot-readiness-latest.json`を読む。週次自動化は観測・候補提示までで、ASP申請、
priority変更、勝者反映、push/deployを行わない。

### 3.4 商品・データ販売

課金対象は、**特定の資料づくりに必要な複数統計の選定・整形・照合・編集用成果物・更新**とする。
基本のランキング・出典・比較データ・既存の基本CSVは無料で維持する。正確な解釈に必要な定義・注意事項も隠さない。
Excel拡張子であることや、公開データをまとめ直したことだけを支払う理由にしない。

#### 最初の商品仮説：議会答弁・計画策定の基礎資料パック

1つの実在業務を選び、その完成資料から必要な統計を逆算する。人口・子育て等は候補であり、
必要な業務・指標・地理粒度を確認する前に採択しない。県・市区町村・県庁所在市のデータを混ぜず、
対象業務に必要な粒度が提供できなければ対象を狭めるか見送る。

| 無料で提供するもの | 有料候補として検証するもの |
|---|---|
| 統計の閲覧、基本の比較・CSV、出典、読み方 | 指定した業務に必要な複数統計をまとめた編集可能なExcel一式 |
| 収録内容、対象地域・年次、サンプル、欠測・比較限界 | 比較表、推移表、図、出典一覧を同じ版に揃えた納品物 |
| 更新日と訂正情報。購入済み版の誤りは新規購入へ誘導しない | 新しい公表データへの更新版、差分確認、検証済みの更新手順 |

納品単位は、完成見本・比較対象・収録期間・指標定義・欠測の扱い・編集可能範囲・更新とサポートの範囲を
事前に明示する。年次や定義を揃えられない箇所は差異として残す。利用者のExcel環境で開き、
編集し、出典まで戻れることを確認する。答弁の結論・政策判断の妥当性まで保証する商品にはしない。

直接の利用者は職員だが、支払者は未確定。職員の個人購入、所属組織による購入、同じ資料を作る外部受託者を
候補として分け、誰に予算と購入判断があるか、納品・支払条件、購入までの期間を確認する。
職員の好意的な感想を組織の購入意思へ置き換えない。

パックにする理由: 都道府県のデータ集単体には全販売面で関心がほぼ無く、関心が集まるのは地図だった (§2.2)。
データと地図と推移が同じ版に揃っていれば、資料に入れるまでの手間 (年を揃える・地図を塗る・出典を書く) を減らす
理由が立つ。価格とその判定は上の PRICE-DATA-PACK-2026-11 のまま (中身を変えた日を交絡として記録する)。
売る地図の境界は、販売に申請が要ると判定した国土数値情報 (N03)・Geoshape を使わない (`MUNI-DATA-LICENSE-CHECK-01`)。

価格提示前に、代替手段の費用、削減できた作業、
支払者の予算、制作・更新・問い合わせ工数を確認し、1つの試験価格と対象範囲を固定する。
価格の安さを優先してサポートで赤字になる商品は横展開しない。

```text
期間収入 = メディアの実収入 + 商品の実売収入（税・返金・確定/未確定を区別）
商品1件の限界利益 = 1件の売上 - 返金 - 販売/決済手数料 - 納品/対応の変動費
期間の事業収支 = 期間収入 - 手数料等 - 制作/更新/対応費 - 共通運営費
工数込み採算 = 期間の事業収支 - 運営者の実作業時間 × 採択した時間単価
```

運営者の時間単価とpilotの工数上限は開始前に決め、無給扱いしない。費用と作業時間を二重計上しない。

**「届いた」の線 (2026-11-06 オーナー決定)**: 当面は、月の確定売上が運営費の上限 ¥1,846 に届くことを線にする。工数の時間単価は未決なので、この線は工数の回収を含まない。
制作費を回収できる販売数は、1件当たりの利益が正の場合にだけ計算する。メディア収益が商品開発を賄えるとも
未確認の段階で想定しない。更新周期ごとの収支が不明なら、買い切りpilotに留める。

進行条件は次の順序に固定する。

1. 無料コンテンツで関心を観測し、対象業務の利用者が無料サンプルを実際に使って残作業と削減時間を確認する
2. 支払者と購入条件を確認し、1業務・1商品・1販売面の買い切りpilotを作る
3. 外部公開・価格設定・出品は人間が承認する
4. 実売と運用工数を確認する
5. 勝った商品だけ別チャネルへ展開する

検索・DL・アンケート上の好意だけでは業務需要や購入需要を証明しない。
無料需要を通らない商品、同文大量展開、AI 無審査公開、複数チャネル同時 pilot は禁止する。

| 3 | 駅近人口は2050年にどれだけ残るか | 移住・交通の意思決定支援 | 比較・県別閲覧・データ導線を確認 | 800m直線距離を徒歩到達圏と誤読される場合 |

1回のデータ取得・空間演算を複数面へ再利用するが、同じ本文の複製や47県の薄い記事量産はしない。
販売物は公的データの再販売ではなく、再現可能な加工・検証・業務時間短縮に対して対価を得る。

### 3.5 雑学の流入と3つの回収経路（2026-10-07 オーナー整理）

雑学（食べ物の消費量、意外な1位など）は検索流入の最大のかたまりだが、**雑学の情報そのものは売らない**。
検索で来た読者は1つの事実を確かめて離れ、同じ事実にお金を払う理由がないためである。
回収は、雑学とは別の支払う理由がある次の3つの経路で行う。

| 経路 | 読者の課題 | HARMと理由 | 支払う理由 | 需要の証拠（2026-10-07） | 次の検証 |
|---|---|---|---|---|---|
| アクセス集客の換金（広告・物販） | 1位の県の味を試したい・贈りたい。雑学そのものは確かめれば済む | 物販はM（購買）とR（贈答）。雑学の閲覧は対象外 | 物販は商品そのもの。広告は読者が払わない | 食べ物の消費量・特産がクエリ別クリックの31%。楽天の商品カードのクリック率は0.40〜0.46%（サイト平均0.145%）だが計4クリックで判定できない | 物販は `AMAZON-ASSOCIATE-PILOT-01` の28日判定。AdSenseは§3.1の再開手続き（`ADSENSE-RESTART-01`）。月額は KPI `site-pageviews` × `ad-yield` で週次に追う（マーケティング戦略「広告収益との換算」） |
| ノウハウ商品 | AIと公的統計を仕事や個人開発に使いたい | A（技能・仕事の達成） | 調べて試す時間を短くできる | note の通算売上¥900はすべてClaude Codeを使う実務記事（¥300×3件・2026-05〜07）。有料マガジン3つ（2026-08-03時点で販売中） | `KNOWHOW-PRODUCT-PILOT-01` で1商品の4週の実売 |
| コンテンツ販売（KDP） | すきま時間に読める地域の話題がほしい | 娯楽で対象外。読み放題の加入者は追加の支払い判断なしに読める（KDPセレクト登録が前提） | 読み放題の既読ページと単品購入 | 都道府県ランキング・県民性の本は大手出版社からの刊行例がある（文藝春秋2013、東洋経済の隔年刊2012〜2020）。自社12冊の売上・既読ページは未計測 | `KDP-EXPANSION-01`。自社12冊の4週の既読ページを取ってから雑学本を1冊 |

この整理の根拠とした実測は次のとおり。

| 項目 | 実測 | 出典 |
|---|---|---|
| 検索流入の内訳 | W40 の28日集計でクエリが分かるクリック2,688件のうち、食べ物の消費量・特産が31%（クエリ文字列の機械分類による概算） | `data/gsc/snapshots/2026-W40/queries.csv` |
| note の雑学有料記事 | ランキング型の有料記事47本が通算（〜2026-09-11）閲覧4,842で売上¥0。直近28日（09-07〜10-04）はnote全体で閲覧7,048・売上¥0 | `data/note/dashboard/` |
| サイトから Kindle への導線 | 案内が出るブログ64記事の閲覧3,901（28日・09-06〜10-03）に対し、案内のクリックは1回 | `data/ga4/snapshots/2026-W40/` |
| 開発者向けの読者 | Claude Code 連載ブログの閲覧は28日で25（サイト全体43,907の0.06%） | 同上 |
| SNS | 1投稿あたりの中央値は X の表示70、Instagram のリーチ45 | `data/sns/metric-snapshots/` |

運用の原則は次のとおり。

- 雑学の情報を note の有料記事やメンバーシップで売らない（§3.3）。既存の雑学有料記事は `NOTE-FREE-DEFAULT-01` で
  無料に戻し、前後の送客を測る。
- 商品の集客は販売先の中（note の検索・推薦、Amazon の検索・読み放題の推薦）で行う。stats47 の雑学の流入を
  商品へ誘導する前提を置かず、サイトから商品への導線は文脈が一致する箇所に限る。
- ノウハウ商品は「稼げる」「収益化できる」を売り文句にしない。stats47 自体の収益実績がまだ無く、証拠のない
  収益の主張は §8 が広告でも扱わない情報商材と同じになる。成果として書くのは、取得日と取得方法を示せる計測値だけとする。
- ノウハウ商品と KDP は、売上を計測できる状態で1商品ずつ試す。行政資料 pilot（§5 の商品領域）の優先は変えない。

### 3.6 ペルソナ別の展開と、商品を増やさない判断（2026-10-17 オーナー整理）

2026-10-17 に、自治体職員・企業・学生の3ペルソナを AI のシミュレーションと Web 検索で調べた
（定義と根拠は [ターゲットペルソナ](./04_ターゲットペルソナ.md) §6）。回答は**仮説**であり、実際の聞き取り
（`ADMIN-STAT-PILOT-01`、0/3 件）の代わりにしない。

調べた結果、各ペルソナ向けの商品案はほぼすべて販売中だった（ココナラ14件・KDP 32冊・note の財政比較2本）。
一方、サイトから商品へのクリックは28日でブログ経由1件・`cta_click` 3件（2026-W41、`data/ga4/snapshots/2026-W41/`）で、
§3.5 の Kindle 案内も64記事の閲覧3,901に対し1クリックだった。**売れない原因は商品の数ではなく、読者の仕事に
合った見せ方と導線にある**と判断し、新しい商品は作らない。

| ペルソナ | 支払う理由（仮説） | 販売中の受け皿 | 2026-10-17 の判断 | 次の確認 |
|---|---|---|---|---|
| 自治体の財政・計画担当 | 毎年くり返す類似団体比較・現状分析の「揃える・確認する」手間 | note「財政指標の同規模比較」2本（¥300）、ココナラ P-04 財政・P-05 医療介護 | 新作なし。職場から読まれる記事に財政・介護のデータ集を案内 | 2本の売上比較（2026-11-09、`NOTE-FISCAL-PEER-PUBLISH-01`）。聞き取り3件 |
| 企業の商品企画・計画策定の受託者 | 提案書・基礎調査で品目や指標を47地域に揃える手間。部署経費・案件原価で払える | ココナラ P-14 家計消費・P-12 総合集、KDP K-S1-02（唯一の販売実績、2026-08 に1冊） | 新作なし。家計・産業の記事にデータ集を案内 | 導線のクリック。KDP の印税率（`KDP-ROYALTY-RATE-CHECK-01`） |
| 学生（卒論・自由研究） | 弱い。無料の公的資料が多く、書籍費は月千円未満 | なし（作らない） | 無料の価値（探し方・出典の書き方）で集め、広告で回収する | CSV の出典表記（`DOWNLOAD-CSV-CITATION-01`） |

展開の順序は次のとおり。

1. **導線**: 職場からの閲覧が多いブログ10記事（GA4 の PC・平日9〜18時が平均超）に、読者の仕事に合うデータ集を
   用途の一文つきで案内する（`apps/web/src/features/products/storefront.ts`、2026-10-17 実装・未デプロイ）。
   効果は `nav_click` の `surface=blog_product` で、本番反映から4週のクリックを読む。
2. **ココナラから撤退済み**（2026-10-19）。データ販売は note に集約し、note 版の公開とサイトの商品ページの行き先の
   付け替えは `NOTE-PACKS-REPLACE-COCONALA-01`。商品の生成コード（product-factory）は note 版が使うので残す。
3. **新商品は、既存の資産から少ない工数で作れるものだけ作る** (2026-11-04 オーナー判断。旧: 新商品は作らない)。
   売れない主因は商品の数ではなく見せ方と導線だという判断は変えず、大きな新作は導線のクリックと売上を見るまで始めない。

### 3.7 問いから収益へ渡す配線

サイトの問いと事業の問いは別の層にある。サイトの問いは `data/content/issues.json` に置き、テーマ・ブログ・GEO を問いの下で結ぶ。事業の問いは backlog の `ISSUE-PAYING-NEED-01` が持つ。

- 問いの `revenue` は、答えが広告・データ・ノウハウ・実務のどれにつながるかの仮置き。`実務` と `データ` の問いは、統計を仕事に使う人を探す入口になる
- e-Stat 以外のデータ (国土数値情報・GEO の空間演算・省庁の個別資料) を問いの `dataNote` に書く。他のサイトが同じ答えを出しにくい問いが、データ商品の候補になる
- この配線は仮説で、問いが売上につながるかはまだ確かめていない

## 5. 意思決定ゲートと実行順

旧P0〜P3の週番号ベース工程は廃止し、施策ごとに次のゲートを使う。

| **AdSense** | 2026-10-11 に手動枠で再開（§3.1）。広告ユニット別の収益・視認率を週次で取れる | 枠を増やさず計測（API 認証）を復旧する |

どこにも残らなかった事例の再発防止）。

### 領域と優先順位（2026-09-25 採択、2026-09-30 にレーンから領域へ移行）

施策を**収益までの流れ（計測 → 収益化 → 品質 → 集客 → 外部チャネル）の上のレーン**に分け、
どのレーンに投資を増やし、どのレーンを現状維持にするかを月をまたいで固定する。
2026-09 時点では検索流入が6週で約2.5倍（GSC 直近28日クリック 3,493 → 8,810、W32 → W38）に伸びた一方、
アフィリエイトのクリック率は 0.046%（28日 23,771 表示 / 11 クリック、〜08-28）で、週次収益を測る計器も止まっている。
流入はボトルネックではないため、計測と収益化を攻め、集客側は維持とする。2026-10-07 にオーナーが、AdSense 月¥1万に向けてサイト（集客）も並行して攻めると決めた。

構えの意味は次のとおり。

| 構え | 許すこと | しないこと |
|---|---|---|
| 攻める | 月次の重点に選ぶ。新しい施策・制作を起票して着手する。打ち手は幅広く並行してよい（§7） | 同じページ・同じ指標に施策を重ねる（§7） |
| 維持 | 進行中施策の効果判定、定期運用、不具合の修正 | 新しい拡大施策を週次 Must に入れる |
| 凍結 | 不具合の修正だけ | 新規の着手 |

2026-09-30 に 11 のレーンを、管理画面のサイドメニューと同じ 8 つの領域（`config/domains.json`）へまとめた。
レーン・役割・カテゴリの 3 軸が並んでいて持ち主が曖昧だったため、土木ノートと同じく領域 1 軸で優先順位を決める。

| 段階 | 実施・記録すること | 次へ進む条件 | 止める・見直す条件 |
|---|---|---|---|
| 1. 業務を選ぶ | オーナーの実例を起点に、対象業務の担当者3人を目安に直近の資料作成手順・出典・所要時間・再実施頻度・既存手段を確認 | 複数の担当者で同じ収集・整理作業が残り、1つの納品仕様にできる | 協力者が集まらなければ未検証とする。既存手段で十分、または個別要件ばかりなら汎用商品化を見送る |
| 2. 無料試用 | 1業務・1地域条件のサンプルを既存資産から作り、同じ完成条件の作業を比較。回顧による時間と実測を区別 | 2人以上が実務用資料に利用でき、照合・手直し込みの総時間が減る。出典と値の検証に阻害要因がない | 時間削減がない、品質確認に余計な工数がかかる、必要な粒度を揃えられない場合は修正または見送り |
| 3. 有料pilot | 支払者・予算・購入経路を確認し、価格・納品範囲・工数上限を固定。見本を提示し既存販売面で実売を確認 | 身内・自己購入を除く実売2件以上、実務利用、正の限界利益を確認 | 試験開始後30日を初回判断点とし、利用はあるが購入がない場合は支払者・予算・価格・経路を切り分ける。購入手続き待ちは予定日を確認し、期限なしに延長しない |
| 4. 更新・横展開 | 初回利用と次回用途を確認し、更新とサポートを含む工数込み採算を測る | 同じ仕様の再利用需要と工数込み採算が確認できた商品だけ更新版や隣接用途へ | 調達・サポート工数が採算を超える、毎回作り直しになる場合は範囲縮小・価格見直し・停止 |

実売2件は次の小規模試験へ進むための条件であり、継続的な事業成立の証明ではない。
メディア側は検索流入・再訪・引用と収益、業務側は総作業時間・実務利用・再利用と収支をそれぞれ評価する。
アフィリエイト計測は継続するが、その完了を聞き取り・無料試用の前提にしない。
商品カタログ全件の制作、会員制、API、新しい決済基盤、無制限の個別受託はこの検証を先回りして開始しない。

## 6. チャネル配分

| チャネル | 収益戦略上の位置づけ |
|---|---|
| SEO / blog | 主力。ranking で広く集客し、blog で比較・意思決定を深める |
| Instagram / X | 送客と指名検索の補助。頻度・運用は SNS 実行規約に従う |
| note | 外部衛星と、ノウハウ商品（§3.5）の販売面。雑学の有料販売には使わない |
| KDP | コンテンツ販売の主チャネル（§3.5）。読み放題の既読ページと単品購入で回収し、集客は Amazon の中で行う。新刊は既刊の売上・既読ページを計測できてから増やす（`KDP-EXPANSION-01`） |
| YouTube | **6週間・通常動画3本の限定 pilot**。収益化を目的に量産せず、視聴維持・指名/サイト送客・制作工数を EXP-006 で検証する |
| TikTok | **撤退済み。収益化を理由に再開しない** |

## 7. 検証規律

- **打ち手は幅広く試し、配分は計測で決める**（2026-10-28 オーナー決定）。新しい打ち手・商品・実験は件数の上限を置かず並行して始めてよい。台帳は `data/business/experiments.json`（打ち手）と `data/business/pilot-board.json`（商品 pilot の判定）。始める前に指標・判定日・停止条件・ベースラインを書き、判定日の実測で続ける・増やす・止めるを決める
- 同一ページ・同一指標に複数変更を重ねず、何が効いたか分離できる状態を保つ（重なるものは順に出す）
- 同じページを直す改善キュー（search-growth / adsense-improvement / affiliate-improvement）の WIP 上限は、原因分離のための機械強制として維持する（全領域の改善施策 WIP 5 以下、AdSense の配置実験は再開時の 1 件 `ADSENSE-RESTART-01`）
- 想定値、根拠、判定日、取得コマンド、実測値が揃うまで `effect/full` 等を付けない
- rolling 28d 同士の差、bot 混入値、未登録 custom dimension をゲート判定に使わない
- 人間承認が必要な OAuth、管理画面設定、ASP申請、外部出品はTODOで追跡し、文書へ期限を重複記載しない

週次候補の収集・承認は search-growth / adsense-improvement / affiliate-improvement、
施策 status は [`improvements.md`](../todo/improvements.md) を正典とする。

## 8. 禁止事項と倫理

- 全 ranking へ同じアフィリエイト広告を置かない
- アフィリエイト未計測のまま枠・商材を拡大しない
- 47都道府県分の薄い記事・商品を一括生成しない
- note と Stats47 に同じ本文を複製しない
- 統計結果を商材・スポンサーに都合よく解釈しない
- 公的統計サイトとしての信頼を損なう商材（精力・マカ等の強壮サプリ、アダルト、情報商材など）を
  収益を理由に置かない。判定は `.claude/scripts/ads/data/a8-curated.json` の `blocklistKeywords` と
  `AFFILIATE_DELIVERY_HOLDS` で機械的に行う（2026-09-18 オーナー判断・AFF-BRAND-FIT-01）
- 広告クリックを促す表現や視覚誘導を置かない
- 公的統計の基本閲覧を有料化しない
- 需要未検証の会員制、API、法人営業基盤を先に作らない
- 収益密度施策を飛ばして、PV や商品数だけを追わない
