# テーマ改善の提案: 医療・健康 (healthcare)

## 結論

**いまは実装しない。** このテーマには測定中の実験 (`THEME-STRUCTURE-20261007-healthcare` (d56 = 2026-12-02)) があり、章や指標を変えると測定に混ざる。実験の判定が出た後 (2026-12-02 以降) に、その結果を踏まえてこの案を見直してから実装する。

機械で一括に組み直す方法 (`apply-design.ts --approved`) は、このテーマには使わない。同じ日に実験のある 5 テーマへ試したところ、人が作り込んだ図・埋め込みの節・章の構成を固定するテストが落ちた (カタログの検査 1 件・テスト 6 件。変更は取り消した)。実装するときは、提案の採否を 1 項目ずつ決めて手で直す (`theme-proposal-format.md` の手順)。

設計の agent の案: いまの先頭の章は人口あたりの指標で最新年も新しいが、需要が最大の「病院が少ない県」に対して診療所が無く、医療費・救急所要時間・死因の各章は 1 指標か図だけで、ブロックの無い章や総量だけの章(年齢別医師数・周産期施設)もあった。そこで病院・診療所・医師を先頭に置き、健康寿命(検索語 約250回)、救急・周産期、入院と医療費、在宅、心の健康の順に並べ、1 指標の章は近い章へまとめて 13 章から 7 章(読み方の markdown 章は別)にした。足す指標は登録済みの 4 件で、看護師・医師の年収は occupation-salary が主担当のため足さない。

## 確かめたこと・確かめていないこと (agent の申告)

- healthcare.json の metrics と metricGroups を読み、context を除く全指標が章のブロックに入ったことを自分で数えて確かめた(drop は空)
- 同じ rankingKey を 2 つのブロックに入れていないことを章ごとに目で確かめた
- 先頭の章の先頭 2 ブロック(一般病院数 2023 年・一般診療所数 2023 年)は stat で最新年が 2020 年以降、2015 年以前の指標は置いていない
- addMetrics 4 件は data/metrics/<key>.ts に isActive: true があり、years と source.url を定義ファイルから写した(診療所 1975-2023、歯科医師 1975-2022、常勤医師 2017/2020/2023、新生児死亡率 1980-2023)
- composition は 2 組だけ。医師の年齢 3 区分は medical-physicians-under-40 の note に「3区分で同表医師総数に一致する」とあり、救急搬送 5 区分は ambulance-transported-persons の note に「5区分は同じ搬送総数の内訳」とあることを確かめた。死因 5 種(人口10万人当たりの率)は全死因ではないので composition にしていない
- trend は 2 年以上ある指標だけで、1 ブロック 3 指標・単位 2 種まで。病床利用率(%)と平均在院日数(日)の 2 単位が最大で、医師・看護師・歯科医師は単位が同じ「人」
- sex は健康寿命(男・女)と平均寿命(男・女)の同単位の組だけ
- 総量の指標を載せた章には率または人口あたりの指標を並べた(年齢別医師数は supply の人口10万人当たり指標と同じ章、救急は出動件数/千人と同じ章、周産期は新生児死亡率と同じ章、在宅は 1 事業所当たりと年収と同じ章、心の健康は K6 割合・受療率と同じ章)。なお周産期の施設数・小児科/産婦人科医師数、在宅の訪問診療/看護件数は、登録済みに人口あたりの版が見つからなければ総量のまま(検索は小児科・産婦人科・分娩・周産期・訪問の語で title を見た範囲)
- nurse-annual-income は occupation-salary で secondary、doctor-annual-income は同テーマで primary のため、selection.json の owned-elsewhere の規則に従い足していない。ただし規則の本文は全部読んでおらず、先頭の数規則までしか見ていない
- 未確認: 新規 4 指標のうち歯科医師数・一般病院常勤医師数・新生児死亡率は定義ファイルに description が無く(grep で 0 件)、図に入れる場合は定義文が必要(theme-metric-description-regression)。今回はカード用でブロックだけなので問題にならない見込みだが、検査は実行していない
- 未確認: access 章と medical-system-and-resources 章は embeddedSectionKeys(depopulation-medical / medical-workforce)を持つ。章を統合したあとの引き継ぎ方は apply-design 側の挙動で、確認していない
- 未確認: 既存の causes-of-death の章の donut と、読み方(reading)の markdown 章はブロック(rankingKeys)を持たないので章に含めていない。扱いは呼び元の判断
- 未確認: e-Stat API での統計表の実在確認と、指標ごとの全県そろい・欠測、/themes/healthcare 単体の検索流入は見ていない。検索語の回数は調査の前段の値をそのまま使った
- 未確認: 章の順を検索需要の大きさで決めたが、hospital-use(病床・医療費)に直接対応する検索語は前段の調査に無く、supply の次に置く案との比較はしていない
- 調査の未確認: data/themes/viewpoints/selection.json は読んでいない
- 調査の未確認: e-Stat API・WebFetch での統計表の実在確認はしていない(statsDataId と cdCat01 は data/metrics の定義から転記)
- 調査の未確認: 検索語はサイト全体の28日分で、/themes/healthcare や /areas/<県>/healthcare 単体の流入は分けていない
- 調査の未確認: inventory.json の metricInfo に無い候補の年数は data/metrics の years 定義から読んだ
- 調査の未確認: 『割合・人口あたり・世帯あたり』の網羅探索は医療施設・人材の範囲に限り、介護・メンタル・健診率など他領域は探していない。特定健診の運動習慣などは isActive:false で候補から外した

## 採用決定

ユーザー承認待ち。判断が要る点:

1. 実験の判定 (2026-12-02 以降) を見てから、章の順と見出しをこの案へ寄せるか。
2. 足す案の指標のうち、どれを載せるか (機械の検査を通ったものに限る)。
3. 人が作り込んだ図・埋め込みの節・テストで固定した構成のうち、変えてよいものはどれか。
