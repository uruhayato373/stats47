## 課題・ブロッカー

### 1. `blog-remediation-daily` が 17 日連続失敗し、2 つのキューが stale 化した

W32 レビューで**最優先**に挙げたが、W33 も 6 run すべて failure で未対応。失敗ステップは
「Provenance ratchet」のまま。影響が W32 時点より広がっている:

- `remediation-queue.json` が 8/11 生成で止まり、**ブログ是正が 2 週連続で 0 本**
- ai-content の LATEST が 8/12 生成で止まり、**W33 の生成 20 件が進捗に反映されていない**
  （done 249 のまま動かない）
- docs/21 outbox の自動掃除も止まっている

**キューが止まると「次に何をするか」が決まらないため、後続の作業がまとめて止まる。**
これが W33 で未着手が 6 件に増えた構造的な原因の一つ。

- 対策案（W32 から変更なし）: (a) provenance 欠陥を是正して ratchet を通す、
  (b) ratchet を独立 job に分離し、キュー更新と outbox 掃除は ratchet 失敗時も走らせる。

### 2. トークン消費が 2.1 倍になり、成果 0 の run が $114 を消費した

W33 は $557.19（W32 $262.88）。8/13 の ai-content は limit 5 に対し **items 0 で $114.40**。
2 週で items 0 の run は 4 回あり、そのうち 1 回が週内 2 番目に高額だった。

生成件数が伸びた分の増加は妥当だが、**成果 0 の run にこの規模が乗るのは投資対効果として成立しない**。
run の conclusion は success なので、workflow の成否だけを見ていると検出できない。

- 対策案: `limit` に対する `items` の充足率を記録し、0 件の run を検出したら次回の limit を下げるか
  原因（quota / gate / 生成失敗）を分類する。

### 3. GA4 Unassigned が 2 週連続で増加し、W33 は engagedSessions 0 の 206 セッション

9 → 206 セッション。engagementRate 0.0%。W32（28 → 158・1.9%）から継続して増えている。
発生源は 2 週間特定されていない。

- 対策案: GA4 の source/medium 内訳で切り分ける。自動アクセスなら GA4 のフィルタか
  Cloudflare WAF を検討する。

### 4. 露出の伸びをクリックに変換できていない

2 週で順位 8.12 → 7.79、表示 25,293 → 30,995（+22.5%）に対し、clicks は 866 → 930（+7.4%）。
CTR は 3.42% → 3.00%。**表示が増えるほど CTR が下がる形**で、順位が上がっているのにクリック率が
落ちるのは、新しく露出した面のクリック率が既存面より低いことを示す。

W32 レビューの申し送り 3「GSC のシーソー切り分け」が**4 週連続で未実施**のため、
どの面が増えてどの面の CTR が落ちたかを特定できていない。

### 5. NSM の週次比較が snapshot 間で一致しない

上記「同一期間の GA4 値が食い違う」問題。W32 の NSM は snapshot 生成時点で -9.1%、
確定後の値では +0.8%。**週次 KPI の信頼性そのものに関わる**ので、
どちらを正とするかのルールが要る。

### 6. IG の投稿が 22 → 2 に激減した

在庫は 4 件残っており、X は 92 件の scheduled を抱えている。原因未調査。

## 学び・ナレッジ

- **週次 KPI は snapshot 生成時刻に依存し、同一期間でも後から変わる。**
  GA4 の 08-02〜08-08 は engagedSessions 1,545 → 1,714、汚染率 46.5% → 7.9% に変化した。
  週次レビューで報告した WoW が、翌週の snapshot では別の値になりうる。
  「その週の snapshot が返した値」を記録し、後続週で差が出たら明記する運用が要る。
  `/knowledge` に記録推奨: **はい**

- **workflow の成否と成果物の有無は別の指標。** ai-content の 8/13 run は conclusion=success で
  items 0、コスト $114.40。success だけを見ていると、成果 0 に高額を投じたことを検出できない。
  充足率（items / limit）を独立に追う必要がある。
  `/knowledge` に記録推奨: **はい**（W32 レビューでは「記録推奨: いいえ」としたが、
  W33 で $114 規模の事例が出たため判断を変える）

- **1 つの job に複数の役割を持たせた場合の損害は、時間とともに拡大する。**
  W32 時点では `blog-remediation-daily` の停止は「是正キューが更新されない」だけだったが、
  W33 では ai-content の進捗表示まで止まり、生成 20 件が反映されない状態になった。
  停止の影響範囲は最初の観測時点で見えている範囲より広がる。
  `/knowledge` に記録推奨: いいえ（W32 で記録した同一知見の続報）
