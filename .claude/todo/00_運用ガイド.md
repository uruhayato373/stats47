# TODO 運用ガイド

`.claude/todo/` は「次に何をするか」だけを管理する。完了履歴、実装経緯、レビュー本文は置かない。

## ファイル構成

| 順序 | ファイル | 役割 |
|---|---|---|
| 1 | `01_未整理タスク.md` | まだ分類できていない一時的な受信箱 |
| 2 | `02_今月の重点.md` | 今月の重点 1〜2 テーマ |
| 3 | `03_今週の計画.md` | 今週実行する最大 5 件 |
| 4 | `04_改善バックログ.md` | SEO、性能、収益、コストなど効果測定を伴う施策 |
| 5 | `05_機能バックログ.md` | 機能、バグ、自動化、外部反映待ち |
| 6 | `06_指標バックログ.md` | 取得可能性を検証済みの指標候補 |

流れは `未整理 → バックログ → 今月 → 今週` とする。月次・週次計画はバックログ ID を参照し、status、期限、実装経緯を複製しない。

## 優先順位

| 優先度 | 判定 | 扱い |
|---|---|---|
| P0 | 公開データ誤り、セキュリティ、障害、課金増、計測不能 | 他作業より先に原因除去または封じ込め |
| P1 | 今月の収益・検索成長・運用継続に直結 | 今月へ pull。進行中は原則 3 件以下 |
| P2 | 価値と取得方法が確認済み | P0/P1 完了後に着手 |
| P3 | 条件付き保留 | `trigger` が成立するまで着手しない |

同一優先度では、期限、依存解除効果、変更の小ささの順に並べる。

## 残す条件と削除条件

- 完了、撤退、superseded は削除する。履歴は Git、効果の詳細は各 improvement log を参照する。レビュー全文は保存せず、未完了策だけをこのTODOへ具体化する。
- レビュー由来の項目には、最低でも「次または実行順」「停止条件または禁止事項」「完了条件」を付ける。恒久知識はrules・strategy・コード近傍READMEへ移し、TODOへ経緯を複製しない。
- 期限を 14 日超過し、次アクション・担当・再開条件のいずれかが無い項目は削除する。
- P3 は `trigger` がない場合は削除する。単なる「いつかやる」は残さない。
- 同じ成果を指す親子タスクは、受入条件を持つ親へ統合する。
- 実装済みで外部反映だけが残る場合は、機能バックログへ完了条件だけを残す。
- 改善施策は `effect/pending` の期限まで保持し、判定後は詳細ログへ結果を残して削除する。
- 指標候補は一次統計、都道府県粒度、最新年、既存重複を確認できたものだけを残す。不在・重複・古すぎる候補は保持しない。

## 機械参照

- `04_改善バックログ.md`: `scan-pending-improvements.mjs` と gallery `/dashboard` が 6 列テーブルを読む。
- `05_機能バックログ.md`: gallery `/dashboard` が見出しと `tier/status/created` を読む。
- `06_指標バックログ.md`: `parse-backlog.cjs` が 7 列テーブルを読む。
- 文書の固定構成・TODO ID・必須項目は`.claude/config/docs-governance.json`と
  `.claude/scripts/lib/check-docs-governance.cjs`が検査する。
- 列構造または見出し規則を変える場合は、パーサーとテストを同時に更新する。

変更後は`npm run docs:check`を実行する。期限・週・月の鮮度を含む棚卸しは
`npm run docs:check:all`または`/maintain-docs`を使う。

## 担当 (排他 write)

| 対象 | 書き手 |
|---|---|
| `01` / `05` / `06` の追記・整形、`00` の整合 | `todo-curator` (削除はしない) |
| `05` / `06` / `01` の**行削除** | `backlog-loop` (CI)。gate 証拠が ledger に要る |
| `04_改善バックログ.md` | `improvement-triage` (排他) |
| `02_今月の重点.md` | `/monthly-plan` skill (Write 上書き) |
| `03_今週の計画.md` | `/weekly-plan` skill (Write 上書き) |

閲覧は管理画面 `npm run admin` → http://127.0.0.1:4747/todo (読み取り専用)。

## 書き込み先

- 単発のバグ修正・機能改修で PR が閉じるものは GitHub Issue (`bug` / `enhancement`) を優先する。
- セッション中の未分類項目だけ `01_未整理タスク.md` へ追加し、作業終了までに可能な限り分類する。
- 一時ハンドオフ文書は作らず、未完了条件を該当バックログへ直接記録する。
- 本番デプロイ、R2 write、外部サービス変更は、バックログに書かれていても別途ユーザー承認を得る。
