note のエディタは操作を数秒〜数十秒で自動保存し、公開記事に未公開の下書き (`has_draft=true`) を作る。下書きのある記事は修復・タグ更新・カバー更新の安全装置が触らないので、以後の自動処理が全部止まる。2026-10-12 にリンクカード修復で、右矢印でカードを選べていないまま Delete を押し、その後のクリック待ち (30 秒) の間に「意図しない削除」入りの下書きが 3 件保存された。

**Why:** 失敗しても素早く抜ければ自動保存前に捨てられるが、待ちを足すと失敗途中の編集が下書きとして残る。下書きは公開版と違う内容を持つので、そのまま公開すると事故になる。

**How to apply:**
- 破壊的なキー (Delete/Backspace) は、対象ノードが選択状態 (`ProseMirror-selectednode`) と確認できたときだけ押す。確認できなければ何も編集せずに止める。
- 編集途中で長く待つ処理 (クリックの自動待機・要素待ち) を足さない。足すなら編集前に置く。
- 失敗のたびに `https://note.com/api/v3/notes/<id>` の `has_draft` を確かめ、残ったら記事を保留にして続ける (下書きの破棄はオーナーが note の画面で行う)。
- 1 日に数百件の編集・取得を連続で流すと公開 API が 403 を返し始める (同日、修復 75 枚＋タグ 280 件＋公開 19 本の後)。連続処理は区切り、403 が出たら即停止して数時間おく。
