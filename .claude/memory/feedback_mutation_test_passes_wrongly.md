「全 PASS を疑え」で 1 件壊して検証する ([[feedback-exit-code-not-via-pipe]]) のは正しいが、
**その壊し方 (probe) 自体が的を外していると、結果を二重に誤読する**。2026-08-20 に 1 セッションで
2 回踏んだ。

**Why:** ミューテーションテストは「発火したか」しか見ない。発火/非発火の**理由**は出力に出ないので、
probe の欠陥と検査対象の欠陥が見分けられない。

## 実際に踏んだ 2 パターン

| パターン | 何が起きたか |
|---|---|
| **probe が除外規則に当たって「緑」** | maintenance-debt の probe に `// legacy: 期限も削除条件も書いていない負債` と書いた。「期限」「削除条件」は**チェッカーが正しく除外する境界語**なので発火しない。チェッカーは正常なのに「検出力が無い」と誤診しかけた |
| **対象がクラッシュして「赤」** | preflight のテスト 2 件が緑になったが、理由は「debt を検出した」ではなく「checker が MODULE_NOT_FOUND で落ちた」。exit≠0 は同じなので区別がつかず、実バグ (checker の在り処と検査対象 root の混同) を緑で覆い隠していた |

**How to apply:**

1. **probe を書く前に除外規則を読む。** 「これは検出されるはず」と思った文字列が、実は
   ぴったり除外語彙だったというのが最頻の失敗。
2. **赤を見たら理由を読む。** 期待した finding コード (`[UNBOUNDED_LEGACY]` 等) が
   出力に**実際に出ているか**を確認する。exit≠0 だけを成功条件にしない。
   クラッシュ・設定ファイル欠落・引数ミスはすべて exit≠0 になる。
3. **緑も同じ。** 「他のゲートは通っている」ことを併せて確認すると、
   対象が起動すらしていないケースを弾ける (preflight では Env Registry の ✅ が
   「checker は動いている」証拠になった)。
4. **fixture は最小にしすぎない。** 対象が要求する土台 (レジストリ本体・設定ファイル) を
   欠くと、全ケースが「土台が無い」で赤くなり、本来測りたい検出力が測れない。

## ★「1 件見つけて満足しない」— 同型の誤りが 2026-08-20 に 5 回出た

上の 4 点は「1 つの検査を正しく読む」話だが、**そもそも検査対象を取りこぼす**方の誤りが
同じ日に 5 回起きた。共通形は **「grep や目視で 1 件見つけ、それで全体だと判断する」**。

| 実例 | 何を取りこぼしたか |
|---|---|
| `url-policy.test.ts` を実行して「通過」 | **同名ファイルが 2 階層にあり**、実際のガードは `src/lib/__tests__/` 側。CI で落ちた |
| recharts ノード 0 →「チャート未描画」 | このプロジェクトは**自前 SVG**。ライブラリ名で探したので見つからなかった |
| SSR HTML に数値なし →「データ無し」 | チャートは `ssr:false` の client component。**見る場所が違った** |
| `road-total-length` が backlog に一致 | `road-total-length-with-expressway` の**部分文字列**。単語境界で照合し直して 0 件 |
| 「81 ファイル生成済み」 | `.local/` は gitignore で**環境をまたがない**。別マシンの成果物は存在しなかった |

**How to apply:**
- **同名ファイルを疑う。** `grep -rln <name>` で**全件**出してから実行する。
  1 件目だけ実行して「通った」と報告しない。
- **識別子ではなく成果物で探す。** ライブラリ名・クラス名で見つからなくても「無い」ではない。
  DOM/生成物そのものを見る。
- **部分文字列一致を単語境界で検算する。** キー名の照合は `(^|[^a-z0-9-])key([^a-z0-9-]|$)`。
- **「生成済み」は生成した環境でのみ有効。** `.local/` `node_modules/` は git を渡らない。
