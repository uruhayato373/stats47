# テーマレビュー: local-finance-city（地方財政・市区町村）

## 結論

主問は、**各市町村がどの程度の財源を持ち、経常支出や債務にどの程度拘束され、人口・産業構造が近い団体と比べてどのような特徴があるか**とする。

全国約1,700団体の単純順位だけでは、小規模村、町村、一般市、中核市、政令指定都市、特別区の行政需要と権限差を無視する。全国順位は入口として残しつつ、自治体区分・類似団体・人口規模による比較を主導線にする。

現状は実装着手前に対象自治体を是正する必要がある。5桁コードだけで抽出すると、財政主体である政令指定都市本体と、その内部行政区が重複する。現行SEOには「熊本市 北区」の財政力指数0が最下位として出ており、行政区の対象外・欠測を真の0としてランキング化した可能性が高い。**東京23特別区は財政主体として含め、政令指定都市の行政区は除外する自治体分類SSOTがP0**である。

読み順は次の4層に分ける。

1. **自治体の前提**: 団体区分、人口、高齢化率、産業構造、類似団体
2. **財政構造**: 財政力指数、経常収支比率、実質収支比率
3. **債務・将来負担**: 実質公債費比率、将来負担比率、地方債・基金
4. **歳入・歳出**: 総額、1人当たり、構成比。目的別と性質別を分離

## P0: 財政主体・年度・値表現監査

実装前に次を確定する。

- 対象を地方財政状況調査上の市町村、政令指定都市、東京23特別区のどこまでとするか
- 政令指定都市本体を含め、その行政区は独立した財政主体ではないため除外すること
- 東京23特別区は政令指定都市の行政区と異なり、独自の財政指標を持つ対象団体として扱うこと
- 市町村コードだけで自治体種別を推測せず、基準日付き自治体マスターの団体種別を使うこと
- 合併・編入・市制移行・区新設等を「廃置分合処理済」系列がどの境界へ組み替えているか
- 消滅自治体と現行自治体を同じ最新年ランキングへ混在させないこと
- `fiscal-strength-index`の2021年「熊本市 北区=0」が真の0ではなく対象外・欠測ではないか
- 財政力指数の現行`decimalPlaces: 0`が小数を失わず、通常の小数3桁程度で表示できるか
- 財政力指数のunitに不要な`‐`が付かず、`2.1‐`等のSEO表現を生成しないこと
- 財政力指数が基準財政収入額÷基準財政需要額の過去3か年平均であること
- 経常収支比率の分子・分母、臨時財政対策債等の扱い、比率の方向
- 実質公債費比率が3か年平均で、早期健全化基準・起債許可等の制度上の意味が異なること
- 将来負担比率の算定なし、負値、0、欠測を区別すること
- 実質収支比率が高いほど無条件に良いとはいえないこと
- 現行5財政指標が2021年度止まりで、総務省・デジタル庁の公開データより古くないか
- `per-taxpayer-taxable-income`が納税義務者1人当たり課税対象所得であり、財政運営指標ではないこと
- 同指標の`entities`が都道府県・市区町村共用なのに、SEOが都道府県固定になっていないか
- 課税対象所得に対する人口・面積normalizationが二重・無意味な正規化になっていないか
- 全国比較と類似団体平均で、単純平均・人口加重平均・合計÷人口を混同しないこと

## 公式根拠

### デジタル庁・総務省「地方財政（市町村ごと）に関するダッシュボード」

- URL: https://www.digital.go.jp/resources/japandashboard/municipal-finance
- 地方財政状況調査と健全化判断比率確報を用いた市町村別財政データの公式比較基盤
- 財政指標、歳入、目的別歳出、性質別歳出、類似団体比較、構造データを確認する
- 毎年の更新、正誤情報、構造データ更新日をstats47のsnapshot provenanceへ記録する

### デジタル庁「地方財政に関するダッシュボードで扱う財政項目の説明」

- URL: https://www.digital.go.jp/resources/japandashboard/local-finance-introduction
- 財政力指数、経常収支比率、標準財政規模、地方債・基金、歳入・歳出分類の定義
- 市町村の類似団体が人口・産業構造による35類型であることを比較UIへ反映する
- 特別区の財政力指数が特別区財政調整交付金の算定値による点を注記する

### 総務省「地方財政状況調査関係資料」

- URL: https://www.soumu.go.jp/iken/jokyo_chousa_shiryo.html
- 市町村別決算、財政状況資料集、類似団体比較、主要財政指標の中心出典
- 普通会計、公営企業会計、年度、団体区分、訂正を元表単位で確認する

### e-Stat「社会・人口統計体系 市区町村データ D行政基盤」

- URL: https://www.e-stat.go.jp/stat-search/database?collect_area=200&cycle=8&layout=datalist&page=1&result_page=1&tclass1=000001111380&tclass2val=0&toukei=00200502&tstat=000001111376
- 現行`statsDataId=0000020204`、D2201・D2202・D2203・D2211・D2212の直接出典
- 「廃置分合処理済」の処理、地域コード、対象外値、年度をmetadataと実データで照合する

### e-Stat「廃置分合等情報」

- URL: https://www.e-stat.go.jp/municipalities/cities/absorption-separation-of-municipalities
- 市町村の合併、編入、名称・コード変更を基準日付きで追跡する公式資料
- 過去年推移の行政境界と現行自治体への組替えを説明する

### e-Gov「地方公共団体の財政の健全化に関する法律」

- URL: https://laws.e-gov.go.jp/law/419AC0000000094
- 実質赤字比率、連結実質赤字比率、実質公債費比率、将来負担比率の法的位置付け
- 財政力指数・経常収支比率を法定健全化判断比率と呼ばない

## テーマ境界

| テーマ | 責務 |

現行はlegacy `IndicatorSet`を専用route `/themes/local-finance/cities`で`areaType: "city"`として読み込み、ThemeCatalog chartはない。

| 表示 | 提案 | 理由 / 実装 |

| 全国ランキング | **keep / 対象自治体を是正** | 政令市行政区を除外し、特別区を含め、団体種別filterを常設する |
| 都道府県・市区町村切替 | **keep / 角丸規約を別途統一** | route責務は明確。都道府県と市町村を同一母集団へ混ぜない |

| 歳入・歳出構成 | **分類別に追加候補** | 歳入、目的別歳出、性質別歳出を別chartにする |

### 追加チャート

1. **主要指標4カード**: 財政力指数、経常収支比率、実質公債費比率、将来負担比率。方向と定義を個別表示。
2. **選択団体の時系列**: 全国一覧から1団体を選び、合併・欠測・3か年平均を注記。
3. **類似団体比較**: 選択団体、類似団体平均、全国中央値。平均方法と対象団体数を表示。
4. **歳入構成**: 地方税、地方交付税、国庫支出金、都道府県支出金、地方債、繰入金、その他。
5. **目的別歳出構成**: 民生、衛生、土木、教育、消防、公債等。同一分類のみ。
6. **性質別歳出構成**: 人件費、扶助費、公債費、普通建設事業費等。同一分類のみ。
7. **地方債と基金**: 総額、1人当たり、標準財政規模比を切り替え、異単位を同一軸へ混ぜない。

## 不採用・保留

| 候補 | 判定 | 理由 / 再検討条件 |
|---|---|---|
| 政令指定都市本体と行政区の同時ランキング | 不採用 | 同一財政主体を重複させ、行政区の対象外値を順位化する |
| 東京特別区を政令市行政区と同じ理由で除外 | 不採用 | 財政制度・団体性が異なる |
| 対象外・欠測の財政力指数を0表示 | 不採用 | 真の0と意味が異なりランキングを壊す |
| 全市町村の単純全国順位だけで優劣評価 | 不採用 | 権限、人口、産業、行政需要が異なる |
| 主要指標を合成した財政健全度スコア | 不採用 | 公式な合成根拠がなく、方向・定義も異なる |
| 財政力指数1未満=財政破綻 | 不採用 | 普通交付税算定上の財源力であり法定再生基準ではない |
| 経常収支比率100%超=直ちに財政再生 | 不採用 | 財政構造の弾力性指標であり法定再生基準ではない |
| 実質収支比率は高いほど良い | 不採用 | 過大な黒字も行政サービス・投資との関係を含め評価が必要 |
| 課税対象所得を自治体の財政成果と呼ぶ | 不採用 | 住民・納税義務者の所得構造を表す |
| 歳出が多い=サービスが良い | 不採用 | 人口密度、権限、固定費、物価、災害等を反映する |
| 最新Japan Dashboardデータへの置換 | 保留 | ライセンス、列定義、更新・正誤反映、R2生成契約の監査後 |
