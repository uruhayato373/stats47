- **存在しない交差軸**: 家計調査は都道府県全体の結果を集計しておらず、4-2/4-3にも都市×収入階級の列は無い。県別所得格差や「高所得者が多い都市ほど〇〇を買う」という地域×階級の結論には使わない。地域と所得を同時に比べたいなら、別調査の実在表を探してから企画する。[総務省の説明](https://www.stat.go.jp/data/kakei/search/before.htm)。
- **真の都道府県別年収**: 別調査の令和6年[全国家計構造調査・時系列表3-1](https://www.e-stat.go.jp/stat-search/database?statdisp_id=0004062104) は、都道府県別の1世帯当たり年間収入額を収録する (`statsDataId=0004062104`)。家計調査の県庁所在市値と同じ母集団・年次として混ぜず、県別比較を作るなら別の出典・ページ責務で扱う。
- **期間・単位**: 品目分類の年次表は年間合計、用途分類の支出額は1か月平均。ただし用途分類の `年間収入` は過去1年間の収入額（万円）であり、支出の月平均円と同じ単位ではない。全国の時系列と都市の単年値、年収階級と五分位、二人以上世帯と勤労者世帯を同じ系列として接続しない。[総務省の説明](https://www.stat.go.jp/data/kakei/search/before.htm)。
- **収入の意味**: 貯蓄・負債編の「年間収入」（万円）と、家計収支編の「実収入」「可処分所得」（1か月平均、円）は別系列。単純に同じ年収推移として連結しない。[総務省のFAQ](https://www.stat.go.jp/library/faq/faq19/faq19a04.html)。4-3の五分位は世帯主年齢と世帯人員も大きく異なるため、支出差を収入だけの効果と書かない。
- **2025年改定と時系列接続**: 2025年1月に収支項目分類が改定された。旧 e-Stat `statsDataId` のまま年だけ2025へ伸ばさない。総務省は新分類DB内の2024年以前の値を必要に応じて合算・接続しており、分割・統合・名称変更の対象品目には注記が要る。上位5品目は2024年の旧・新表で53地域すべて一致し、[2025年改定一覧](https://www.stat.go.jp/data/kakei/2025np/pdf/fr7.pdf)の変更対象にも含まれない。[DBの接続方針](https://www.stat.go.jp/data/kakei/pdf/change2025.pdf)。
- **2025年 API の分類コード**: 上位5品目の `cat01` は納豆 `010530030`、カップ麺 `010130050`、米 `010110001`、緑茶 `011010010`、牛肉 `010310010`。`cat02=03` は農林漁家世帯を含む二人以上世帯。公式 Excel の「282」等は印刷用の品目分類番号で、API の9桁 `cat01` とは別。
- **分析の順序**: ①表ID・分類コード・世帯・地域・期間・単位・欠測を確定 ②読者の問いと GSC 需要を照合 ③その軸に合う図を選ぶ ④数値と出典を確かめた説明をランキング・テーマ・ブログへ置く。参考書の `data/source-inventory/kakei-marketing/2015/analyses.json` は問いの候補であり、値・図・本文の出典にはしない。NotebookLM の回答も公式表で照合する。

## サイトへの配置順

1. **都市別の入口**: 既存ランキングの需要上位5品目を2025年単年で更新し、地域単位を「県庁所在市」に固定する。支出額と購入数量が両方ある品目では相互リンクし、金額増だけを「量が増えた」と解釈しない。
2. **全国時系列の説明**: 同じ品目の2000〜2025年の全国支出額・数量を別軸で示す。都市のランキング系列を全国系列の代用にせず、名目支出と購入量を区別する。既存の `/japan` 候補とテーマ内の折れ線を先に確認する。
3. **年収別の小さな試作**: 全国の五分位別「食料費・消費支出・エンゲル係数」を1組にし、2025年の水準と2000〜2025年の推移を分ける。年収帯18区分はExcelを別途取り込み・検証できた場合だけ加える。世帯主年齢や世帯人員を注記し、収入だけの効果と書かない。
4. **導線**: `/survey/kakei-chousa` は調査・粒度の入口、`/themes/household-food-spending` は食の比較、`/ranking/*` は都市別の個別品目、ブログは「支出と数量の違い」など既存ページで答えきれない問いを扱う。独立した年収別ページは検索需要と試作の回遊が確認できてから判断する。

## 基本構造

家計調査は**都道府県庁所在市**（＋政令指定都市）単位のデータ。
社会・人口統計体系（`lvArea=2` で都道府県取得）とは取得方法が異なる。

| パラメータ | 値 | 備考 |
|---|---|---|
| statsDataId | `0003348239` / `0003348235` | 金額 / 数量 |
| cat01 | 品目コード | 品目ごとに異なる |
| cat02 | `03` (二人以上の世帯) | `01`=勤労者世帯, `02`=勤労者以外, `03`=総数 |
| エリア | `lvArea` 指定なし | `lvArea=2` では該当データなし |
| 年次 | `2007000000`〜`2024000000` 等 | cdTime で指定 |

## 取得時の注意点

### 1. エリアフィルタ

`lvArea=2`（都道府県レベル）では該当データがない。**フィルタなし**で全エリアを取得し、プログラム側でフィルタする。

### 2. 政令指定都市の重複

県庁所在市が政令指定都市の場合、**同一県に複数行**が返る（2023年時点で52行）。

| area code | 都市名 | 都道府県 |
|---|---|---|
| `14003` | 横浜市 | 神奈川県 |
| `14004` | 川崎市 | 神奈川県 |
| `14150` | 相模原市 | 神奈川県 |
| `22003` | 静岡市 | 静岡県 |
| `22004` | 浜松市 | 静岡県 |
| `27003` | 大阪市 | 大阪府 |
| `27004` | 堺市 | 大阪府 |
| `40003` | 北九州市 | 福岡県 |
| `40004` | 福岡市 | 福岡県 |

**対処法**: 現行 `page-data-batch.ts` の `KAKEI_CITY_TO_PREF` で県庁所在市だけを明示的に写像する。福岡市は例外コード `40004`。ファイルの並び順で「各県の最初の行」を選ぶと北九州市などを誤採用するため使わない。

### 3. 標準バッチと2025年分類

現行 `packages/data-configs/scripts/page-data-batch.ts` は `kakeiEstatSource` で既存の
`kakei-chousa` 設定を e-Stat 取得へ渡し、`remapKakeiAreas` で県庁所在市を県表示へ対応させる。
ただし、既存設定の表 ID・品目コードは2024年までの系列であり、2025年改定との対応を確認せずに
`years.to` だけ変更してはならない。R2 は `app/stats/<key>/values.json` を配信する。
