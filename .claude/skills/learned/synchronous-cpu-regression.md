# 同期処理の計算量を検査する

**トリガー**: 同期アルゴリズムの性能回帰テストが、子プロセス起動やホストの待ち時間を含む時間制限で不安定になる。
**対処**: 有限の悪条件入力を使い、対象処理の前後だけを `process.cpuUsage()` で測る。旧実装が閾値を超え、修正後が十分下回ることを同じ入力で実測する。ネットワーク期限や非同期タイムアウト自体の検証には適用しない。
**根拠**: R2 key の10万スラッシュ入力で旧正規表現はCPU 3,960,400µs、修正後は1,207µs。500,000µsの回帰検査は旧実装を検出し、対象12テストは通過した。子プロセス版の2回のタイムアウトでは処理以外の経過時間が混入し、処理そのものの遅さを判定できなかった。
